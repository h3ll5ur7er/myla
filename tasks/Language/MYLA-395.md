- [x] Find every place `selfhost/`, `lib/std/` and `tools/` wrap on purpose (hashes: `std.hash`'s wyhash and FNV, `std.digest`, `std.random`'s xoshiro and SplitMix, `std.num`, `std.rt`'s allocator and maps, the compiler's own hashing) and move them to `std.int`'s `wrapping_add`/`wrapping_sub`/`wrapping_mul` (natively these must stay one instruction: check the lowering inlines them). Built as IR the lowering adds, the same on every target, not as flags (below)
- [x] Constant folding and literals: an overflowing constant expression is a compile-time error where it is one today, a trap otherwise
- [x] Parity programs on every target, interpreted and `--checked`, and the error corpus

## What was built

- **`wrapping_add`, `wrapping_sub`, `wrapping_mul`, `wrapping_neg` are builtin methods** of every integer type (checker `infer_wrapping`, interpreter `eval_wrapping`, lowering `wrapping`: the plain `Bin`/`Un`, so one instruction natively, inlined where it stands; `imulq` for `h.wrapping_mul(k)`). std.int's generator drops its own four (an impl can't define a builtin's name, as for `len`) and keeps `wrapping_pow`, the `overflowing_*` on the builtins. Why builtins and not std.int's methods: std.rt, std.hash, std.digest and std.random don't get the implicit modules, and importing std.int (5,000 lines, 1,826 cases, [[MYLA-396]]) into std.rt would parse it for every native program; and the inliner copies only same-module functions, so std.int's methods called from std.hash would have stayed calls. The first commit is the compiler side, the second (`Stage:`) the seed that knows them (D156's exception), then their use.
- **The interpreter** (`eval_binary`, `eval_unary`): `+`, `-`, `*` whose result doesn't fit the operands' type, unary `-` of the signed minimum or of an unsigned number but 0, and the signed minimum `/ -1` are `runtime error: integer overflow` at the operator; a shift whose run-time count isn't below the width is `shift amount out of range`. The checks are `add_overflows`/`sub_overflows`/`mul_overflows` of [[selfhost/checker.my]] (no allocation, no string comparison per operation); the interpreter's own arithmetic goes through the wrapping methods, so it doesn't overflow where it runs interpreted itself. A negative literal is a literal (`-128i8`).
- **`myla build --checked`** (file and project mode, `gen_main --checked`), and checked builds wherever `myla test` builds: the `--native` harness, the test programs of `tests/` and the program they run. The lowering (`checked_arith`, `check_neg`) adds plain IR before or after the operation: narrower than 64 bits the operation in 64 bits (exact), cast back to the type and compared with itself; at 64 bits the operands' and the result's signs (`+`, `-`), an unsigned comparison (`uint64`), std.rt's `mul_overflows_i64`/`mul_overflows_u64` (`*`, by division); `(a ^ MIN) | (b ^ -1) != 0` before a signed `/`; `count <u width` before a shift; then `check %ok overflow` (`__trap_overflow`) or `check %ok shift` (`__trap_shift`). So x86-64, aarch64 and wasm32 need nothing but the two trap entries, which only a checked build has. On x86-64 a comparison only its check reads is one `cmpq` and a jump over the trap call (`emit_compare_check`), as a bounds check is. The runtime (std.rt, std.platform*) is built plain in a checked build too (`checked_code`): the interpreter's primitives are that code built plain, and its address, size and hash arithmetic isn't the program's. Not done: `jo`/`jc` or aarch64's flags; the IR form costs a few instructions more (an `int32` `a + b` is `addq`, `movslq`, `cmpq`, `je`), a checked build only.
- **Constant folding**: the lowering folds no overflowing constant in a checked build (it traps where it runs; a plain build folds it wrapped, as before); a `const` whose value overflows is the compile-time error `const integer overflow`, as `const division by zero` is, in every build (a const has no run to trap in, and the interpreter reads consts folded).
- **The deliberate wraps moved onto the wrapping methods**, found by running every std module's cases interpreted and natively with the checks on, the compiler's cases, and a `--checked` compiler compiling itself: std.rt (`str_hash` and the maps' multiplications by 2^64/φ, `int_to_str`'s negation, `digit_count`, `digits_at`, the scheduler's generator, `fmod`'s subtractions), std.hash (FNV-1a), std.digest (every addition of MD5's, SHA-1's, SHA-256's and SHA-512's rounds: 1,257 statements, rewritten by a script that only touched sums at the top level of an assignment), std.random (SplitMix64, xoshiro256**, Lemire's method, `int_in`/`int64_in`'s range sizes and offsets), std.bigint (the borrows, `from_int` and `to_int64` of the minimum), std.bitset and std.int (SWAR popcounts, the lowest bit), std.compress (the three-byte hash), std.fmt, std.num and std.time (the minimum's magnitude, the lower end of `to_unix_ns`), the tests' generators in std.btree, std.compress, std.encoding, std.heap, std.regex and std.set; the compiler's literal values (`util.parse_value`, a `uint64` past the int64 maximum), the interpreter's `idiv`/`imod`, `mix_key` and scheduler. Two examples that showed wrapping (`attributes.my`, `types_and_aliases.my`) say `wrapping_add` now.

## Proposals (the owner decides; D175 has a `?` on them)

- **`<<` and `>>`**: built: a run-time count outside `0 … width-1` is the runtime error `shift amount out of range` where overflow traps, the run-time twin of the type error a constant count already is; a plain build masks the count as before. Bits shifted out are never an error (`1 << 31` is the `int32` minimum): a shift is a bit operation, and hashes, bit sets and packing rely on it. Alternatives: no check at all (masking everywhere, the cheapest); or also trap on bits shifted out, which would want a `wrapping_shl` in every hash.
- **`MIN / -1`**: built: `integer overflow` where overflow traps (the quotient doesn't fit), the minimum in a plain build as before. **`MIN % -1` is 0 everywhere**: the remainder fits, so it isn't an overflow. Alternative: Rust's, where `%` traps too, as `checked_rem` already gives `None` for it.
- **Unary `-` of an unsigned number**: built: an overflow for any but 0, as `0 - x` is. Alternative: reject it at compile time (Rust's).
- **A `const` that overflows**: built: the compile-time error `const integer overflow` in every build. Alternative: wrap, which makes a const's value the one place overflow is silent.
- **The runtime is built plain under `--checked`** (above). Alternative: check it too; a checked `word_freq` then ran 2.7 times the instructions, 14% of them in `mul_overflows_i64`.

## Evidence

- **Failing first**: `print(2147483647 + 1)`, `-(-2147483648)`, `uint8 3 - 4` printed `-2147483648`, `-2147483648`, `255` under `myla run` before; now each is `runtime error: integer overflow` with its position. [[tests/burn/test_overflow.py]] (25 tests: 21 operations × interpreted, plain, `--checked`; what fits the same everywhere; a constant expression; compound assignment; `myla test` interpreted and `--native`), the error corpus's `runtime_integer_overflow.my`, `runtime_shift_out_of_range.my` (`//~ checked`: the binary built with `--checked`) and `type_const_overflow.my`, and the parity program `wrapping_methods` fail at the base and pass now.
- **Every std module's cases** pass interpreted and natively (`myla test --native`, the harness built checked): 54 modules (std.rt's harness doesn't link at the base either, `NOT_NATIVE`); before the migration 19 modules failed interpreted (digest 10/62, random 6/41, int 1723/1826, …).
- **The compiler built `--checked` compiles itself** to the same assembly byte for byte as the plain one: no overflow anywhere in the compiler's code on its own source. The bootstrap reaches its fixed point.
- **aarch64 and wasm32**: `test_overflow` is in `_targets.SUITES`; a `--checked` program traps with the same message and position under qemu-aarch64 and Node.
- **A plain build is unchanged** (the base compiler is the seed at `eaa905d` with its library, both run from a directory where the library is `lib`): every benchmark's binary is the same size (closures 8 bytes smaller), and its assembly differs only in `int_to_str`'s negation (`negq` for `0 - x`, 2 instructions for 3) and the positions' line numbers. callgrind at each benchmark's profile size: the same instructions to within a dozen (fib 9,853,723 → 9,853,767; binary trees 750,992,313 → 750,992,301; geometric mean +0.0000%). Wall time (7 alternating runs, a shared machine): new/base −0.6% on the geometric mean, within the noise.
- **A checked build** (callgrind): +24.1% instructions on the geometric mean (n_body +0.7%, binary trees +5.1%, game of life +16.3%, word_freq +17.6%, quicksort +24.3%, fib +41.9%, string_build +53.3%); wall time +7.7% (the same runs); binaries 2 to 23% larger. Before the runtime was built plain: +115% instructions on word_freq, +130% wall time on map_remove.
- **The interpreter's cost** (callgrind): a loop of 1.4 million integer operations, 4,419.6 M instructions at the base, 4,503.3 M now (+1.9%; +11% before the checks lost their string comparisons and the `Type` they built); `fib(18)` 985.9 M → 976.2 M (−1.0%); MD5 and SHA-256 of 4 KB, whose rounds are all `wrapping_add` now, 1,209.0 M → 1,292.3 M (+6.9%; +102% before the interpreter took the wrapping methods first, ahead of the general method dispatch); a program's start (loading and checking the implicit modules) 362.9 M → 358.4 M (−1.2%: std.int has 216 cases fewer). The checker: `myla check examples/maps.my` 215.0 M → 210.3 M (−2.2%, the smaller std.int); its only new work is per constant.
- **Suites**: `scripts/test.sh fast`: 757 tests OK (3 skipped); the slow suites that cover it pass: `test_compiler_parity` (218), `test_selfhost_cases`, `test_selfhost_checker`, `test_lsp` (160), `test_std_modules`, `test_error_corpus` (308), `test_overflow` (25), `test_selfhost_codegen`, `test_selfhost_interp`, `test_selfhost_cli`, `test_native_runtime`, `test_examples_run`, `test_examples_compile`, `test_examples_tests`; on aarch64-linux (qemu) and wasm32-wasi (Node), `scripts/test-target.py` with `test_overflow`, `test_ir_contract` and `test_error_corpus`. `test_embedded_std` passes here with the regenerated `selfhost/embedded_std.my`, which isn't committed (the integrator's seed commit).
