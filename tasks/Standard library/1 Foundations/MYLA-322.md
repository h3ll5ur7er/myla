## Evidence

Built on branch `stdlib/MYLA-322` from the wave's branch (5fa7d95).

- **`std.char`** ([[lib/std/char.my]], [[Language/Standard-library/Char]]): the ten methods and `from_digit` as asked. `is_space` is C's `isspace` set (space, `\t`, `\n`, `\v`, `\f`, `\r`), the one `std.str` trims, as the str lane asked; Rust's `is_ascii_whitespace` leaves out `\v`. A radix outside 2 to 36 is a runtime error, as in Rust.
- **`std.int`** ([[lib/std/int.my]], [[Language/Standard-library/Int]]): one `impl` per width (no bound means "an integer type"), generated by [[scripts/gen_std_int.py]] (`--check` says whether the file is current). Signed widths: `abs`, `signum`, `checked_abs`; every width: `min`, `max`, `clamp`, `pow(exp: uint32)`, `gcd`, `lcm`, `div_euclid`, `rem_euclid`, `checked_` add/sub/mul/div/rem/neg/pow, `wrapping_` add/sub/mul/neg/pow, `saturating_` add/sub/mul/pow, `overflowing_` add/sub/mul/neg/pow, `mulmod`, `powmod(exp: T, m)`, `modinv(m) -> Option<T>`. The task's `sign` is Rust's `signum`. `checked_rem(MIN, -1)` is `None`, as in Rust.
- **Overflow and MYLA-311**: the checked, saturating and overflowing methods decide overflow by comparisons that can't overflow (CERT's division test at 64 bits) before they compute; only `wrapping_*` rely on the operators wrapping. `mulmod` at 64 bits doubles and adds when the product would pass 64 bits; `modinv` is extended Euclid with its coefficients kept modulo `m`.
- **Tests first**: the stubbed modules failed (`char`: 41/81 passed; `int`, generated with `--stub`: 0/1810), then passed.
- **Cases**: `myla test lib/std/char.my --stdlib lib` 82/82, with `--native` 82/82; `lib/std/int.my` 1826/1826 both ways (each case computed by the generator's Python integers). `python3 -m unittest tests.burn.test_std_modules tests.burn.test_doc_blocks`: 6 tests OK.
- **Differential check** (scratch, not committed): every pair of `int8` and `uint8` operands, and boundary and 1500 random pairs of `int16`, `uint32`, `int64` and `uint64`, through all two-operand methods, `mulmod`, `powmod`, `modinv` and the four `pow` kinds for exponents 0 to 69, against a Python model: 3,318,624 results, 0 differ, interpreted and native.
- **Check time** of a hello-world (median of 15, `myla check`): no import 0.4 ms, `import std.char` 1.8 ms, `import std.int` 26.7 ms (`std.json` 7.1 ms for comparison). Without its 1826 `#test` lines `std.int` costs 12.8 ms: the cases are more than half, and a checker that skipped `#test` attributes outside `myla test` would halve the cost of every module MYLA-320 makes implicit. A native hello-world stays 18176 bytes with either import (unused methods are dropped).
- **Compiler bugs found**, worked around here, suggested as tasks of their own: natively `assert(cond, f"…")` fails the IR verifier (the test functions use a private `holds` helper); the native test harness types an unsuffixed literal receiver as `int32` (the cases suffix every receiver, `5i8`); natively a literal on the left of `/` or `%` with a `uint64` at or above 2^63 on the right divides signed (`10 / m` gave `18446744073709551606`), which `2u64.modinv(MAX)` caught (the generated code never puts a literal there).
