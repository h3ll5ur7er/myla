Wave 2 of [[Project/Standard-library-roadmap]], roadmap #59. RE2's model: a pattern compiles to an automaton (Thompson NFA with a lazily built DFA), matching in time linear in the input, no backreferences and no lookaround. A longer task with no dependencies, so it can start in any wave.

- **Owns:** `lib/std/regex.my`, `docs/Language/Standard-library/Regex.md`
- **Needs:** nothing; it can start as soon as its wave does
- Work by the lane rules of [[Project/Standard-library-roadmap#Working in parallel]]: touch only the files this task owns, plus one row of the index table on [[Language/Standard-library]]; don't commit seeds or `selfhost/embedded_std.my`.

- [x] The syntax: literals, `.`, classes (`[a-z]`, `\d`, `\w`, `\s`), anchors, groups, alternation, `*` `+` `?` `{m,n}`, lazy forms
- [x] `compile`, `is_match`, `find`, `find_all`, `captures`, `replace`, `split`
- [x] A pathological pattern (`(a*)*b` on 10,000 `a`s) takes linear time
- [x] Checked against a corpus of patterns and inputs whose expected results come from RE2's or Go's tests
- [x] `#test` cases on every public function that has values to compare, test functions for the generic ones (D162), passing interpreted and with `--native`
- [x] Its page below [[Language/Standard-library]], with a doc block that runs

## Evidence

- **The design** ([[Language/Standard-library/Regex]]): a parser to a tree, a Thompson NFA, a Pike VM for the groups, and, on texts of 96 bytes or more, a lazy forward DFA (leftmost-first, `.*?` in front) for the end of a match and a lazy DFA of the reversed pattern for its start. Past 2,000 states a search goes on in the Pike VM. The measurements below decided the DFA: the Pike VM alone does 17–22 MB/s on `\w+@\w+\.com`, the DFAs 234–328 MB/s.
- **The corpus:** RE2's `re2-search.txt` from Go's `regexp/testdata`, its leftmost-first column, 1,660 cases (left out: `\p`, `\Q`, `\C`, which Go doesn't have, and text outside ASCII, where Go's characters and these bytes differ), and 156 cases of the rest of the syntax whose spans Go's `regexp` (go1.24.7) gave, generated by a scratch Go program. Every case is searched by the Pike VM alone and by the DFAs, which must agree (a fault planted in the DFA's `\b` failed 186 cases).
- **Tests:** `build/myla test lib/std/regex.my --stdlib lib`: 1944/1944 passed interpreted (23 s), with `--native` (1.6 s) and with `--target aarch64-linux` under qemu (5 min); wasm32 wasn't run (the container's harness can't run it for any module, and the module does no I/O). After `scripts/bootstrap.sh`, `python3 -m unittest tests.burn.test_std_modules tests.burn.test_doc_blocks`: 6 tests OK. The first version, before the DFA, passed every corpus case at once but two error positions of my own cases.
- **Measured** natively, best of five, on the shared 4-core container:

  | Search over 10 MB | DFAs | Pike VM alone |
  | --- | ---: | ---: |
  | literal `needle` (at the end) | 7.4 ms, 1.35 GB/s | |
  | `\w+@\w+\.com`, `find_all`, 29,706 matches | 42 ms, 238 MB/s | 551 ms, 18 MB/s |
  | `\w+@\w+\.org`, `is_match`, none | 30 ms, 328 MB/s | 445 ms, 22 MB/s |
  | 100 alternatives, `find_all` | 39 ms, 257 MB/s | |

  | `a` × n, no match | `(a*)*b` Pike VM | DFA | `(a\|a)*b` Pike VM | DFA |
  | --- | ---: | ---: | ---: | ---: |
  | 10,000 | 1.1 ms | 39 µs | 1.4 ms | 39 µs |
  | 100,000 | 11.7 ms | 381 µs | 13.7 ms | 368 µs |
  | 1,000,000 | 115 ms | 3.7 ms | 110 ms | 3.7 ms |

  Compiling a pattern of 100 alternatives (867 bytes): 65 µs.
