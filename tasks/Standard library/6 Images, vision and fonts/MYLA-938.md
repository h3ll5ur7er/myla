## Decisions made here

- **What a frame's pixels are.** Every pixel is `Rgba`. A frame's transparent index has alpha 0 and keeps its palette colour, as Pillow's `convert("RGBA")` gives it, so the composited corpus matches Pillow byte for byte, transparent pixels included.
- **`Animation.background`**, a field the plan didn't have: the canvas before the first frame and what `Disposal.Background` clears to. Pillow clears to the transparency index's colour with alpha 0 (the corpus's `animated-disposal2.gif` shows it: clearing to `(0, 0, 0, 0)` differs in 30 pixels a frame), so the decoder sets it as Pillow does: the first frame's transparent colour with alpha 0, else the global palette's background colour, opaque. Browsers clear to transparent; a program sets the field for that.
- **`composite`'s rule**: the canvas starts as `background`; a pixel of alpha 0 leaves the canvas, any other replaces it; clipped to the canvas; then the disposal. Pillow's quirks this doesn't copy, none in the corpus: an unspecified disposal that keeps the previous frame's method, and a canvas that grows for any frame (here only the first frame grows it, as browsers do; later ones are clipped).
- **`Disposal`'s variants** are `Unspecified, Keep, Background, Previous` (GIF's 0 to 3; not `None`, which reads as `Option`'s in a pattern); 4 to 7 are `Unspecified`.
- **`loops`**: the NETSCAPE2.0 count as stored, 0 forever, -1 without the extension.
- **`max_pixels`** counts, for each frame, its rectangle and the canvas `composite` makes for it.
- **Lenient where Pillow and browsers are**: a missing trailer, bytes that start no block after a frame, LZW data that ends early (the rest transparent), no palette at all (gray levels). Strict where the decoder must be: more LZW output than the rectangle (`Corrupt`; `lzw_decode_gif` refuses it with `max_output`), a file cut inside a block (`Truncated`, in any frame).
- **The encoder writes what `composite` shows**, not `a.frames` as given: the first frame whole, each later one as the rectangle of what changed with `Keep`; where pixels turn transparent the frame before gets `Background` over a rectangle grown to hold them. With any transparent pixel in the animation every frame reserves a transparent entry, so Pillow (which reads an animation whose first frame has no transparency as RGB) shows the transparency too. Transparent pixels take the colour of the opaque pixel before them while a frame is quantised, so they add no colour and ≤ 255 colours stay exact.

## Evidence

Measured on 2026-11-25 in the lane's worktree (branch `stdlib/MYLA-938` over `088e285`), on a shared 4-core x86-64 machine.

- **Pillow's compositing modelled first**: a Python model of the decoder and of the compositing rules above, run over the corpus before any Myla was written, matched all 10 `ok` GIFs' expected PAM files; with `Background` clearing to `(0, 0, 0, 0)` instead it failed `animated-disposal2.gif` (30 pixels in each of frames 1 to 3), which is why `background` exists.
- **Module cases** (`lib/std/gif.my`, 43 cases: `#test` cases on `disposal_of`, `code`, `format`, `info` and the helpers; test functions decoding Pillow's 2×2, transparent 3×2, interlaced 1×8 and three-frame 3×3 files to their pixels as Pillow gives them, the broken files (cut in each part, code size 12, GIF88a, `max_pixels` of one frame and of an animation, a first frame wider than the screen, no palette), round trips of `encode` (exact colours, gray, alpha below and above 128, 300 colours quantised) and of `encode_all` (changed rectangles, delays, loops, a hole needing `Background`, a `Previous` frame), and `composite`'s disposals and clipping): `build/myla test lib/std/gif.my --stdlib lib` 43/43 in 1.3 s; `--native` 43/43; `--target wasm32-wasi` with `MYLA_EMULATOR="node tools/wasm/run.mjs"` 43/43. aarch64 not run: no `qemu-aarch64` here. Failing first: `broken_files` failed (a code size written at the wrong offset of the test file, then a frame-growth expectation that forgot the background shows through), and the encoder's burn test failed until its animation cleared each frame (`Disposal.Background`), so that the hole is shown at all.
- **Corpus and fuzz** (`python3 -m unittest tests.burn.test_images.GifDecoder`, driver `tests/burn/drivers/gif.my`: `decode_all` then `composite`, each checked against `decode`): 5 tests OK in 11 s. All 17 GIFs natively and `--checked` (the 10 `ok` ones exactly Pillow's frames, the 4 `err` ones `Err`, the 3 `any` ones `Err`: `cut-in-data` `Truncated`, `huge-screen` and `frame-outside-screen` `TooLarge`), the 4 smallest and 2 broken interpreted; fuzz 11,845 cases (truncations of the 6 smallest files at every length up to 512 bytes and 10,000 seeded mutations) plain and `--checked`: 3,864 `Ok`, 7,981 `Err`, no runtime error. No manifest entry changed.
- **Encoder** (`python3 -m unittest tests.burn.test_gif`, driver `tests/burn/drivers/gif_encode.my`): 3 tests OK. Every `ok` GIF of the corpus decoded and encoded again, and two 6-frame 64×48 animations made by the driver (4 colours; a gradient of 3,072 colours; each with a moving square and a moving transparent hole): our decode of each output shows the input's frames exactly (alpha all or nothing), but the quantised one; frames after the first are smaller than the canvas and a `Background` disposal is written. With Pillow 13: Pillow reads every output to the same frames as std.gif (the colour of transparent pixels aside), the corpus's outputs to the frames Pillow reads from the originals, with the same durations and loop counts (absent where the original has none), the made ones with delays 30 to 80 ms and loop 0; the quantised animation 34.0 dB from its source.
