Step 4 of [[Project/Standard-library-roadmap/Images-vision-and-fonts]]: the module most programs import.

- **Owns:** `lib/std/imageio.my`, `docs/Language/Standard-library/Imageio.md`
- **Needs:** [[MYLA-960]], [[MYLA-961]], [[MYLA-962]]; [[MYLA-964]] and [[MYLA-965]] as they land
- Work by the lane rules of [[Project/Standard-library-roadmap#Working in parallel]]: touch only the files this task owns, plus one row of the index table on [[Language/Standard-library]]; don't commit seeds or `selfhost/embedded_std.my`.

- [x] `Format`, `sniff` (magic bytes), `format_of` (extension, case-insensitive)
- [x] `info`, `decode`, `encode`, `load` (EXIF orientation applied), `save` (format from the extension, `quality` for JPEG); file errors as `ImageError.Io`. JPEG encoding goes through a private helper until [[MYLA-963]]'s `jpeg.encode` lands (see Evidence): until then `save` of a `.jpg` is `Unsupported("jpeg encoding")` and `encode(img, Format.Jpeg)` a failure
- [x] A file whose extension and contents disagree is read by its contents
- [x] Measured: the check time of a program that imports std.imageio, against one that imports std.png alone
- [x] `#test` cases on every public function that has values to compare (images up to about 16×16), test functions for the generic ones (D162), passing interpreted and `--native`, and on aarch64 (qemu) and wasm32 (Node)
- [x] Its page below [[Language/Standard-library]] with a doc block that runs, the skill's `reference/stdlib.md`, and an example in `examples/`, registered

## Evidence

- **API shipped** ([[Language/Standard-library/Imageio]]): `#derive(Eq, Hash) pub enum Format { Png, Jpeg, Gif, Tiff, Bmp, Pnm, Qoi }` with `name()`, `extension()`, `lossless()`; `formats() -> [Format]`; `sniff(b: [uint8]) -> Option<Format>`; `format_of(path: str) -> Option<Format>`; `info(b) -> Result<ImageInfo, ImageError>`; `decode(b, max_pixels: int64 = image.MAX_PIXELS) -> Result<Image8, ImageError>`; `decode16(b, max_pixels) -> Result<Image16, ImageError>`; `load(path: str, max_pixels) -> Result<Image8, ImageError>`; `load16`; `encode(img: Image8, f: Format, quality: int = 90) -> [uint8]`; `encode16(img: Image16, f, quality)`; `save(path: str, img: Image8, quality: int = 90) -> Result<(), ImageError>`; `save16`. `.pbm`/`.pgm`/`.ppm`/`.pam` save that Netpbm kind (`pnm.encode_as`).
- **Private helper to be replaced by `jpeg.encode`:** `encode_jpeg(img: Image8, quality: int) -> Option<[uint8]>` in `lib/std/imageio.my` returns None. Wiring it is one line, `return Some(jpeg.encode(img, quality))`. Its tests switch on by themselves: the test function `jpeg_is_saved_once_std_jpeg_encodes` checks `Unsupported` and that nothing is written while it is None, and a round trip within 8 levels at quality 95 once it isn't; `tests/burn/test_imageio.py`'s round trips accept `jpeg=no` or `jpeg=yes` (the same for every file) and check a saved JPEG's size.
- **Not `impl Format for Format`** as the plan has it: a module that declares a type named like a prelude trait can't name the trait in an `impl` when another module imports it (`type error: unknown trait 'fmtmod.Format' in 'impl fmtmod.Format for fmtmod.Format'`; `Renamer.decl` in `selfhost/loader.my` resolves an impl's trait name through the module's own names). A two-file repro: `pub enum Format { A }` + `impl Format for Format { fun format(self, spec: str) -> str { … } }` imported by `main.my`. Checking the module alone passes. Programs print `f.name()`; the impl can come back once the loader is fixed.
- **Order of work:** the draft of an interrupted first attempt (its `#test` cases and test functions, 86) passed as found; the burn test was written next and failed first on things the draft had wrong: PNG writes the smallest lossless layout, so a lossless round trip gives the same pixels but not always the same layout (the driver compares `convert(Layout.Rgba)`), `ImageError.Io`'s message is the `IoError`'s name (`NotFound`), and a JPEG cut after `FF D8` is `BadSignature` to `sniff`, where std.jpeg says `Truncated` (the one listed exception). Mutations of the module (no turn in `load`, `.jpe` dropped from `format_of`) fail both the module's cases and the burn test.
- **Cases:** 86/86 pass interpreted (`build/myla test lib/std/imageio.my`, 2.2 s), `--native` (1.1 s), `--target aarch64-linux` (qemu, 6.8 s) and `--target wasm32-wasi` (Node, 1.7 s).
- **Burn test** `python3 -m unittest tests.burn.test_imageio`: 13/13 pass natively in 11 s. `ImageioDecode`: all 344 corpus entries of every format (all but the float TIFFs; GIFs as their first frame) through `imageio.decode` against the manifest's pixels natively and `--checked`, the smallest file of each format interpreted, and the fuzz runs (the two smallest readable files of each format, truncations of half of them up to 512 bytes, 10,000 seeded mutations) plain and `--checked`: `Ok` or `Err` only. `ImageioCheck` (driver `tests/burn/drivers/imageio_check.my`): `decode` and `info` equal each codec's on all 346 corpus files, broken ones included; `sniff` names all 272 readable files' formats and none of the 5 broken signatures; a `format_of` table of 35 names; the smallest file of each format copied under the next format's extension, under `.webp` and without one loads as under its own name; `load` of the 3 EXIF-oriented JPEGs gives Pillow 13's `ImageOps.exif_transpose` pixels (hashes vendored, `--vendor` prints them) and the other JPEGs `decode`'s; every readable 8-bit file saved and loaded through a temporary directory in each format (same pixels for PNG, TIFF, BMP, PNM, QOI, same size for GIF, JPEG `Unsupported` and not written), and the 16-bit files through `save16`/`load16` as PNG, TIFF and PNM; Pillow reads what `save` wrote (PNG, TIFF, BMP, PPM/PGM, QOI; not PAM with alpha, which Pillow 13 doesn't open) as the same pixels, over a sixth of the corpus; the errors of a missing file, a text file, an empty file and a directory.
- **Targets:** `python3 scripts/test-target.py aarch64-linux test_imageio` (qemu) passes in 104 s and `wasm32-wasi` (Node) in 31 s, everything but the interpreted run, which is the host's. `tests.burn.test_doc_blocks` passes (5/5, every page's blocks, 40 s).
- **Measured** (shared 4-core x86-64, best of 7, `build/myla` with its embedded library): `myla check` of a program that `imageio.load`s a file and prints its size 81 ms, against 35 ms for the same through `png.decode` alone (58 ms importing the seven codecs directly, 5 ms for `print("hi")`); `myla build` 426 against 180 ms, binaries 352 against 108 KB. With `--stdlib lib`: 83 against 33 ms to check, 405 against 181 ms to build.
- **Docs and example:** [[Language/Standard-library/Imageio]] (its doc block runs and prints its output), the row on [[Language/Standard-library]], `## std.imageio` in both copies of the skill's `reference/stdlib.md`, `examples/image_formats.my` (registered in `test_examples_run.py` and `test_examples_compile.py`, which pass for it).
- **Found:** besides the `impl Format` one above, a parameter named `format` breaks every f-string in its function (`fun f(format: str) -> str { return f"x {format}" }` is `type error: cannot call a value of type 'str'`: f-strings call `format` by name, and the parameter hides it). Neither is filed yet.
