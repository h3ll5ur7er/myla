The owner's decision on [[MYLA-402]]'s scope (2026-11-09): extend std.toml so that what the writer writes, the parser reads back, and add a derive for TOML as [[MYLA-385]] did for JSON.

- [x] The parser reads TOML 1.0: floats (`inf`, `nan`, exponents, underscores), integers in hex, octal and binary, offset and local date-times, dates and times, multi-line and literal strings, dotted keys, inline tables, arrays of any values, arrays of tables (`[[x]]`); the errors keep their line and column
- [x] `Toml` gains the variants it needs (`Float`, the date and time kinds); `selfhost/project.my` and `tools/lsp/projects.my`, which match on it, updated
- [x] The writer writes every variant, so `parse(to_string(doc)) == doc` for every document `parse` gives; the toml-test suite's valid TOML 1.0 files read and written back (none refused), its invalid ones refused
- [x] `#derive(Toml)`: `ToToml` and `FromToml` traits in std.toml, `encode` and `decode<T>`, generated as source as `#derive(Json)` is (D172), on structs and enums, generic types included (bounded per parameter, as [[MYLA-379]] does); the error corpus and parity programs
- [x] [[Language/Standard-library/Toml]], [[Language/Methods-and-traits]] (the derive), the myla skill

## The change of scope (a decision note for the owner)

D73 (1) made the manifest "a TOML subset: tables, strings, integers, booleans, string arrays, inline tables", and std.toml read only that ([[MYLA-89]]); [[MYLA-402]] proposed keeping it. The owner chose on 2026-11-09 to extend std.toml to TOML 1.0 and to add `#derive(Toml)`. What changes, and a row for [[Project/Decisions]] if the owner wants one (the integrator numbers it):

> **std.toml reads TOML 1.0, and `#derive(Toml)`** ([[MYLA-407]]; refines D73 (1) and D172). (1) `std.toml` parses all of TOML 1.0, not D73's subset; a manifest and a lock file are TOML 1.0 documents whose own rules refuse values they have no use for (`'package.version' must be a string`). (2) `Toml` gains `Float(float64)`, `DateTime(TomlDateTime)`, `Date(TomlDate)` and `Time(TomlTime)`, the date and time kinds as structs of their fields. (3) `#derive(Toml)` writes `ToToml` and `FromToml` against std.toml as `#derive(Json)` writes std.json's; D172's "TOML reaches typed values through its `Json` conversion" is superseded. Enums are externally tagged as in JSON; TOML has no null, so an `Option` is only a struct's field; `toml.encode` returns a `Result`, as a document must be a table.

The manifest's behaviour: what was a parse error naming the construct ("floats are not supported", "arrays may only hold strings") is now the manifest's error at the value (`'package.version' must be a string`, `'package.authors' must be an array of strings`, `'dependencies' must be a table`); dotted keys and TOML's other spellings work (`geo.path = "../geo"`). [[Architecture/Project-tool]]'s "The TOML subset" section became "TOML".

## Proposals (the owner decides)

1. **Dates and times: three variants of structs of their fields, no original text.** `DateTime(TomlDateTime { date, time, offset: Option<int32> })` (offset in minutes; `None` local), `Date(TomlDate { year, month, day })`, `Time(TomlTime { hour, minute, second, nanosecond })`. Why: a program wants the fields; `==` then says `1979-05-27 07:32:00Z` equals `1979-05-27T07:32:00+00:00`, as TOML means; the writer writes RFC 3339 from the fields, so the round trip needs no text; no illegal combination (an offset without a date) can be built; the three structs are also the derive's field types. Alternatives: (a) one variant with optional date, time and offset (illegal states); (b) four variants, one per TOML type (a local and an offset date-time are the same struct but for the offset); (c) keep the original text in the struct (equality by spelling, and a constructed value needs a text); (d) `std.time.DateTime` (UTC only, and std.toml, which the compiler imports, would import std.time). Lost in the round trip: the spelling (`.500` → `.5`, `-00:00` → `Z`, a space → `T`).
2. **Enums externally tagged, as `#derive(Json)`:** `"Red"`, `{ Dot = x }`, `{ Line = [a, b] }` (TOML 1.0 arrays may mix types). A variant with a payload is a table, so a document of its own; a variant without is a string. Alternatives: (a) every variant a table, `{ Red = {} }`, so any enum value is a document (uglier everywhere else: `color = { Red = {} }`); (b) internally tagged, `{ type = "Dot", x = 1 }` (no place for tuple payloads).
3. **`encode<T: ToToml>(v) -> Result<str, TomlError>`**, a `WrongType` error at `$` when `v.to_toml()` isn't a table (a number, a list, a unit variant): TOML's document is a table. Alternatives: (a) `-> str`, writing a non-table as `inline_string` (no TOML document, `decode` refuses it; std.toml's `to_string` does that for a bare value); (b) wrap it as `value = …` (then `decode` must guess). Rust's `toml::to_string` returns a `Result` for the same reason.
4. **TOML has no null: `Option` only as a struct's field**, left out when `None`, read as `None` when absent; no `impl ToToml for Option<T>`, and the derive refuses an `Option` in a list, a map, a payload or another `Option`, with a note that says why. Alternative: `None` written as nothing in a list (a list's length would change) or as `[]` (ambiguous with a list).
5. **Integers and floats apart:** an integer field doesn't read a float (`2.0`), unlike std.json, whose numbers are untyped; a float field reads an integer (`ratio = 1`). A `uint64` beyond int64 (TOML's integers) is written as the nearest float, as std.json does, and read back from a whole float in [2^63, 2^64).
6. **Dates as `tomllib` and std.time have them:** no leap second (`:60` refused), the year 0001 to 9999 (`0000` refused), the fraction cut after nine digits (TOML allows truncation). Alternative: RFC 3339's second 60 and year 0000.
7. **Error paths as std.json's** (`$.servers[0].port`, `$["a b"]`), and `TomlError` becomes D168's struct with a `kind` (`TomlErrorKind`, the same five as `JsonErrorKind`) and a `path`, with `message()` and `Format`. Alternative: TOML's own key syntax for paths (`servers[0].port`).
8. **The toml-test files vendored** as one JSON file, [[tests/burn/data/toml_test_1.0.json]] (133 KB: the 208 valid TOML 1.0 files with their JSON, the 509 invalid ones; MIT, commit `96fd088` named in it), so the suite runs in every `test_toml` run rather than only with a checkout; `python3 -m tests.burn.test_toml --vendor <checkout>` makes it again, `MYLA_TOML_TEST` runs a checkout instead.

## What was built

- **std.toml** ([[lib/std/toml.my]]): the parser builds the document as a tree of nodes (a table, an array of tables whose last element headers and keys go to, or a closed value), with `tomllib`'s rules on what may be added where: a table a header or an earlier section's dotted keys defined is explicit and is neither opened again nor extended with dotted keys; a header may open a sub-table of a dotted-key table; inline tables and arrays are closed. Positions: `key_pos`/`value_pos` work for dotted keys (the part that names the key) and inside arrays of tables (the last element's). Numbers: decimal with an overflow check that reports `integer out of range` rather than trapping (D175), the three other bases with the same check, floats through `std.num.parse_float` (correctly rounded), `inf`/`nan`. Strings: the multi-line kinds (first line break trimmed, CRLF as `\n`, a line-ending backslash, up to two quotes before the closing ones). The whole text is checked for well-formed UTF-8 first. `Toml`'s `Eq` is written by hand so a NaN equals a NaN (a document with `nan` reads back as itself). The writer writes floats in their shortest form and dates as RFC 3339. Typed values: `ToToml`, `FromToml`, `encode`, `decode<T>`, the helpers the derive calls (`members`, `member`, `optional_member`, `variant_of`, `unit_variant`, `payload`, `unknown_variant`, `wrong_type`), impls for the integers, floats, `bool`, `str`, `char`, the three date and time structs, `Toml`, lists and `[str: V]` maps.
- **The derive** ([[selfhost/checker.my]]): `#derive(Json)`'s code made format-neutral rather than copied: a `Serial` (`json_serial()`, `toml_serial()`) names the format's value enum, traits, method names, table variant and whether it has null; `derived_struct_src`, `derived_enum_src`, `is_serial_type`, `serial_field_ok` (an `Option` field without null), `serial_note`, `holds_option`, and the methods `serial_prefix`, `derive_serial`, `check_derivable_serial`, `mark_serial_broken`; `json_prefix`, `json_help` and `mark_json_broken` cover both. `Toml` joins the derivable traits (`only 'Eq', 'Hash', 'Json' and 'Toml' are derivable`). JSON's derived source is unchanged byte for byte (its `#test` cases stand, now against `json_serial()`).
- **Callers:** [[selfhost/project.my]] needed no change of its matches (they have `_` arms); its case for `authors = ['a', 2]` now expects the manifest's own error, and three cases were added (a float version, a dotted-key dependency, `[[dependencies]]`). [[tools/lsp/projects.my]] uses only `TomlPos`, unchanged; the language server builds (bootstrap's `lsp` step). The Json page's hand-written TOML-to-JSON conversion block went (it no longer matches `Toml`); the page points at `#derive(Toml)`.

## Evidence

Built on `3499093`.

- **Before:** the new `#test` cases of the parser were written first; the old parser refuses all of them ("floats are not supported", "dotted keys are not supported", …), and the new burn driver doesn't compile against the old `Toml` (no `Toml.Float`). On toml-test the old parser read 90 of 208 valid files and refused 118 as outside the subset (MYLA-402's evidence). The derive's corpus files and parity programs failed before the checker change with `cannot derive 'Toml': only 'Eq', 'Hash' and 'Json' are derivable`.
- **std.toml's cases:** 48 → 168: `build/myla test lib/std/toml.my --stdlib lib` 168/168 interpreted, `--native` 168/168, `--target aarch64-linux` 168/168 (numbers in four bases and their errors, floats, dates and times with every range error, multi-line strings, dotted keys, arrays of tables, the table rules' errors, positions of dotted keys and arrays of tables, bad UTF-8, writing floats and dates, round trips of documents with every construct, the typed impls, `encode`/`decode`, the enum helpers).
- **toml-test** (vendored, commit `96fd088`): **208 of 208** valid TOML 1.0 files read as their JSON says (floats, integers and dates compared by value) and what `to_string` writes read back as the same value by `parse` and by `tomllib`; **509 of 509** invalid files refused. - **Against `tomllib`** ([[tests/burn/test_toml.py]], rewritten for TOML 1.0): 3000 generated documents (2796 read, 132 refused by both, 72 with an integer beyond int64 refused as `integer out of range`), 4000 broken ones (1923 read, 2013 refused by both, 64 beyond int64), 60 interpreted, all agreeing, keys in order, written back and read as the original by both parsers; 2000 random values (floats, dates, arrays of tables) written and read by `tomllib` as themselves. `python3 -m unittest tests.burn.test_toml`: `Ran 5 tests … OK`.
