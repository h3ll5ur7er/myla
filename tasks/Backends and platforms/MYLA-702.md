D210, D211, D212, D214: the x86-64 backend emits COFF (`.rdata`, no `.type`/`.size`, Win64 at the boundary to kernel32 only, D130), clang assembles it, `llvm-dlltool` makes the import libraries from a list of names, `lld-link` links; the start code reads the command line and environment from kernel32, thread-local state through `gs:` (the TEB).

- [x] `myla build --target x86_64-windows hello.my` gives a static `hello.exe` that prints under Wine
- [x] Wine as the target's emulator in `scripts/test-target.py` and `tests/burn/_targets.py` (`MYLA_EMULATOR`), as qemu is for aarch64; the suites that run report what is still `Unsupported`

- [x] The console in UTF-8 (`SetConsoleOutputCP`), `\n` written as is (D215)

## What changed

**The build** ([[selfhost/target.my]], [[selfhost/driver.my]]). `x86_64-windows` is supported; `myla build` writes the assembly, clang assembles it (`--target=x86_64-pc-windows-msvc`), the driver writes `<out>.def` (`def_text`: `LIBRARY kernel32.dll`, the functions the program names) and `llvm-dlltool` makes `<out>.lib` (`import_command`), `lld-link /nologo /subsystem:console /entry:_start /nodefaultlib /stack:125829120` links, and the four intermediate files are removed. Without `-o` the program is `a.exe` (D217). The result is a PE32+ console executable whose only import is `kernel32.dll` (D212).

**The code generator** ([[selfhost/codegen.my]], [[selfhost/ir_x86.my]]), behind `CodeGen.windows`, so Linux's output is byte for byte what it was: COFF's `.section .rdata,"dr"`, no `.note.GNU-stack` (the backend wrote no `.type`/`.size`; the rest of its directives are COFF's too); every `__imp_<name>` an `Inst.Global` loads recorded (`note_import`, `windows_imports`) for the import library, so no list is kept by hand; with tasks, the worker's state block is the first of `__tls_blocks`, next to `%rip` (`tv`, `rt_var_at`, `RtAddr`), not `%fs` (which Wine's own C library holds): tasks run on one worker until [[MYLA-703]], as on wasm32 (D125).

**The runtime** ([[selfhost/runtime_x86.my]]). Linux's start, its signal handlers and its system calls moved into functions of their own (`emit_linux_start`, `emit_linux_handlers`, `emit_linux_calls`; the same text in the same order). Windows' `_start` (`emit_windows_start`) aligns the stack, sets up the one worker's block with tasks, calls std.platform's `windows_start`, then `__sched_init` and the ring with tasks, the entry and `__exit_program`. `__syscall(f, a, b, c)` and `__syscall5(f, a, b, c, d, e)` (`emit_windows_calls`) call the kernel32 function at `f` with Win64's convention at that boundary only (D130): %rcx, %rdx, %r8, %r9, the fifth above 32 bytes of shadow space and a sixth 0, the stack aligned to 16; no new primitive, so the seed needed nothing.

**The platform module** ([[lib/std/platform_windows.my]], new): the whole interface of [[MYLA-701]] (the declarations test holds it to x86-64's, with `windows_start` its own entry point, `backend_std_functions`). The standard streams as descriptors 0 to 2 (`GetStdHandle`, `ReadFile`, `WriteFile`, `CloseHandle`; a closed pipe's read is the end, its write BROKEN_PIPE; a read with a time limit through `PeekNamedPipe`), the heap's chunks (`VirtualAlloc`, `VirtualFree`, `VirtualQuery` to release a whole mapping and decommit part of one), the clocks (`QueryPerformanceCounter`, `GetSystemTimePreciseAsFileTime`), `Sleep`, a poller that waits for the nearest timer only, `ExitProcess` with the code's 32 bits (D216). The command line (`GetCommandLineW`) split as MSVC's runtime splits it and the environment block, both UTF-8 (D215), the console's code pages UTF-8 while the program runs and put back at its exit; `"\n"` is written as is. Windows' error codes are causes (D219); see the proposal below for those without one. Files, directories and the working directory ([[MYLA-704]]), processes ([[MYLA-705]], `PROCESSES` false), sockets and descriptor waits ([[MYLA-706]], `SOCKETS` false), the terminal and signals ([[MYLA-707]]) and random bytes are `Unsupported` (D210). The heap needed `VirtualAlloc` for its chunks (the step's allowance); the words `unmap_memory` and a read or write need are runtime blocks (`__win_memory_info`, `__win_io`), as those run while the heap grows or report that it can't.

**Tests and CI.** [[tests/burn/test_windows.py]] (new); `scripts/test-target.py x86_64-windows` (Wine found on `PATH` or at Ubuntu's `/usr/lib/wine/wine64`, put in `MYLA_EMULATOR`, a prefix in `build/wineprefix` made first, its server kept running); `tests/burn/_native.py` builds, links and runs for Windows; `tests/burn/_targets.py` excuses what later steps bring, each with its task, and `test_std_modules` skips std's modules that need files or random bytes (`program_excuse`); `NetOnWasm`, `PipesOnWasm`, `TermOnWasm`, `HttpOnWasm` check those are `Unsupported` on Windows too. CI's `targets` job has `x86_64-windows` (`llvm` and `wine64` installed); the `burn` job installs them for `test_windows.py` (`MYLA_REQUIRE_TARGETS`).

**Docs.** [[Language/Targets]] (the row, a Windows column, text in UTF-8 everywhere), [[Architecture/Native-backend#windows-on-x86-64]], [[Getting started]], [[Development/Testing]], [[Language/Standard-library/Rt]], [[Architecture/Self-hosted-compiler]], the `myla` skill's references (both copies).

## Proposals

1. **A Windows error code without a cause is Linux's errno of the same meaning, else 4096 plus the code** (built). `ERROR_DISK_FULL` is ENOSPC's `Other(28)` ("no space left on device", as std.rt's and std.io's texts name Linux's numbers), `ERROR_NOT_ENOUGH_MEMORY` ENOMEM's, and one Linux hasn't `Other(4096 + code)`, never taken for a Linux number, as wasm32 does with WASI's ([[MYLA-426]]). Alternative: D219's letter, `Other(code)` with Windows' own number, which reads as an unrelated Linux errno in every text (`ERROR_NOT_SAME_DEVICE` 17 as "file exists"), until [[MYLA-716]]'s per-platform texts. Proposed row: *"A Windows error code with no cause is `Other` of Linux's errno of the same meaning, else of 4096 plus the code, as wasm32 maps WASI's (D219, [[MYLA-702]])."*
2. **Tasks run on one worker on Windows until [[MYLA-703]]** (built), its state block next to `%rip`. Alternative: refuse a program with tasks; but `task_line` counts every `async let` of every module loaded, so std.process (`exit`) and std.test, and with them `myla test --target x86_64-windows`, would all be refused. Proposed row: *"Until Windows' threads, its tasks run on one worker, as on wasm32 (D125): `MYLA_THREADS` is ignored there ([[MYLA-702]], [[MYLA-703]])."*
3. **The console's code pages are put back at the exit** (built): `windows_start` keeps the console's output and input code pages and sets both to UTF-8 (D215); `exit` sets them back, so the console a program ran in isn't left in UTF-8 (a program killed leaves it so). Alternatives: leave them UTF-8 (D215's letter, simpler), or never touch them and write to a console handle with `WriteConsoleW` from UTF-8 (the console's own code page then doesn't matter, but a console write is no longer the same bytes as a pipe's).
4. **kernel32 through `__syscall` with the import slot's word, and the import list from the code** (built): `__syscall(__rt_get("__imp_WriteFile"), …)`; the code generator collects the names. Alternatives: a primitive of its own (`__win_call`), which the seed would have to know (a `Stage:` commit), or a fixed list of kernel32's functions in the compiler to keep in step with the module.
5. **A write to a closed pipe on the standard output or error ends the program with 141** (built), as on wasm32, the code a shell shows for SIGPIPE. Alternative: the runtime error `write failed: broken pipe` and 1, as a write to another descriptor reports.
