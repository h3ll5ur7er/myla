A part of [[MYLA-165]], the Windows target, found by [[MYLA-704]]: Windows' `random_fill` in [[lib/std/platform_windows.my]] is still `UNSUPPORTED`. D212 names `bcrypt` for it (`BCryptGenRandom` with `BCRYPT_USE_SYSTEM_PREFERRED_RNG`), a second import library beside kernel32's, which the driver doesn't make yet (`def_text` writes `LIBRARY kernel32.dll` only; wave 4 brings `ws2_32` too, [[MYLA-706]]).

Until then a Windows program has no `__random_bytes`, so `std.random`'s seeding from the system, `std.uuid`, and the names of `std.fs`'s temporary files and directories (`make_temp_dir`, `make_temp_file`, and with them `std.test`'s `temp_dir()` and `temp_file()`) are `Unsupported` there. `tests/burn/_targets.py` excuses `test_platform_primitives.Entropy` and std's `random`, `uuid`, `fs` and `test` modules for it (`_WIN_RANDOM`); `test_windows.py`'s `test_what_isnt_there_yet_says_so` checks it.

- [x] An import library per DLL the program calls (the code generator's `windows_imports` names each function's DLL), linked together
- [x] `random_fill` over `BCryptGenRandom`; the excuses above lifted, std.fs's and std.test's cases run under Wine
- [x] WaitOnAddress and WakeByAddressSingle imported from `api-ms-win-core-synch-l1-2-0.dll`, not found with `GetProcAddress` at the start (D227's "until wave 4")

## What changed

- **One table names a function's DLL**: `windows_dlls` in [[selfhost/codegen.my]] lists the system DLLs other than kernel32 with the functions std.platform calls of each (`bcrypt.dll`: `BCryptGenRandom`; `api-ms-win-core-synch-l1-2-0.dll`: `WaitOnAddress`, `WakeByAddressSingle`); any other `__imp_` name is kernel32's (`windows_dll`). `windows_imports` gives the noted names by DLL, kernel32 first, a DLL none of whose functions is called left out. Adding a DLL or a function of one (ws2_32's, [[MYLA-706]]) is a line there; std.platform calls it as `__syscall(__rt_get("__imp_Name"), …)` as it calls kernel32's ([[Architecture/Native-backend]], "The boundary to the system's DLLs").
- **The driver** ([[selfhost/driver.my]]) writes `<out>.<dll>.def` and runs llvm-dlltool for each DLL (`import_files`, `import_command(…, dll)`), and the target's link command takes them all (`{libs}`, [[selfhost/target.my]]'s `with_libs`); all are removed after the link. The Windows assembly ends with the same lists as comments (`# import bcrypt.dll BCryptGenRandom`, `windows_import_lines`), which [[tests/burn/_native.py]]'s build of the suites' programs reads instead of grepping `__imp_` and assuming kernel32.
- **Random bytes** ([[lib/std/platform_windows.my]]'s `random_fill`): `BCryptGenRandom(NULL, buf, n, BCRYPT_USE_SYSTEM_PREFERRED_RNG)`, at most 1 GiB a call (its count is a ULONG); a failure's NTSTATUS is INVALID_INPUT for STATUS_INVALID_PARAMETER, else Linux's EIO (`Other(5)`), as BCrypt sets no last error.
- **Parking**: `park` and `unpark_one` call the imported `WaitOnAddress`/`WakeByAddressSingle`; `find_synch`, its `zero_ended` helper and the runtime's `__win_synch` words are gone, and so is the millisecond nap where a system had neither (Windows 7: the program no longer loads there; `CreateFile2` already needs Windows 8). A hello world now imports 18 kernel32 functions, `GetModuleHandleW` and `GetProcAddress` no longer among them.
- **Temporary names** on Windows are joined with `\` (std.fs's `joined_on`), so `make_temp_dir()` is `C:\users\root\Temp\myla-…` under Wine rather than `…\Temp/myla-…`; std.fs's `open_options` case accepts Windows' 0o666 (D218), which the module-wide excuse hid.
- **Excuses lifted** ([[tests/burn/_targets.py]], `_WIN_RANDOM`): `test_platform_primitives.Entropy`, and std's `random`, `uuid`, `fs` and `test` modules in `test_std_modules`. `test_windows`'s `test_what_isnt_there_yet_says_so` now checks a socket (`Unsupported` until [[MYLA-706]]).

## Proposals (accepted 2026-11-16: D228 and D229)

1. **A function of a DLL other than kernel32 is named with its DLL in one table of the code generator's, and an import library is made per DLL the program calls** (built). Proposed row: *"A Windows program imports each system function from its DLL through an import library of that DLL's ([[MYLA-722]]): `windows_dlls` in selfhost/codegen.my names the DLL of every function that isn't kernel32's (bcrypt's `BCryptGenRandom`; `WaitOnAddress` and `WakeByAddressSingle` from `api-ms-win-core-synch-l1-2-0.dll`, ending D227's `GetProcAddress`), the driver makes `<out>.<dll>.lib` of each DLL with a function called and links them all, so a program calling only kernel32 imports only it. Random bytes are `BCryptGenRandom` with the system's preferred generator, at most 1 GiB a call, a failure INVALID_INPUT or Linux's EIO. Without WaitOnAddress a program doesn't load (Windows 8 on, as `CreateFile2`)."* Alternatives: the DLL in the name std.platform uses (`__imp_bcrypt$BCryptGenRandom`, the code generator renaming the slot), which needs no table but changes every call site's text and the symbols llvm-dlltool makes; one table in Python and Myla each (the suites' build kept grepping `__imp_`), two places to keep in step; `kernelbase.dll` for the synch functions (where Windows 8 on forwards the API set, but not a documented home of them; Microsoft's `Synchronization.lib` and Rust's std link the API set's).
2. **A temporary file's path on Windows is joined with `\`** (built), as Rust's `env::temp_dir().join` and Python's `tempfile` give it. Alternative: `/` as before, which Windows accepts but shows mixed (`C:\Temp/myla-…`).
