A step of [[MYLA-165]], the Windows target, in the plan the owner accepted on 2026-11-14 ([[Project/Follow-up-plan#windows-2026-11-14]]). D214 (second phase): a third seed, `bootstrap/seed-windows.s` (cheap under D207), and the bootstrap run on Windows with Git Bash and LLVM's tools.

- [x] `scripts/bootstrap.sh` on Windows (Git Bash), the seed found by `scripts/host.sh`
- [x] `bootstrap/seed-windows.s` from `scripts/update-seed.sh`, checked by the Windows runner's bootstrap (CI's `bootstrap-windows`; here under Wine)

## What changed

- **[[scripts/host.sh]]** finds Windows by `uname -s` (Git Bash's `MINGW64_NT-…`, `MSYS_NT-…`; `MYLA_OS=windows` in its place, as `MYLA_ARCH` is for the architecture) and sets `HOST_OS`, `HOST_TARGET=x86_64-windows`, the seed `bootstrap/seed-windows.s` and `EXE=.exe`. Its tools there are LLVM's (`AS=clang`, `LD=lld-link`, `DLLTOOL=llvm-dlltool`, each overridable; a missing one says where LLVM for Windows puts them). `asm_to_bin` on Windows is `windows_asm_to_bin`: the steps and command lines of `myla build --target x86_64-windows` ([[selfhost/driver.my]]'s `cmd_build`, [[selfhost/target.my]]'s tools): `clang --target=x86_64-pc-windows-msvc -c` into `<out>.o`; for each `# import <dll> <function>…` line at the assembly's end ([[MYLA-722]]'s `windows_import_lines`, which [[tests/burn/_native.py]] reads too) `<out>.<dll>.def` and llvm-dlltool's `<out>.<dll>.lib`; lld-link with the driver's flags. Git Bash's argument conversion is off for the three (`MSYS_NO_PATHCONV=1`, `MSYS2_ARG_CONV_EXCL='*'`, as it would take `/nologo` and `/out:` for paths), and an absolute path is given as Windows writes it (`cygpath -m`, where there is one). `seed_compile` copies `lib/` there instead of `ln -s`. Linux's branch is unchanged.
- **[[scripts/bootstrap.sh]]**, **[[scripts/check-seed.sh]]**, **[[scripts/update-seed.sh]]**: every program is `<name>$EXE` (`build/stage3.exe`, `build/myla.exe`, `build/myla-lsp.exe` on Windows; the same names as before on Linux); the assembly keeps its names and the fixed point compares `stage2.s` with `stage3.s`. `SEEDS` names `x86_64-windows:bootstrap/seed-windows.s`, so `update-seed.sh` writes it, `--out DIR` included (CI's `myla-seeds-<sha>` artifact gets it), and check-seed reports whether it is the current compiler. `update-seed.sh` takes target names, writing only their seeds (`scripts/update-seed.sh x86_64-windows`: a new target's seed without rewriting the others, which D207 keeps); check-seed says a missing seed is missing.
- **`.gitattributes`**: `* text=auto eol=lf`, every text file checked out with LF whatever `core.autocrlf` says (Git for Windows' default converts to CRLF, which would change what the compiler reads and embeds, and break the scripts under bash). Every file in the index was LF already (`git ls-files --eol`), so nothing is renormalized. `bootstrap/seed-windows.s` is `-diff linguist-generated` as the other seeds.
- **`bootstrap/seed-windows.s`** (the `Stage:` commit 2d6fd45): the compiler at b10d5df compiled for x86_64-windows by itself at its fixed point, without the embedded library (MYLA-431 applies as to the others): 13,657,631 bytes (seed.s 13,277,767, seed-aarch64.s 28,503,027), about 1.28 MB gzipped (seed.s 1.24 MB).
- **CI's `bootstrap-windows`** ([[.github/workflows/ci.yml]]), on `windows-latest` with `shell: bash` (Git Bash): checks the checkout has no CR in `selfhost/`, `lib/std/`, `scripts/` and the seed; puts `C:\Program Files\LLVM\bin` first on `PATH` (`GITHUB_PATH`) and prints each tool's path and version; `scripts/bootstrap.sh build`; `scripts/check-seed.sh build`; every example built by `build/myla.exe` with that LLVM against `build/myla.exe run`. It publishes nothing (proposal 2).
- **Tests** ([[tests/burn/test_windows.py]]): `HostScript` (host.sh's answer for Linux on both architectures, Git Bash's `uname -s` names, Windows on aarch64 and Darwin refused; every seed in `SEEDS` committed) and `BootstrapLink` (a program calling kernel32, bcrypt and the synch API set built by `myla build --target x86_64-windows` and its assembly built again by `asm_to_bin` with `MYLA_OS=windows`, each tool a stub that logs its command line and keeps its `.s` and `.def`: the same five command lines, the same three import lists, and the program runs under Wine).
- **Docs**: [[Development/Bootstrap]] (the seeds, a section "On Windows", the Wine stand-in), [[Development/Testing]] (the job), [[Language/Targets]] (the Windows row), [[Getting-started]], [[Development]], [[Home]], [[Architecture/Native-backend]] (who reads `# import`), the README, and the `myla` skill's `SKILL.md`, `reference/toolchain.md` and `reference/compiler.md` (both copies identical).

## Proposals

1. **The Windows seed's check runs only on Windows, in `bootstrap-windows`** (built); Linux's `check-seed.sh` checks the Linux seed and only reports whether the Windows seed is the current compiler (one more `seed_compile`, 1.6 s of check-seed's 5.0 s, this machine, 2026-11-16, `b10d5df`), as the aarch64 seed is checked by `bootstrap-arm64`. `MYLA_OS=windows MYLA_RUN=wine64 scripts/check-seed.sh` checks it under Wine where one wants. Alternatives: the Wine check in Linux's `bootstrap` or the `targets` x86_64-windows job (the bootstrap under Wine took 22.6 s here, see Evidence, plus Wine's install and start; it proves less than Windows itself does, and duplicates `bootstrap-windows`); check-seed bootstrapping every seed under its emulator (qemu's aarch64 bootstrap takes minutes).
2. **`bootstrap-windows` publishes nothing; D233 stands** (built: the `windows` job keeps publishing the `myla.exe` and `myla-lsp.exe` built on Linux, once they ran its 160 cases on Windows). The bootstrap's `myla.exe` is the same assembly (the Linux compiler's `--target x86_64-windows` output for `selfhost/main.my`, byte for byte, here) and differs only in lld-link's time stamps; publishing it too would give two tools of one commit, and publishing it instead would publish tools that didn't run the Windows runner's cases. Alternatives: `bootstrap-windows` publishes `myla-x86_64-windows-<sha>` instead (as `bootstrap-arm64` publishes the aarch64 tools it built, "each machine's own"), the `windows` job then testing the cross-built tools only; both, under different names.
3. **`update-seed.sh` takes target names** (built), so a new target's seed is added without rewriting the seeds that still bootstrap the sources (D207): `scripts/update-seed.sh x86_64-windows`. Alternative: run it whole and `git checkout` the other seeds, which a `Stage:` commit's reader can't tell from a forgotten update.
4. **Every text file is checked out LF** (`* text=auto eol=lf`, built). Alternatives: only `*.my`, `*.s` and `*.sh` (what the bootstrap reads; the tests' pinned outputs and the docs would then follow `core.autocrlf`); `git config core.autocrlf false` in the CI job only (a Windows developer's clone would still get CRLF).

## Evidence

- **Test first**: `HostScript` and `BootstrapLink` against BASE's (9b9a3c2) `scripts/host.sh`: 3 of 3 failed (`'x86_64-linux bootstrap/seed.s []' != 'linux x86_64-linux bootstrap/seed.s []'`, `'bootstrap/seed-windows.s' not found in [...]`, and GNU `as` refusing the Windows assembly: `prog.exe.s: Assembler messages: …`, exit 1). After: 3 of 3 pass; `test_every_seed_is_committed` failed until the `Stage:` commit.
- **The Windows bootstrap under Wine** (this machine, 4 cores, Wine 9.0, Ubuntu's clang 18.1.3, llvm-dlltool and lld-link; `MYLA_OS=windows MYLA_RUN=/usr/lib/wine/wine64 scripts/bootstrap.sh build/win`, Wine's server and services started first; 2026-11-16, `2d6fd45`): from `bootstrap/seed-windows.s` stage 0 to stage 3, `OK: byte-identical fixpoint reached (29439334 bytes)`, `build/win/myla.exe`, the type error's exit 1 from `build` and `run`, `build/win/myla-lsp.exe` answering initialize and shutdown: 22.6 s in all (the Linux bootstrap 13.7 s); one stage, stage 0 compiling `selfhost/gen_main.my` under Wine, 2.0 s. Sizes: `stage2.s` = `stage3.s` 29,439,334 bytes (Linux's 29,237,053), `stage3.exe` 6,162,944, `myla.exe` 6,828,544, `myla-lsp.exe` 5,276,672, `stage0.exe` 2,548,224.
- **The same compiler as Linux's**: `build/win/stage3.s` is byte for byte the Linux `build/stage3 selfhost/gen_main.my lib --target x86_64-windows`; so are `myla.s` (`selfhost/main.my`) and `myla-lsp.s` (`tools/lsp/main.my`). The seeds the Windows compiler makes for x86_64-linux, aarch64-linux and x86_64-windows (check-seed's `check-*.s`) are byte for byte those the Linux compiler makes.
- **check-seed under Wine** (`MYLA_OS=windows MYLA_RUN=… scripts/check-seed.sh build/win`): `bootstrap/seed-windows.s bootstraps these sources (the fixed point)`, `seed-windows.s is the current compiler`, the other two older compilers (from 657881f) as on Linux; exit 0, 5.7 s.

Nothing in `selfhost/`, `lib/` or `tools/` changed, so every target's assembly is BASE's (the compilers are byte-identical).
