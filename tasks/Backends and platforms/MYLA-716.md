[[MYLA-701]] (D209) made `std.platform`'s errors cause codes, a directory's entries names and kinds, a file its kind, size and permissions, and processes and sockets capabilities a target declares; `tests/burn/test_platform_interface.py` holds the modules to one interface. Left, none needed before Windows' steps ([[MYLA-702]] on), each where a step will meet it:

- [ ] **The poller in Myla's terms.** (Left open: not in Windows wave 6's lane for this task, which took the error boxes; Windows' poller, [[MYLA-706]], is built on the shape as it is.) `poller_watch`, `poller_watch_socket` (`again`: armed once more, EPOLLONESHOT's shape), `poller_event(i)` and `poller_event_ready(i)` over a buffer of the last wait are epoll's form; wasm32 builds it on `poll_oneoff` (a legitimate implementation, not a translation: it stays), Windows will on IOCP ([[MYLA-706]]). A `POLLER` capability, and a wait that gives `(token, ready)` pairs, would let a target without one (and the interpreter) say so. `park` and `unpark_one` are futex's (`addr`, `seen`): wasm32's do nothing, as one worker needs; Windows' are `WaitOnAddress`/`WakeByAddressSingle`, the same shape, so they can stay.
- [x] **`Other`'s numbers on Windows.** std gives the causes an error type has no variant for Linux's numbers on every target (`code_number`: `Other(9)` a closed handle, `terminal error 22`, `SpawnError.WorkingDir(2)`), and wasm32 its unmapped errnos Linux's too ([[MYLA-426]]). A Windows code with no cause is `Other` of its own number (D129). Decide whether wasm32 keeps Linux's numbers or gives WASI's own (then `test_fs.py`'s `ERRNOS` changes there), and whether std's own (`Other(9)`, `Other(11)`, `Other(27)`, `Other(29)`) become causes of their own (`Closed`, `WouldBlock`, …), a change programs see.
- [x] **Texts of a failed write.** `std.rt`'s and `std.io`'s `errno_text` name ENOSPC, EIO, EFBIG and EDQUOT by Linux's numbers; a platform's `error_text(code)` would name its own (`ERROR_DISK_FULL`).
- [x] **`SpawnError.WorkingDir(int32)`** holds Linux's number of why (D189). Proposal: `WorkingDir(IoError)`, which needs `IoError` to be `Eq` (`SpawnError` derives it).
- [x] **std.http's `accept_fate`** keys EMFILE and ENFILE (`Other(24)`, `Other(23)`): Windows' `WSAEMFILE` needs a cause (`TooManyOpen`?) or its own number there.
- [x] **`from_errno`** stays for programs that hold a Linux errno; nothing in std calls it. Remove it, or keep it documented as Linux's.
- [x] **wasm32's devices.** WASI's file types name block and character devices and sockets; wasm32's module gives them `KIND_OTHER`, as its made-up modes did, so `FileKind` stays what it was. Giving WASI's own is a change programs see there.
- [ ] **One Linux layer** (Left open: proposal 6 below sizes it; it changes x86-64 Linux's assembly, so it isn't contained) ([[MYLA-265]]'s second box): `platform.my` and `platform_aarch64.my` still differ only in system-call numbers, `struct stat`'s mode offset and a few `*at` calls; the changes of MYLA-701 were made twice.

## What changed

**Windows' own codes** ([[lib/std/platform_windows.my]]). A Windows error with no cause is `Other` of Windows' own code (D219's letter; D220's Linux numbers are gone): `cause` gives `OTHER + e`, and `linux_errno` is removed; `wsa_cause` gives a Winsock code without a cause its own number too (`WSAENOBUFS` `Other(10055)`, was ENOBUFS' 105). Where the module finds an error itself that Windows names, it gives Windows' code: a name past 255 units `Other(206)` (FILENAME_EXCED_RANGE; was ENAMETOOLONG's 36, `path_failed`), a program that isn't one `Other(193)` (BAD_EXE_FORMAT; was ENOEXEC's 8, `create_child`), an NTSTATUS not mapped `Other(1117)` (IO_DEVICE; was EIO's 5, `status_cause`, `random_fill`). std.process's documented `Other(10)` (a child already reaped, `try_reap`) and `Other(3)` (`kill`) stay std's numbers. On Linux and wasm32 nothing changes: an `Other` is Linux's errno (wasm32's WASI errnos as Linux's, [[MYLA-426]]).

**A failed write's words, per target** ([[lib/std/system_error.my]], [[lib/std/system_error_windows.my]], new). `error_text(n: int64) -> str` names a system's own code: Linux's (`no space left on device`, `input/output error`, `file too large`, `disk quota exceeded`, else `errno 71`), Windows' as its messages say them (`there is not enough space on the disk` for ERROR_DISK_FULL, `the disk is full`, the I/O device's, CRC's, a file too large, a quota, else `Windows error 1392`). A module per target as std.path_style is (D223): the loader's `for_target` takes `std/system_error_windows.my` for `std/system_error.my` on Windows (one line in [[selfhost/loader.my]], `own_copy`). std.rt's and std.io's `errno_text` call it for a code past OTHER; a handle that isn't open (`bad file descriptor`) and a cause std numbers itself (`errno 22`) are as before. Its import costs checking a program that imports std.io 48.6 M → 49.2 M instructions (valgrind's count, this branch's tools, the library copied out of the repository with io.my with and without it, 2026-11-16).

**Two causes std.http acts on** ([[lib/std/ioerror.my]], every platform module). `TOO_MANY_OPEN` (36: EMFILE, Windows' TOO_MANY_OPEN_FILES and WSAEMFILE, and Windows' own table of watched handles full in `pipe_pair`, `sock_open`, `sock_accept`) and `TOO_MANY_OPEN_SYSTEM` (37: ENFILE), shown as `Other(24)` and `Other(23)` on every target (`code_number`, LINUX_NUMBERS and std.rt's CAUSE_NUMBERS), so [[lib/std/http.my]]'s `accept_fate` waits and accepts again on Windows too, its code unchanged; Linux's output is the same.

**`SpawnError.WorkingDir(IoError)`** ([[lib/std/process.my]]). `IoError` derives `Eq`; `spawn_error_from_cause` gives `WorkingDir(from_cause(code))`, the same cause on every target; `message()` says what it said for `NotFound`, `NotADirectory` and `PermissionDenied`, and `could not enter the working directory: <the IoError>` for the rest (was `…: errno 5`). The `#test` cases of `message`, `dir_message`, `spawn_error_from_cause` and `spawn_errors` change with the type (the Tests lane's file: only those lines). `examples/subprocess/main.my` and `tests/burn/test_process.py`'s pin (`working directory 2` → `working directory not found (NotFound)`, the type's change) follow.

**`from_errno`** stays, documented as reading a Linux errno on every target (std.ioerror's and std.fs' pages); nothing in std calls it.

**wasm32's devices** ([[lib/std/platform_wasm.my]]'s `kind_of_type`): WASI's block and character devices and its sockets are `BlockDevice`, `CharDevice` and `Socket`, as on Linux (were `Other`).

**Docs.** [[Language/Standard-library/Ioerror]] (the new causes, "System codes"), [[Language/Standard-library/Io]] (`errno_text`), [[Language/Standard-library/Process]], [[Language/Standard-library/Fs]], [[Language/Standard-library]] (std.system_error), [[Architecture/Module-loader]] (Windows' third copy), [[Architecture/Native-backend]], the `myla` skill's stdlib reference (both copies).

## Proposals

1. **A Windows code with no cause is `Other` of Windows' own code, and a failed write says the target's words for it** (built). Programs on Windows see `Other(112)` for a full disk and `write failed: there is not enough space on the disk`; on Linux and wasm32 nothing changes. Alternatives: *(a)* keep D220 (Linux's errno where one means the same, else 4096 plus the code) and only give Windows' fallback its own words: an `Other` reads alike on every target, but a Windows program's numbers are neither Windows' nor always Linux's, and `Other(5488)` means 1392; *(b)* Windows' codes past 4096 always (never taken for a Linux number), which no Windows reader recognises; *(c)* `FormatMessageW` at run time: every code, in the user's language, but under Wine its texts are Wine's own (`Disk full.`) and a program's output would depend on the machine's language; *(d)* `error_text` in each platform module beside `cause`, reached from std.io through a new primitive `__error_text`: one table per platform and the interpreter gets its host's words without [[MYLA-723]], but a primitive on every target and the interpreter, and a `Stage:` commit of the three seeds; the module per target (D223) needs neither. wasm32 keeps Linux's numbers (WASI's own would change `test_fs.py`'s `ERRNOS` there and make the same name read differently from Linux's). std's own numbers (`Other(9)` a closed handle, `Other(11)`, `Other(27)`, `Other(10)`) stay std's on every target, as D219 says: causes of their own (`Closed`, `WouldBlock`) would be variants of `IoError`, which breaks every program's exhaustive `match` of it. Until [[MYLA-723]], `myla run` under a Windows `myla.exe` loads Linux's std.system_error and says Linux's words for Windows' numbers; [[MYLA-770]] is `SpawnError.Other`'s `errno N`. Proposed row: *"A Windows error code with no cause is `Other` of Windows' own code ([[MYLA-716]], supersedes D220; D219's letter): `ERROR_DISK_FULL` is `Other(112)`; where the platform module finds an error Windows names, Windows' code for it (a name past 255 units `Other(206)`). A failed write says a system's code in the target's words, std.system_error's `error_text`, a module per target (D223): `strerror`'s on Linux and wasm32, Windows' messages on Windows (`there is not enough space on the disk`, else `Windows error N`). wasm32 keeps Linux's numbers, and std's own numbers (`Other(9)`, …) stay the same on every target."*
2. **`SpawnError.WorkingDir(IoError)`** (built), `IoError` `Eq`. Alternatives: keep `int32`, which is std's (Linux's) number on every target and can't hold Windows' own codes; an enum of its own for the directory's causes, a second type for the same causes. Proposed row: *"`SpawnError.WorkingDir` holds the `IoError` of why the directory can't be entered, the same cause on every target ([[MYLA-716]], refining D189), and `IoError` is `Eq`."*
3. **Too many open descriptors is a cause std acts on, `TOO_MANY_OPEN` (36) and `TOO_MANY_OPEN_SYSTEM` (37), `Other(24)` and `Other(23)` on every target** (built), so std.http's `accept_fate` reads it on Windows with no Windows number. Alternatives: an `IoError` variant `TooManyOpen` (clearer to programs, but every exhaustive `match` of `IoError` breaks); `accept_fate` comparing each system's numbers (`Other(10024)`, `Other(4)` on Windows: a system's number read above the platform, which D219 forbids); one cause for both (ENFILE's `Other(23)` would become 24 on Linux). Proposed row: *"Running out of descriptors or handles is a cause code std acts on, `TOO_MANY_OPEN` and `TOO_MANY_OPEN_SYSTEM`, which an `IoError` shows as `Other(24)` and `Other(23)` on every target ([[MYLA-716]], D219): Linux's EMFILE and ENFILE, Windows' TOO_MANY_OPEN_FILES and WSAEMFILE."*
4. **`from_errno` stays, documented as Linux's** (built: the docs). Alternatives: remove it (a program's and std.fs' re-export break, with `test_fs.py` and the parity program that use it); rename it `from_linux_errno` (clearer, the same break). Proposed row: *"`from_errno` reads a Linux errno on every target, for a program that holds one; std gives cause codes and never calls it ([[MYLA-716]])."*
5. **wasm32's devices and sockets are their kinds** (built: four lines of `kind_of_type`): `fs.metadata("/dev/null")` is `CharDevice` under Node as on Linux. Alternative: keep `Other` (what the made-up modes gave). Proposed row: *"wasm32 gives WASI's block and character devices and sockets their `FileKind`, as Linux does ([[MYLA-716]])."*
6. **One Linux layer** (not built). `platform.my` and `platform_aarch64.my` are 2,083 and 2,096 lines and differ in 47 places, 229 lines: 158 of them system-call numbers, 44 code (the `*at` calls, `AT_FDCWD`, `clone` for `fork`, `ppoll`, `epoll_pwait`, `stat`'s mode offset, `EVENT_DATA`), the rest comments. A contained form doesn't exist: either x86-64 moves to the generic calls (`openat`, `mkdirat`, `unlinkat`, `renameat2`, `dup3`, `ppoll`, `epoll_pwait`, `clone`), which changes its assembly in every program, then the numbers and the two layout constants go into a per-architecture copy module (`std/linux_calls.my` and `linux_calls_aarch64.my`, D223) and `platform_aarch64.my` goes, about 250 lines changed and the target record's `platform_file` ""; or a shared `platform_linux.my` that both import, which needs every one of the 85 `pub` functions declared again in each module for the interface test and the loader's one-module-per-target. Recommended: the first, as a task of its own after Windows' wave, with an `strace` comparison of the suites on x86-64. Proposed row: *"Linux's platform layer is one module on both architectures, over the generic system calls; the numbers and layouts are a per-architecture copy (D223)."*
