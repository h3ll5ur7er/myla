The numeric toolbox that `std.jpeg`, `std.imgproc`, `std.ai` and the planned GUI system will build on. The owner's shape (2026-11-13): the common fixed sizes as their own types, plus a slower generic type of any size whose dimensions are checked at run time.

- `std.vector`: `Vec2`, `Vec3`, `Vec4` (structs `{ x, y[, z[, w]] }`), and `Vector`, any length (`[float]` inside; a size mismatch is a runtime error that names both sizes).
- `std.matrix`: `Mat2`, `Mat3`, `Mat4`, and `Matrix`, any `rows × cols` (one flat list inside; shapes checked at run time).
- `std.quaternion`: `Quat` (from axis and angle, from Euler angles, to `Mat3`/`Mat4`, `slerp`, rotating a `Vec3`).
- Operators wherever they read naturally, through [[MYLA-612]]: `+ -` between same-sized values, `*` and `/` by a scalar on either side, `Mat * Vec`, `Mat * Mat`, `Quat * Quat`, `Quat * Vec3`, unary `-`, and the compound forms (`pos += vel * dt`). Named methods for the rest: `dot`, `cross`, `length`, `length_squared`, `normalized`, `distance`, `lerp`, `transpose`, `determinant`, `inverse` (an `Option`), `identity`, the 3D transforms (`translation`, `rotation_*`, `scaling`, `look_at`, `perspective`, `orthographic`).
- `#derive(Eq, Hash)` (with [[MYLA-586]]), `impl Format` (`f"{v}"` as `(1, 2, 3)`), `#derive(Json)` where it fits.

Depends on [[MYLA-612]] (operators between different types) and [[MYLA-585]] (float methods). Building it first with methods only would give the library an API to rewrite.

## Open questions for the owner

- [x] Element type (D201: both; `std.vector32` etc., the float32 twins, generated with the float64 modules from one template): `float64` only (Myla's `float`); also `float32` variants for graphics and GPU upload (`Vec3f`/`Mat4f`, or `Vec3<T>` generic with `T: Float`, which needs a numeric trait and spells `Vec3<float>` everywhere since type parameters have no defaults)
- [x] Matrix storage and multiplication convention (D201: column-major, column vectors, right-handed): column-major and column vectors (OpenGL, glam, most GPU APIs) or row-major
- [x] Construction (D201: free functions and `std.algebra`'s `Zero`, `One`, `Identity`): Myla has no static functions, so `vector.vec3(1.0, 2.0, 3.0)`, the struct literal after `from std.vector import Vec3`, and `Vec3.zero()` through a trait with functions without `self` (D172), say `Zero`/`One`/`Identity` in a small `std.num`-level trait module
- [x] Indexing `v[0]` and `m[r, c]` needs an `Index` trait (done in MYLA-612: `v[0]`, `m[(r, c)]`, `m[i]` a column) (an open question in [[MYLA-612]]); until then `v.at(i)`, `m.at(r, c)`

### Follow-ups (2026-11-13)

- Benchmarks: `benchmarks/linalg_std.my` (`std.bench`, the library against the same work by hand; its by-hand versions have `#test` cases, which `test_linalg` runs). Natively, the fastest of each, on a shared 4-core x86-64 machine:
  - `MatN * VecN` summed scaled columns, building a vector for each. Summing each component's products instead: `Mat4 * Vec4` went from 26.7 to 19.7 ns, the same as the 16 products written on the fields (19.5 ns). `Mat4 * Mat4` went from 101 to 76 ns, against 142 ns for a triple loop over `[float]`. The sums keep their order, so results are bit-identical, and `examples/transforms.my` prints the same pixels.
  - `Vector`'s `+ - *` and scaling called a closure per element (`zip_with`, `map`). As loops, `Vector + Vector` (1000 elements) went from 3.12 to 2.03 µs, the same as the loop by hand (2.04 µs). `Vector.dot` is 1.08 µs against 0.95 µs by hand (it checks the lengths first). `Matrix * Matrix` at 4x4 is 160 ns against 142 ns.
- JSON (D203): arrays as glTF writes them; `Vector` an array, `Matrix` `{rows, cols, data}`. Errors carry their path, and a `Matrix` whose data doesn't fit its shape is an error at `$.data`. std.json's `within` is now public for impls written by hand. Measured cost of the std.json import, before the impls: checking a program that uses std.vector went from 34 to 47 ms, building it from 148 to 174 ms. `test_linalg`'s `Json` test was written first and failed (`field 'translation' has type 'vector.Vec3', which isn't ToJson and FromJson`). It now passes interpreted, natively, on wasm32 and on aarch64 (qemu). Module cases, interpreted and `--native`: vector and vector32 21/21, matrix and matrix32 11/11, quaternion and quaternion32 4/4, json 103/103.
