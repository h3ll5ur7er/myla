`render_arg` in [[selfhost/codegen.my]] (around line 2586) has no `TChar` or `TFloat` arm, so the value is used as a string pointer. `format("{}", 'a')` and `f"{c}"` with a `char` crash.

## Done when

- [x] `TChar` renders through `__char_to_str` (the self-hosted runtime had none; it now embeds the Python backend's, generated by `scripts/gen_selfhost_runtime.py`)
- [x] `TFloat` renders through `__float_to_str` ([[MYLA-29]]); both covered by the parity program `floats_in_depth`, also run through the self-hosted compiler
- [x] Differential test: the parity program `format_renders_chars` (`format` and f-strings with ASCII and multi-byte chars, a char field, chars next to floats and bools) runs through both native backends and the self-hosted compiler against the interpreter

## Evidence

- `test_compiler_parity.TestCompilerParity.test_format_renders_chars` and `test_selfhost_codegen…test_parity_programs_match_the_oracle` pass. With the `TChar` arm of the lowering's format helper choice removed, `format_renders_chars` and `floats_in_depth` fail.
