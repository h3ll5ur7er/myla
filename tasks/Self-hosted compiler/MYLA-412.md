Found by [[MYLA-359]]. With the implicit modules' bodies parsed only once called, a hello world's check is 39.4 M instructions (about 9.5 ms on the development container; 1.8 M and 1.2 ms without the implicit modules). What is left is reading their signatures on every check: lexing 16.8 M (decoding the 300 KB of text to code points 2.5 M, skipping the bodies and `#test` cases 4 M, the signatures, comments and declarations the rest), parsing 3.7 M, renaming 1.9 M, recording the bodies left 1.4 M; and registering the 1,100 methods in the checker (`resolve_impls`, 4.9 M). The embedded library's text is fixed per build, so all but the last could be done once, at build time.

- [x] `scripts/bootstrap.sh` (which generates `selfhost/embedded_std.my`) also stores the seven modules' loaded and renamed declarations, with their bodies' sites, in a form the loader reads faster than it parses the text (a compact binary or Myla literal; node ids relative to the module's first, so the loader can place them) — every module of `std` but std.rt, parsed (not renamed: see "What is left"), the implicit modules' bodies parsed too
- [x] The loader uses it when the library is the embedded one and no override replaces an implicit module's file; a `--stdlib`/`MYLA_STDLIB` library is read as now — keyed by the file's text instead: a `--stdlib` directory whose file is the embedded text (an unedited `lib/`) uses it too, an edited or other one is parsed as before
- [x] Measured with callgrind and CPU time on a hello world, `examples/maps.my`, a program importing std.io and `check selfhost/main.my`; the estimate is 39.4 M → about 20 M (5 ms), the reading of the cache included

Alternatives: lazy signatures (an impl's methods registered only once a method of their name is called, which needs the checker's method lookup to fall back on a name index); a smaller std.int (its eight impls generated by `scripts/gen_std_int.py`, half of what is left).

Since [[MYLA-413]] ([[MYLA-432]], 2026-11-11) every imported module of `std` but std.rt has its bodies read once called too, so an import costs its modules' signatures and the bodies it calls: `myla check --stdlib lib` of a hello world 41.3 M instructions (the implicit modules' signatures, as above), with `from std.io import println` 60.6 M, with `import std.http` 201.1 M. A cache of every module's signatures, not only the implicit seven's, would take most of the rest.

## What changed

- **The form** ([[selfhost/astcache.my]], new): `cache_entry(src, with_bodies)` encodes `parse_source_lazy(src, 0)` as text: a string table, then the declarations, the bodies' sites (each with where its body's text is in the file's bytes and where its parse starts in the entry, -1 for none), the next node id, and with `with_bodies` the bodies parsed (`parse_body`). Numbers are printable digits (base 32 then a last base-64 digit), signed ones zigzagged; a node's id and line are differences with the last ones written, so every id is relative to the module's first (a body's to its site's) and is placed by `decode(entry, first_id)` for free; a name the parser makes of a node's id (`%for12`, `%index7`) is a prefix and a relative id. Writer and reader cover the whole AST (every kind of declaration, type, pattern, statement and expression, attributes and constants), as a body the lexer didn't skip is in the declarations. The entry is kept only if it is sound: the parse at a second first id (`PROBE_BASE`) encodes to the same entry (every id moved, nothing else), the entry decodes and re-encodes to itself, and every body cut out of the text by its bytes (`body_part`) parses as the one in the module's code points; else `""` (the module is then parsed on every use; `embed` warns, and `stdroot`'s case `carried_unparsed` fails).
- **Written when the toolchain is built** ([[tools/embed/main.my]]): the embedding tool, which `scripts/bootstrap.sh` runs before stage 1, writes `embedded_cache(path)` into `selfhost/embedded_std.my` beside `embedded_file(path)`: an entry for every module of `std` but std.rt (which the loader parses whole), with bodies for the seven implicit ones (`with_bodies`). `embed --check` checks it too, so `test_embedded_std` fails on a stale one. The seed's stub library in [[scripts/host.sh]] has an empty `embedded_cache`.
- **Read by the loader** ([[selfhost/loader.my]]): `parse_module` asks `Loader.cached` before `parse_source_lazy`: the file's path under the stdlib root (`std/io.my`), and `stdroot.embedded_parse(rel, src)`, which gives the entry only when `src` is the embedded file's text (one string comparison; the same cell for the built-in library). A module read so keeps its text and its bodies' byte places instead of its code points (`Module.src`, `Module.bytes`, `Module.bodies`), so the 300 KB are no longer decoded to code points; `LazyTable.body_text` cuts a body's code points out of the text when it is read (and for `task_line`), and `read_parsed` takes the cached parse of an implicit module's body (`cached_body`) before parsing its text. `LazyTable.bodies` is a list and `keys` maps each `body_key` to its index (one small map instead of two, one of them of whole bodies): `LazyBodies.keys` is `[int64: int32]` in [[selfhost/checker.my]] (the type and a sentence of its comment). `Renamer.ty` returns a type it doesn't change without arguments as it is.

## Decisions (proposals)

1. **The key is the file's text**, not "the library is the embedded one": the loader uses the parse wherever the module's text is byte for byte the text the parse was made of, so `--stdlib lib` with an unedited `lib/` (every contributor and the burn suite) gets it, and an edited file, another library or an editor's buffer is parsed. Alternative: only for the embedded root (`<myla>`), as the task said; it would leave `--stdlib lib` at the old cost. Recommended as built: the parse is a function of the text alone, which the two-base check confirms per module.
2. **Parsed, not renamed, declarations.** The parse depends on the text only; the renaming also on the other modules' exports and the program's kinds, and caching it would need a key over the module's import closure and a second copy of the declarations (the loader needs the unrenamed ones for exports, bindings and the bodies). Renaming the implicit modules costs a hello world 2.5 M. Alternative: cache renamed declarations keyed by the import closure's texts.
3. **Bodies parsed only for the implicit modules.** With every module's bodies parsed in the cache, `import std.http` checks in 114.6 M instead of 145.3 M and std.io 33.8 M instead of 36.7 M, but `selfhost/embedded_std.my` is 5.0 MB instead of 3.1 MB (2.5 MB before) and `build/myla` 8.0 MB instead of 6.1 MB (5.5 MB before; each stage's assembly 31 MB instead of 23.6 MB). Recommended as built: every program reads the implicit modules' bodies, another module's only when imported; the switch is `with_bodies` in `tools/embed/main.my`.
4. **The cache is as current as `embedded_std.my`.** It is the parse of the parser the embedding tool was built from, so a compiler built from sources whose parser changed but whose `embedded_std.my` wasn't rewritten (no bootstrap) reads an old parse of an unedited library. The bootstrap rewrites it before stage 1, and `test_embedded_std` (`embed --check`) and CI's seed check fail on a stale one, as for the library's text. Alternative: a fingerprint of the parser's sources in the entry, which the compiler can't compute about itself.

## What is left

A hello world's check is 20.9 M instructions (5.8 ms): the checker 14.7 M (registering the implicit modules' methods, `resolve_impls`, 5.0 M; checking the 205 bodies 4.3 M; `collect_globals` 1.1 M, `synthesize_derives` 1.0 M, `resolve_signatures` 0.7 M), reading the cache 3.2 M (2.0 M the declarations, 0.4 M the strings of the bodies, which could be read only with the bodies), renaming 2.5 M (proposal 2), recording the bodies 0.8 M, and 0.5 M of the runtime's idle workers at exit (`exec_idle`). Under 5 ms ([[MYLA-359]]) now needs the checker's part: lazy signatures (an impl's methods registered only once a method of their name is called) or a smaller std.int, as above.
