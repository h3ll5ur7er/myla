Left of the first box, and why: the panic's position ([[MYLA-435]], a library function reporting its caller's place, as Rust's `#[track_caller]`) needs a language feature, which that task is; and a flag named `help` or short `h` stays the spec's own (the proposal below).

## What was built

- **`std.args`' spec checks** ([[lib/std/args.my]]). A panic where the spec is built, as for the other mistakes ([[MYLA-426]]), for: a positional after `many` or after a command (positionals are read before them whatever the order, so one declared after them would look like a last argument, `cp <from>... <to>`, which the parser doesn't have); `many` twice (the second replaced the first); a command whose name is empty, starts with `-` or holds a space or a control character (it could never be given: an argument starting with `-` is an option); an option's name with a space or a control character (it is typed as one argument; a positional's name is only shown in the help, `<lib dir>`, so `tools/embed/main.my`'s `positional("lib dir")` stays right); the short name `=` (as a long name holds no `=`). A private `printed(name)` tests the bytes. The repro's 25 specs (`repro-r5/std/spec.my`): before, `space`, `short-eq`, `many-twice`, `cmd-empty`, `cmd-dash` and `opt-pos-after-cmd` were accepted and `many-then-pos` built and then read its first argument as the positional; now each panics with its reason, and `help-name`, `help-short`, `opt-empty-value` and `pos-cmd-same` are accepted as before. [[Language/Standard-library/Args]] lists the new checks and says what a spec's own `help` does.
- **`iter()`** (D171): `BitSet.iter()` is a `BitSetIter` (the words, the word it is in and its bits not visited yet: a word at a time, as `items()`, without the list) ([[lib/std/bitset.my]]); `Lru.iter()` an `LruIter<K, V>` that walks the recency list from the head, giving `(K, V)` and changing no order ([[lib/std/cache.my]]); `Grid.iter()` the cells' `ListIter<T>`, row by row ([[lib/std/grid.my]]). Each has a test function (the order, word boundaries, empty and fixed sets, evictions and removals, a copy's own position); their pages say so, and the two pages' sentences that `for i in b` waits for [[MYLA-353]] are now that a set isn't an iterator itself.
- **The checker's hint** ([[selfhost/checker.my]], one call in `check_for`, the checker lane's file): `for x in s` over a type with an `iter()` method now carries the `help` that a pipeline's bound already gave (`iter_hint`, [[MYLA-383]]): `help: 'set.Set<int32>' is not an Iterator: write 's.iter()'`. Pinned in `examples/errors/type_for_over_a_set_needs_iter.my` and its `.stderr`.
- **The heapsort** ([[lib/std/list.my]] `sort_unstable_falls_back_to_heapsort`): the old input's heapsort sorts 72 elements, and with an even count the last parent has one child, which the first extraction moves to the top anyway, so a heap built from `n / 2 - 1` down sorted them too (the mutant is equivalent for even counts). The new input is McIlroy's adversary run against 91 elements (a scratch port of the quicksort with the adversary's comparison), whose heapsort sorts 63, with the last parent holding the least of them and its left child, which stays, the greatest.
- **`xs == ys`**: `args.same` is gone (its seven calls are `a.all("out") == ["a.out"]` and so on), and `encoding.same_bytes` too (`decodes_to` compares `got == want`).
- **The import's cost, measured again.** `myla check` of a program that uses each module, against a copy of `lib/` where the module imports std.encoding and calls its function instead of its own copy (callgrind; the base the toolchain's cached parse of today's `lib/`): std.fs +1.42 M instructions on 42.37 M (+3.4 %, 11.3 → 11.6 ms best of 15), std.digest +1.82 M on 236.56 M (+0.8 %), std.net +1.37 M on 74.58 M (+1.8 %), std.archive +1.51 M on 126.82 M (+1.2 %), std.compress +1.82 M on 97.26 M (+1.9 %). So std.digest now shares `hex_encode` (its HMACs' hex; `hex_of` and its case went), std.fs keeps its copy (3.4 % on every program that imports it, for the names of temporary files) with today's number, and std.net, std.archive and std.compress keep theirs, which only the tests call: a lazy module's function nobody calls isn't checked, so the copies cost an importer nothing and the import would cost 1.2 to 1.9 %. The comments and [[Development/Conventions]]' sentence say so. (`lib/std/task.my`'s comment at line 476, "about 2.5 ms of checking", is of the same kind and in another lane's file: not changed.)

## Proposal (open for the owner): a spec's own `help`

The review counted a flag named `help` or short `h` as a spec that shadows the built-in help. It is documented and tested as a feature: `-h` is the spec's own when it gives `h` to an option (`--here`), and a spec that declares `help` (`flag("help", 'h', "…")`, or `option("help", …)` for `--help TOPIC`) takes `--help` as its own argument, gives no `Help` error, and its help lists its own line in place of the built-in one. Recommended and built: keep it (now said on [[Language/Standard-library/Args]]). The alternative: panic on a name `help` (a program that wants its own help then can't have `--help`), or panic only on a flag `help` without a short `h`.
