Work package R6 of [[Project/Review-2026-11-12]]. Files: `lib/std/rt.my`, `lib/std/net.my`, `lib/std/term.my`, `lib/std/process.my`, the platform modules. Follows [[MYLA-419]] and [[MYLA-426]]. Decisions 2 and 5 of the review are the owner's.

- [x] **`net.line_reader` has no line limit** and holds about three times the line (a 512 MiB line: 1.59 GB), so a peer that never sends `\n` ends the program with `out of memory`. A `net.line_reader_with(s, max_line)` that gives an `IoError` past the limit (`repro-r5/runtime/longline.my`)
- [x] **The poller's creation isn't checked**: under `ulimit -n 64` with `MYLA_THREADS=1` and no descriptor left, the first `read_async` hangs for good; a failed `os.poller_new()` should fail the wait with its errno (`emfile2.my`)
- [x] **A failure doesn't end the program while another task blocks in a key read**: the error is printed, the terminal stays raw, and a worker spins at 99 percent of a CPU until a key is pressed; `exit(4)` in a task waits the same way (`rawblock.my` with `t_rawblock.py`, 4 workers). In `wait_stopped`: run the exit hook before the wait, bound the wait, don't spin (D187)
- [x] **Raw mode and signals** (decision 2, decided as recommended: D192): SIGINT, SIGTERM, SIGHUP, SIGQUIT leave the terminal raw, as the Term page says. Recommended: catch them while raw, restore, and end as the signal would
- [x] **`Signals` as a D181 handle**: `Signals { handle: 0 }.try_next()` consumes a byte of stdin, and `close()` on any copy or forged value stops the real listening (`sig2.my`)
- [x] **`Notifier.close()` beside a wait that is starting** (decision 5, decided as recommended: D195): six waiters closed 1 ms after they announced themselves died with `use of a closed notifier` in 2 of 9 runs (`nstress.my`). Recommended: a wait on a closed notifier returns at once; otherwise Concurrency.md must say that a closer has to know its waiters are parked
- [x] More than 2^20 live notifiers is `too many notifiers open` interpreted and fine natively (`manyn.my`): one limit, documented
- [x] A double close is `Ok` on a `TcpStream` and a `TcpListener`, `Other(9)` on a `File` and a `ChildStdin`
- [x] `LineReader` gives a line cut off by the peer's close as an ordinary line; the caller can't tell
- [x] `net.listen`'s backlog is fixed at 128 (100 connects at once on one loaded worker: up to a quarter reset by the kernel): a `listen_with(backlog)`
- [x] `io.buffered(s).read_line()` in a task is a silent hang with more connections than workers; the type error for `buffered(s).read_line_async()` should point to `net.line_reader`. The type error points there and the Io page says it (round 6); the hang now says so on stderr after a second (round 6's follow-up, proposal 8)
- [x] `myla repl` loses a line longer than 4,095 bytes typed while the last one runs: the terminal is cooked between lines (`t_repl4.py`)

## What changed

**The line limit.** `net.line_reader_with(s, max_line)` ([[lib/std/net.my]]): a line longer than `max_line` bytes (without its `"\n"`) is `InvalidData` as soon as more than `max_line` bytes of it are there, and so is every call after it, which reads nothing more, so the reader holds about `max_line` and one read's 4 KiB. A negative `max_line` is a runtime error (D184). `line_reader(s)` keeps no limit (proposal 1).

**The poller.** `std.rt` makes the reactor's poller at the start of a program with tasks (`sched_init`), while descriptors are free; `poller()` keeps no failed one (it stored -1 for good: the timers' waits then spun and the first `read_async` hung), so a later need tries again; `os.poller_new` gives minus the errno and closes the epoll descriptor when the eventfd fails (it kept it). Without a poller the timers are kept by naps of a millisecond (`exec_poll`), the glances skip it, no wake-up writes to descriptor 0, and a wait for a descriptor is the runtime error `no descriptor left to wait for input or output on (too many open files)` (proposal 3).

**A failure beside a blocked key read.** `wait_stopped` ([[lib/std/rt.my]]) runs the exit hook first (D187), spins 1,000 pauses, then sleeps a millisecond at a time, and gives up after `STOP_WAIT_MS` (1 s): the program ends with the failure's status. On one worker the key read holds the only worker, the failing task's too (documented on [[Language/Concurrency]]).

**Raw mode and signals (D192).** `std.platform`'s `raw_signal(sig)` on each target (a stub on wasm32) is the handler: it puts the terminal's mode back from the exit hook's block and sends the signal again; installed with SA_RESETHAND and SA_NODEFER, the default is back as it runs, so the program ends by the signal. It allocates nothing. The code generator names it `__on_raw_signal` in every program (`rt_exec`, [[selfhost/codegen.my]]; `backend_std_functions` in [[selfhost/checker.my]]): the staging of D156. `raw_signals(on)` installs it for SIGHUP, SIGINT, SIGQUIT and SIGTERM where the handler is the default (`__term_raw` and `__term_cbreak` with the hook), and takes it off where it is theirs (`__term_set` that leaves raw mode); `catch_signal` gives it its own flags, and std.signal letting go puts it back while the terminal is raw (`signal_listen`). A signal ignored (`nohup`) or listened for is left alone; the other signals aren't the decision's (SIGUSR1 and SIGALRM still leave the terminal raw, as does SIGKILL).

**`Signals` as a D181 handle.** Each `signal.listen()` gets a handle of its own in the runtime's table (kind H_FD, for the self-pipe's read end); `close()` passes it (`__signal_listen(h)`), so a second close or one through a value built by hand is EBADF and lets go of nothing; `__signal_take` takes only a listener's handle (`os.signal_fd()` names the pipe). A `next()` on a value built by hand with a small number still waits until that descriptor is readable (it takes nothing, and then fails), as `__wait_readable` passes descriptors 0 to 2 on.

**Notifiers (D195, one limit).** A wait, a `wait_timeout` or a `listen` on a closed notifier gives false at once (a listener's waits do), through any copy, as does a wait that was starting while it closed; a forged handle stays `use of a closed notifier`, as do a wake and a second close. Natively a closed handle is told from a forged one by the numbers given so far (`handle_given`: given in increasing order, never twice), interpreted by the notifiers made (`notif_given`, [[selfhost/interp.my]], whose handles now keep 31 bits for the slot, so as many may be open as memory holds, as natively). Proposals 5 and 6.

**A double close** of a `TcpStream`, `TcpListener` or `UdpSocket` through the same value is `Other(9)`, as through a copy, and as a `File`'s and a child's pipe's are (proposal 2). `test_net`'s ERRORS program pinned the old `Ok` and is updated.

**A line cut off.** `LineReader.cut_off()`: whether the line given last ended at the end of the stream without a `"\n"`.

**The backlog.** `net.listen_with(a, backlog)`; `listen` is `listen_with(a, 128)`. A backlog below 1 is a runtime error (D184).

**`io.buffered(s).read_line_async()` on a socket.** The checker's help for the unmet `Pollable` bound of a `TcpStream` names `net.line_reader` (`json_help`, a small change in [[selfhost/checker.my]]), pinned in `examples/errors/type_buffered_tcp_stream_async.my`.

**The REPL's long line.** `std.term`'s `cbreak_mode()` over a new primitive `__term_cbreak` (a key at a time, echoed, signal keys and line ends kept; the exit hook and the signals as for raw mode), with the platforms' `term_make_cbreak`; `myla repl` holds it for the session, so between lines, while an input runs, the terminal isn't cooked and a line typed meanwhile reaches the editor whole (proposal 7). Staged as D156 says: the checker's side, a seed, then the interpreter's line and the uses.

**The hang said (round 6's follow-up).** A new primitive, `__tasks_waiting()` (an `int`): -1 in a program without tasks (the lowering's constant, as `__task_cancelled`'s 0; [[selfhost/lower.my]]), else whether another task waits for a worker that none is free to give it: natively std.rt's `tasks_waiting` ([[lib/std/rt.my]]: a frame queued, or no worker idle while timers or watched descriptors wait, as only an idle worker looks at them), interpreted another task ready, asleep or waiting for a descriptor (-1 outside any task, [[selfhost/interp.my]]); the checker types it and lists `std$rt$tasks_waiting` among the back end's names, and the lowering calls that routine where the primitive is used (`myla_runtime_function`), not in every program with tasks, so the tools' embedded library, behind `lib/` until the seed commit, still builds every program (named in every program with tasks, the routine was missing from it, and every such build without `--stdlib` failed: `no function 'std$rt$tasks_waiting' to compile`). std.net's `wait_ready` ([[lib/std/net.my]]), the wait of every blocking call (a read, a write, an accept, `connect_timeout`), waits in slices of 100 ms when the primitive isn't -1, and once it has held its worker for a second while the primitive says 1, writes `warning: a blocking wait for a socket has held its worker for a second while other tasks wait for one; in a task, use the async calls (lines: 'net.line_reader(s)' and 'await r.read_line_async()')` on stderr, once per wait, and waits the rest in one piece. A timeout is kept whole (the slices add up to it). No seed was staged: the compiler doesn't import std.net, the primitive's one user, so the bootstrap reaches its fixed point with the old seed (the integrator's seed carries it).

## Proposals (open decisions)

1. **`line_reader` keeps no limit**; `line_reader_with` sets one. Alternative: a default limit (Python's asyncio has 64 KiB, Go's `bufio.Scanner` 64 KiB) that breaks programs reading long lines. Recommended: as built, documented on the Net page: the default is `io.Buffered`'s and doesn't change what a program reads.
2. **A second close is `Other(9)` everywhere**, as D181 has any operation through a closed handle and as files and pipes had it. Alternative: `Ok` everywhere (Python's `close`), which would change files, pipes and every copy's close. Recommended: as built.
3. **No poller is a runtime error**, after the poller is made at the start. The task asked for the wait to fail with the errno; that can't be had reliably: the frame a failed wait queues may go on on another worker, whose errno is another, and the waits give no result. Alternatives: a result for the wait primitives (a change to the lowering of `__wait_*`), or a spin. Recommended: as built; with the poller made at the start it takes a program started with almost no descriptor.
4. **The end waits for the other workers 1 s at most.** MYLA-170's "for ever if it never reaches a suspension point" becomes "a second". Alternatives: no bound (a blocked worker holds the end for ever, as before), or a longer one. Recommended: as built, as the task's box asked.
5. **Closed and forged told apart by the handle's number**: a number no greater than the last handle given counts as closed, so a `Notifier` built from a once-given number of another kind gives false rather than the error. Alternative: tombstones for closed notifiers in the table (exact until the entry is reused, then the same question). Recommended: as built.
6. **`listen` on a closed notifier gives a listener whose waits give false**, as the waits do; D195 names the waits only. Alternative: `listen` stays the runtime error. Recommended: as built: `listen` is the first half of a wait.
7. **The REPL's terminal between lines is cbreak**: an input that reads standard input (`stdin().read_line()`) gets the keys as typed, without the terminal's line editing, echoed. Alternatives: cooked between lines (a line typed meanwhile is cut at 4,095 bytes), or raw (Ctrl-C couldn't stop an input that loops). Recommended: as built.
8. **The silent hang of a blocking socket read in a task: a warning from std.net's blocking waits, through a primitive that asks whether other tasks wait for a worker** (built in round 6's follow-up). The hang stays (a blocking read holds its worker by design, D180), but after a second of it while other tasks wait, the wait says so on stderr and names `net.line_reader`. The parts and their alternatives:

   *Accepted by the owner (2026-11-13): as built (100 ms slices, a warning once per wait after a second, interpreted too); no decision row.*
   - *Where it waits in slices*: in `std.net`'s `wait_ready`, the one wait of every blocking socket call, on every runner (as built). Alternatives: natively in std.rt's `sock_poll`, as first proposed (the interpreter's hang stays silent, and the message is the runtime's, not the module's); or a reactor wait for the blocking calls when in a task (the hang would go, but a blocking call would then suspend a task the caller didn't `await`, which the language doesn't allow).
   - *The primitive*: `__tasks_waiting()`, -1 without tasks, else 1 or 0 (as built): a program without tasks waits in one piece, exactly as before (one `poll` with no limit, by strace; a program with tasks: a `poll` of 100 ms each slice). Alternatives: `__in_task()` alone (a bool), with the queue's state read through more primitives; or a primitive that also writes the warning, once per program (the message would live in std.rt and the interpreter both).
   - *Once per wait* (as built): with four workers held by four reads, four lines, one per worker held. Alternative: once per program, which wants a runtime variable (another staging seed) and an interpreter field.
   - *A second, slices of 100 ms*: a slice is a `poll` that wakes ten times a second while a blocking call waits in a program with tasks. Alternatives: longer (a later warning) or shorter (more wake-ups).
   Recommended: as built. No decision row is needed beyond this task, unless the owner wants the warning's wording or its once-per-wait as a rule.
