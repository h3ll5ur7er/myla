## Proposals

1. **The seed at full size (D262).** At `MYLA_GENERATED=full` every case runs, so the seed draws nothing today (`sample` returns every name); the step still passes the run's number as `MYLA_GENERATED_SEED`, as D262 says, and a failure names it with the size, so a generator that later draws values or cuts a sample at full size uses it. Built: full size on every push to master. Alternatives: (a) the sample on master with the run's number as its seed instead of full size (74 s rather than 24 min, and the space turned over in about a dozen runs, never all of it at once); (b) both, the sample on every push and full size on a schedule (the workflow would need a `schedule` trigger and every other job a condition against it).
2. **Every push to master rather than a schedule.** Built: on every push, as a job of its own beside the others (it needs no apt, only the runner's binutils and the cached tools), so a failure names the commit. Alternative: nightly, which leaves a failing commit to be found among a day's merges.
3. **Master's runs are never cancelled.** Built: the concurrency group is `ci-<sha>` for a push (to master, the only branch the workflow runs on for a push) and `ci-<ref>` otherwise, cancelling only pull requests' runs; the `pages` job has a group of its own, one deploy at a time. Alternative: `cancel-in-progress: false` with the group per ref, which still cancels a pending run when a third arrives (GitHub keeps one pending run per group), so a master commit's artifacts could still be lost. What the pages group doesn't settle: an older run's deploy that starts after a newer one's puts the older site back until the next merge.
4. **The historical paths.** Built: a link into `src/myla/` or `tests/unit/` whose file moved is pointed at it (three); the others become plain paths, and the task gets one line at its end naming D101 and the tag `python-toolchain-final`. Alternatives: links to the tag's files on GitHub (their line numbers are the files' last state, not what the task saw), or a note at each link (83 notes).

A decision row for the integrator: "**A master commit's CI run is never cancelled** ([[MYLA-800]], D207): its concurrency group is its commit, so every master commit's seeds and tools are uploaded; a pull request's newer push cancels its older run" | "The review of 2026-11-17 ([[MYLA-629]]'s follow-up): `cancel-in-progress` on the branch's group let a second merge cancel the first one's run and its artifacts". And a clause for D262: "(2026-11-18) At full size every case runs, so the seed draws nothing; the run's number is passed and named in a failure for what later draws at full size ([[MYLA-800]])."
