## What changed

**H12: what a failed child gave, the rate, and two causes from the code.**
- *The case says why.* `test_windows.MANY_CHILDREN` is the review's diagnosing variant: each child that gives something else is a line on the standard error (`BAD round r child k (cat|args|sleep): exit N (hex), stdout … bytes […], stderr […]`, or `ERR round r child k (…): <SpawnError>`); the count stays on the standard output. [[scripts/windows-runner.py]]: a step that fails reports the program's standard error, checked or not (`its standard error b'…'`, 4,000 bytes), and the case's steps expect it empty.
- *The rate.* `windows-runner.py run --tally` runs every one of a repeated step's `--runs`, a line each (verdict, time, and on Windows the commit charge), then `rate <case> step <k> (…, <n> workers): N of M right, <fastest> to <slowest> s`. `process/many-children`'s steps (4 and 16 workers) repeat and sample the commit charge on Windows (`CommitSampler`: `GetPerformanceInfo`'s system commit at its peak against its limit and the most processes at once, `GetProcessMemoryInfo`'s peak of the program's own). CI's `windows` job has a step after the cases, `if: always()` and `continue-on-error`, so it reports and never fails the job: `--runs 10 --tally` of `process/many-children`, `process/a-child-s-commit` (a helper of 16 workers sleeping, its peak commit, Windows only) and `net/sockets-and-children`; the job's limit is 35 minutes (was 20).
- *Cause 1, the commit charge* (a hypothesis that fits: real Windows only, 16 workers only, intermittent). Windows counts committed memory against RAM plus the page file; Linux, and so Wine, overcommits. Every Windows program with tasks committed its workers' rings of ready frames at the start, 8 MiB each (EXEC_CAP frames, D106): a child of `many-children` inherits `MYLA_THREADS=16` and committed 128 MiB for rings it hardly touches, and 200 children run at once. Now `_start` reserves the rings ([[selfhost/runtime_x86.my]]: `VirtualAlloc` MEM_RESERVE with PAGE_READONLY as the mark) and `__win_on_fault` commits them as they are touched (`emit_windows_lazy_commit`: an access violation at private memory reserved PAGE_READONLY commits 64 KiB from the page and runs the access again, also when another thread committed it meanwhile; one Windows refuses is `runtime error: out of memory`). That check comes before the look near the stack pointer, as a worker's stack may lie right below the rings. A system call that writes into reserved memory fails instead of faulting (ERROR_NOACCESS), so only memory nothing but the program's code touches can be lazy: the heap's arenas still commit 16 MiB a worker that allocates ([[MYLA-861]]).
- *Cause 2, a failed read taken for the end.* [[lib/std/process.my]]'s `collect_async` (`output_async`, `run_async`) gives `Err(SpawnError.Other(cause))` once the child ended when a pipe fails to read, and Windows' `run_with` ([[lib/std/platform_windows.my]]) makes it the run's cause, as `output`'s other reads already did: the output was cut with nothing said. Linux's `run_with` does the same as Windows' did: [[MYLA-862]].
- *A smaller one.* A text input's temporary file is named by a number of the process's own (the pipes' counter) beside the time, and a name whose file is being deleted (ACCESS_DENIED: closed while its child still runs) is retried with another, as FILE_EXISTS was.

**M13.** std.rt's `getenv` ([[lib/std/rt.my]], `getenv`, new `same_folded`) matches a name's ASCII letters in either case on Windows (`os.TARGET`), as Windows compares them: `env("PATH")` is the system's `Path`, `env("MYLA_VAR")` finds `MyLa_Var`. `is_batch` drops the dots and spaces after the name before it looks at `.bat`/`.cmd`, as Windows drops them and as Rust does since CVE-2024-43402, so `x.bat.`, `x.bat ` and `x.bat. .` are run by cmd with cmd's quoting (they were `Other(193)` under Wine; on Windows CreateProcess would run them with the C runtime's quoting). `e.bat::$DATA` stays "not found".

**The deferred close's limit.** `ws_close_later`'s wait has a limit, `CLOSE_LATER_MS` (30 s): a peer that takes nothing in that time gets the close then, the send cancelled, so a socket or a pipe and its 256 KiB copy aren't kept for good (Linux gives up an orphaned socket's data after its zero-window probes, about a minute on loopback).

**Long paths (D261).** `path_wide` makes a path of 248 units or more (Rust's LEGACY_MAX_PATH) `GetFullPathNameW`'s absolute form after `\\?\` (`\\?\UNC\` for a share, `\\.\x` as `\\?\x`; `verbatim_units`), and one verbatim already stays: `open_handle`, `on_path` (CreateDirectoryW, RemoveDirectoryW), `remove_file` and `rename` take it.

**Verbatim paths in std.path** ([[lib/std/path_windows.my]], MYLA-704's follow-up): `join` onto a verbatim `a` (and a `b` without a prefix) is Rust's `PathBuf::push`: `b` split at either separator and joined with `\`, `.` left out, `..` taking away the name before it, none above the anchor, a rooted `b` going on from `a`'s prefix (`verbatim_join`); `normalize` gives a verbatim path as it is, as `ntpath.normpath` does.

**The console's code page after a default Ctrl-C** (MYLA-707's follow-up). `windows_start` adds the console's control handler when the program has a console, and the handler ([[selfhost/runtime_x86.my]], `emit_windows_ctrl_handler`) runs `raw_signal` for an interrupt or a terminate nobody listens for whether or not the console is raw: the code pages and output mode go back before Windows' default handler ends the process (they were left UTF-8). A runner case on Windows (`test_windows.RUNNER_CASES`' "a child that Windows' default handler ended puts the console's code page back", the CONSOLE program's new `code-page` mode and `wait plain`): `chcp 437`, a child ended by a Ctrl-Break, then `chcp` must say 437.

**`myla check --target`** ([[selfhost/main.my]], [[selfhost/driver.my]]'s new `load_for_target`, a few lines, outside this lane's files): the target's std.platform, std.path, std.path_style and std.system_error, as its build takes them.

**D254 under Node** ([[tools/wasm/node_fs.mjs]]'s `typeOf`, four lines, outside this lane's files): a block device is WASI's 1 and a socket 6, so `fs.metadata` gives `BlockDevice` and `Socket` as on Linux.

**`debug/dwarfdump`.** `windows-runner.py build` verifies the `-g` program's DWARF with Linux's `llvm-dwarfdump --verify` on the same file (`verify_dwarf`; the build fails if it doesn't verify), and the case that never ran on Windows' image is gone (`DEBUG_TOOLS` is llvm-symbolizer alone, so no skip is annotated).

**New runner cases** (Windows itself): `process/env-case`, `process/batch-names` (CVE-2024-43402's hole, which only Windows shows), `files/long-paths` (past MAX_PATH, which only Windows refuses), `process/a-child-s-commit`.

**A UTF-8 locale for Wine.** `tests/burn/_native.py`'s `wine_env` and the runner's `prepare_wine` set `LC_ALL=C.UTF-8` unless the locale is UTF-8 already: in the C locale an argument `é中` reached a Windows program as `C)d8-`.

## Proposals

Accepted by the owner on 2026-11-18 as D274 to D278.

1. **The deferred close waits 30 s at most** (built). Alternatives: as long as Linux's orphan probes take on loopback (about a minute); the socket's write timeout, which a close doesn't have; no limit with a cap on the number of closes waiting.
2. **Lazy commit for the rings only, by the fault handler** (built). Alternatives: commit the heap's arenas lazily too, which a system call writing into a fresh buffer breaks (ERROR_NOACCESS, no fault reaches the handler), so that needs the allocator to commit as its bump pointer moves ([[MYLA-861]]); smaller rings on Windows (EXEC_CAP is D106's, the same on every target).
3. **`env`'s names fold ASCII only** (built), as std.platform's `same_name` folds a child's environment; Windows folds all of Unicode's simple case mappings. Alternative: `CompareStringOrdinal` with ignore-case at each lookup, a system call per entry.
4. **The console's control handler is added at the start of every program with a console** (built), as the only way to put the code pages back after a default Ctrl-C. Alternative: leave the code page as it was put and say so (Rust and Go don't change it at all).

Proposed decision rows: *"On Windows a close whose send or write goes on waits for it at most 30 seconds, then cancels it ([[MYLA-798]], MYLA-706)."* *"A Windows program's workers' rings of ready frames are reserved and committed as they are touched ([[MYLA-798]], D106)."*

- **`files/long-paths` failed**: every operation NotFound (`true NotFound NotFound … false false NotFound ok false`). Why: `path_wide` measured the path as given, so a relative path short itself (make_dir_all's parents of about 220 to 247 units) reached Windows as it was, though past MAX_PATH once Windows made it absolute in the case's directory (`D:\a\myla\myla\windows-bundle\work\files-long-paths\…`); the first such parent failed, so nothing below it was made, and every later step found nothing. `/`, `.` and `..` were not it: `GetFullPathNameW` resolves them before the prefix. ## net/sockets-and-children on Windows (run 44239811699)

One run in 46 on real Windows failed: step 3, run 3 (16 workers), exit 2 after 201 s, `ask 19: connection failed: Cancelled` then `still running after 200 s, tasks:` (filed as [[MYLA-863]]). The suspect named first, the deferred close's new limit cancelling by handle a value reused by a new socket, is ruled out from the code: no `CancelIo` or `CancelIoEx` exists in std or the runtime; `ws_close_later`'s timeout runs `closesocket` on a handle that is still the program's own (closed only then, so no other socket can have its value), and the case's runs take a few seconds, never the 30 s. The output reads otherwise: the 20th HTTP request waited for an answer for the whole 200 s, and the time limit's cancel ended that wait as `Cancelled`. A reduced copy (a server that accepts and never answers, `get_async` inside `task.timeout`) prints exactly those two lines under Wine 9.0 and on Linux; every other task had ended (the list after `tasks:` is empty). What lost the request isn't known (MYLA-863). The program waited because nothing gave the request a limit: `SOCKETS`' `ask` now gives each request 30 s, so a recurrence says `ask N: timed out after … ms, K answered before` and the run ends with its count instead of waiting 200 s. Under Wine the case passes as before (`Sockets.test_many_sockets_and_children_at_once`).
