## Proposals

Open points the decisions leave, each built as recommended:

1. **D255 and a `std.my` file.** Built: a file `std.my` at the root is refused too, as [[Language/Modules]] said ("a project file or folder named `std` is an error"); its module id `std` collides with nothing today. Alternative: the folder only, as D255's words.
2. **Where a repeated impl is reported (D257).** Built: at the later of the two, unless that is the library's and the other the program's, then at the program's; the other named by a note (its place in the same file, its file and place in another, its module and file in the library). Alternative: always at the later one, which blamed `std/vector32.my` for a program's impl.
3. **The literal rule (D257's "the operators page states it").** Built and stated: a literal operand takes the type of the only impl of its kind (integer or float) on its side; with none or several of its kind it keeps its own type (`int32`, `float64`), which then needs an impl. Alternative: prefer the default type among several, or refuse several as ambiguous.
4. **M15.** Built: a struct literal on the left is typed by itself only where the right operand's type picks an impl alone (one not by the target's own type); else by the right operand, as MYLA-544 has it. Alternative: try the right operand's type and fall back, which the checker can't undo cheaply.
5. **D95 and `defer`.** Built: a deferred block is followed at its block's end, after every statement of the block, so a `defer` before an early `return` that precedes the `await` is taken as running after the `await` too (conservative: a warning, never a missed one). Alternative: follow it at each exit (`return`, `?`, `break`), more exact, more code.
