## What was built

- **`static_files` (D260, H8 and the low items).** `file_response` takes the decoded path through `served_segments`: split on every separator of the target (`/`, and `\` where std.path_style's `WINDOWS`), `""` and `.` dropped, `..` taking the segment before it off and 404 past the root; a segment refused when it is a dot file's (unless `static_files(prefix, dir, dot_files = true)`) or has a control character, and on Windows when it has `<>:"|?*`, ends in a dot or a space, is a device's name (`windows_device`: `con`, `prn`, `aux`, `nul`, `com0`–`com9`, `lpt0`–`lpt9`, `com¹²³`, `lpt¹²³`, `conin$`, `conout$`, `clock$`, by the name up to its first dot, in any case) or a short name's `~` and digit. Then each part below the root is looked at with `symlink_metadata`, never opened: a directory, then a regular file, else 404. So a link below the root is never followed, and a FIFO, a device or a socket never opened.
- **Streaming.** `Response` has a new field `file` (the path a body is sent from, `""` for none; `body` is empty then). The server (`serve_ready`, MYLA-794's code, the hook named below) opens it when it sends the response (`opened_file`: `Content-Length` the open file's size, 404 if it is no longer a regular file), sends the head, then the file 64 KiB at a time (`Link.send_file`, within `write_ms` as `send`; `Truncated` and the connection closed if the file shrank), and closes it. `text()`, `bytes()` and `format_response` read a file's body, so a handler called directly (the tests, `examples/book_api.my`'s style) still sees it.
- **Patterns (M14).** `route` (and so `get`, `post`, …) checks its pattern (`pattern_problem`) and a malformed one is a runtime error naming it (D184): `http: the route pattern '/files/{p:path}/meta': {p:path} isn't the last segment, and a path parameter takes the rest of the path`; an unknown kind (`{id:integer}`, `{id:}`), a brace in a segment that isn't a whole parameter (`x{id}`, `{id`, `{a{b}`), a name that isn't letters, digits and `_` (`{}`, `{a-b}`, `{%rest}`: `%` is the router's own, which `static_files` uses through `add_route(…, reserved = true)`), a name twice. `router(base)` refuses a brace in its base, which is matched literally.
- **JSON numbers (H9).** `bounded_number` (json.my) gives `parse_float` at most 800 significant digits and a sticky one (a 1 in place of the dropped digits when one of them isn't 0) with the exponent made up for them: a halfway point between two float64s has at most 767 significant digits, so this rounds as all the digits do. Used by `Reader.number` only. A small change in `lib/std/num.my` (no lane's file this round): `big_divmod` starts its remainder at the bits of `n` above the quotient's instead of taking a step for each of `n`'s bits, which made every number of hundreds of digits cost milliseconds.

The changes outside the router: in the server part of `http.my`, `serve_ready` (the hook: open a file body, send it after the head, close it) and `response_parts` (a file body keeps the `Content-Length` `opened_file` gave and is never chunked); `Response` (the field `file`, `response`, `text`, `bytes`, `Parser.to_response`, `format_response`). In `json.my`: `Reader.number` (one call), new `KEPT_DIGITS`, `bounded_number`, `long_numbers`, `repeated`. In `num.my`: `big_divmod` (and `#derive(Eq)` on `DivMod` for its cases).

## Proposals

Accepted by the owner on 2026-11-18 as D284 to D289 (proposals 1 to 6 in order).

1. **Symbolic links below the root: every one is refused** (built), one that stays inside too. D260 says "no symlinks out of the root", but std.fs can't say where a link leads (no `readlink`, no canonical path, and no primitive for either). Alternatives: follow a link whose target stays under the root, which needs a primitive staged in the seeds on every target and in the interpreter ([[MYLA-841]]); follow every link (nginx's default, which D260 refuses).
2. **`..` is resolved, not refused** (built): `/assets/sub/../app.css` is `app.css`, as Go's `path.Clean` and nginx do, and 404 only past the root. Alternative: 404 for any `..`, as before (stricter, but a well-formed relative link in a served page could 404).
3. **Dot files: an argument, `static_files(prefix, dir, dot_files = false)`** (built), refusing every dot segment by default, `.well-known` too. Alternatives: a `StaticOptions` struct (room for an index file, cache headers), or `.well-known` served by default.
4. **Windows' short names: a segment with `~` and a digit is refused** (built), since `TOPSEC~1.TXT` may name `.topsecret` and get past the dot file rule. Alternative: serve them (a real name with `~1` is 404 now).
5. **A body from a file is a field of `Response`, `file`** (built), which `text()`, `bytes()` and `format_response` read. Alternatives: a body enum (`Text(str)`, `File(path)`), which would change every use of `r.body`; a producer closure (`() -> Option<str>`), which a `#derive(Eq)` `Response` can't hold.
6. **JSON numbers keep 800 significant digits and a sticky one** (built), any length accepted. Alternatives: refuse a number past N digits as a `Syntax` or `OutOfRange` error (Python's `int()` refuses past 4,300 digits, its `json` takes floats of any length); make std.num's `f64_literal_bits` subquadratic (the digits in chunks of 9, a division of its own), which the cap makes unnecessary for std.json.

Filed: [[MYLA-841]] (where a link leads, for proposal 1), [[MYLA-842]] (the check and the server's open are two steps: a file swapped for a FIFO between them still blocks the open), [[MYLA-843]] (`parse_float` takes bignum arithmetic for every number: 300 kB of `1e-300` in JSON parse a thousand times slower than 300 kB of strings).
