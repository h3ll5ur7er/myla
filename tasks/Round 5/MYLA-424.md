## What changed

- **std.toml** ([[lib/std/toml.my]]): tables and arrays nest at most 100 deep (`MAX_DEPTH`), the document's own table not counted. One depth counts a header's tables, an array of tables (its array and its element), a dotted key's tables, arrays and inline tables; the parser carries it (`Parser.depth` for the current section, a `depth` argument to `assign`, `value`, `array` and `inline_table`). A container past it is the `Syntax` error `tables and arrays nested too deeply (more than 100 levels)` at that container, as std.yaml (100, `TooDeep`) and std.json (200, `Too deeply nested`) give theirs. [[Language/Standard-library/Toml]] says so.
- **The help of `#derive(Toml)`** ([[selfhost/checker.my]]): `Serial` gains `decision`, so the help of a type without `ToToml`/`FromToml` names D176 (it said D172, which D176 superseded for TOML); JSON's still names D172. [[examples/errors/type_decode_not_from_toml.stderr]] follows.
- **std.yaml** ([[lib/std/yaml.my]]):
  - a block scalar without a line with content (its lines only spaces, ended by a line indented as its parent or less) takes its indentation from its longest empty line (YAML 1.2, 8.1.1.1), so `a: |`, a line of spaces, `b: 1` is `{"a": "", "b": 1}` (was `" \n"`), `|+` keeps `"\n"`, as PyYAML reads them; the error for a leading empty line longer than the first content line now points at that line (was past the content line);
  - a raw C0 control other than a tab, LF and CR is `Unexpected` anywhere, quoted scalars included (`control_at`, a scan before parsing, as std.toml checks UTF-8 first); DEL and the C1 controls, which the specification allows in quoted scalars, aren't looked for;
  - `...` may be repeated after the document (the reproducer's fifth case);
  - the writer quotes what YAML 1.1 reads as something else (`yaml11_other`, `number11`, `fraction11`, `timestamp11`): below.
- **std.json** ([[lib/std/json.my]]): `to_string` and `pretty` write NaN and the infinities as `null` (proposal 2); `decode` parses in an exact mode (`Parser.exact`, `parse_with`, `holds_exactly`): an integer literal beyond `int64`, below 2^64 in size, that its float64 doesn't hold exactly is `OutOfRange` with its line and column, `1:8: 9223372036854775809 can't be read exactly: beyond int64's range a number is a float64` (D184 (1)); `JsonError`'s format writes `line:col` for any error that has a line. `parse` is unchanged (Python's behaviour, a float).
- **std.xml** ([[lib/std/xml.my]], [[MYLA-460]]): `XmlStreamReader.fill` reads until the new bytes at least match the held-back tail (or the stream ends), into one builder, so an event a read cut is lexed again a logarithmic number of times.
- **Tests**: [[tests/burn/test_yaml.py]] `YamlWriterForYaml11` (PyYAML reads what the writer writes); [[tests/burn/test_json.py]] and test_yaml's expected values write NaN as `null`; [[tests/burn/test_xml.py]] fetches the W3C suite (proposal 4); [[tests/burn/test_toml.py]] builds its drivers for `MYLA_TEST_TARGET` and is in `_targets.SUITES`, so the toml-test suite runs under qemu-aarch64 and Node.
- **Pages**: [[Language/Standard-library/Toml]], [[Language/Standard-library/Json]], [[Language/Standard-library/Yaml]], [[Language/Standard-library/Xml]] (the wasm32 sentence: a million levels are read and written back on x86-64, aarch64 and wasm32 since [[MYLA-389]]; the suite's place; the stream reader; 90 cases).

## Proposals (the owner decides)

1. **TOML's depth: 100, a syntax error.** Built: 100 levels, as std.yaml has, counted over every way of nesting, and the `Syntax` kind with the message (std.toml's errors are all `Syntax` with a message; a new `TomlErrorKind` would break exhaustive matches). Alternatives: 200 as std.json (the interpreter survives about 800 nested arrays and 1600 inline tables fail); limit only arrays and inline tables, leaving dotted keys and headers unlimited (they were quadratic too, 0.3 s for 4000 parts, and `build` recurses over them).
2. **`json.to_string` of NaN and the infinities: `null`.** Built: `null`, as JavaScript's `JSON.stringify` writes them, and as `encode`'s float impls already did; `parse` keeps reading `NaN` and `Infinity` as Python does. Python's `json.dumps` writes `NaN`/`Infinity` (not JSON; `allow_nan=False` raises `ValueError`); Go's `json.Marshal` fails with `UnsupportedValueError`. An error would need `to_string` to return a `Result` (every caller changes) or a runtime error on data that may come from outside (a YAML `.nan` through `to_json`), which D184 rules out.
3. **Integers beyond int64 in `decode`.** Built: `decode` refuses an integer literal beyond `int64`, below 2^64 in size, that its float64 doesn't hold; `parse` still reads it as a float. Left as it was, and named on the Json page: `encode` of a `uint64` above 2^63 that a float64 doesn't hold (`9223372036854775809`) writes the nearest float, `9.223372036854776e+18`, which `decode` reads back as `9223372036854775808` (a float's text is a float's; refusing whole floats there would refuse what a `float64` field reads); std.toml is the same, as TOML's integers are `int64`. The whole fix is a variant for them, `Json.UInt(uint64)` (exact through `parse`, `to_string`, `encode` and `decode`), which changes `Json` for every exhaustive `match`: for the owner. A side effect of the exact mode: a `float64` field given an integer literal between 2^63 and 2^64 that isn't a float64 is refused by `decode` too.
4. **The W3C suite: fetched, not vendored.** Built: test_xml downloads `xmlts20130923.tar.gz` from the W3C once into `build/xmlts/`, checks its SHA-256 and extracts it with `tarfile`'s data filter (curl, which takes the proxy from the environment; skipped when it fails; `MYLA_XMLTS` still names a copy). Vendoring as toml-test is isn't allowed: James Clark's notice in `xmltest/readme.html` lets the collection be passed on only as the unmodified `xmltest.zip`, "permission to distribute the collection in any other form is not granted". Vendoring that zip (or the 641 KB archive) unchanged would be allowed, if the owner prefers the test to run without the network.
5. **YAML 1.1's set in the writer.** Built: booleans (`y`, `n`, `yes`, `no`, `on`, `off` in their three cases), integers (`0b`, `0x` with `_`, octal `0…`, `_` anywhere after the first digit, base 60), floats (`_`, base 60, `.5`), timestamps (PyYAML's expression), `<<` and `=`. It errs towards quoting (`09`, an exponent without a sign, `y` and `n`, which PyYAML reads as strings but the 1.1 specification as booleans). Null needs nothing: 1.1's nulls are 1.2's. Alternative: quote only what PyYAML misreads.
6. **Controls in YAML.** Built: C0 refused everywhere (c-printable and nb-json both leave it out), as `Unexpected`. Left: DEL and C1 (except NEL) outside quoted scalars, which the specification forbids there and PyYAML refuses everywhere; a check per scalar kind, for a later task if wanted.
