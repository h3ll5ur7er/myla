Seconds per workload, average of the runs. Labelled at the ends: the fastest and slowest language for that workload.

Where Myla is strong. Binary trees take 0.47 s, ahead of C (0.71 s), Rust (0.72 s) and Swift (1.50 s). Only garbage-collected runtimes and Nim are faster. The tree is a plain recursive enum; reference counting frees each tree the moment it goes out of use, and the allocator is Myla's own. Mandelbrot is about 25% behind C, and strings are level with Swift.

Where it loses time. k-nucleotide costs 4.9 s, close to Node and Ada. Every seq[i:i + k] slice is a new string value, where Rust and Swift hash a borrowed view of the same bytes. Fibonacci costs 2.7 s: the backend makes one real call per recursion, while the GCC-based compilers unroll part of it. Primes is the surprise. Most runtimes tie at 0.69 s because the hardware divider sets the pace, and Myla needs 1.16 s. The disassembly shows why: it divides 32-bit integers with the 64-bit idiv instruction, which is slower on this CPU, and checks the divisor before each one.

What sets Myla apart

Myla reads like Swift and Rust, but its design choices differ from both. These are the ones that shaped the benchmark code and the numbers above.

Values everywhere, no borrow checker

Lists, maps, strings and structs are values. A copy is cheap because storage is reference counted and copied only on write. There are no references, lifetimes or &mut, and no garbage collector pauses. In the strings workload, var cur = words is the whole "clone the list" step.

A compiler that builds itself in seconds

The toolchain is written in Myla and reaches a byte-identical fixed point from a committed assembly seed. It needs only as and ld to bootstrap. The whole benchmark compiles faster than any other native build measured here.

Static binaries without libc

Programs talk to the kernel directly. The runtime, including the allocator, hash maps and a work-stealing task scheduler, is itself Myla code in std.rt. One compiler targets x86-64 and aarch64 Linux and WebAssembly (WASI).

Tests live on the function

#test(args)[expected] above a function is a test case, run by myla test in the interpreter or natively. The benchmark file carries twelve of them, checked against the Python reference before the first timed run.

Interpreter and native code agree

myla run interprets with overflow checks; myla build compiles. Both must print the same output, which the project's test suite enforces. Development is instant, release is native.

Algebraic types, traits and Swift-style concurrency

Enums with exhaustive match, generic traits, closures, a pipe operator, guaranteed tail calls with become, and async/await with structured child tasks and actors on a multi-threaded runtime.
