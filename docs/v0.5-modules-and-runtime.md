# Myla v0.5 — Modules & Runtime (design)

This is the detailed, decision-complete design for the **v0.5 "modules &
runtime"** milestone — Tier E in [self-hosting.md](self-hosting.md) §3. It
expands the sketches in [future-features.md](future-features.md) §10/§17/§18 (and
the Floats note under "Recently decided") into a real specification: concrete
syntax, semantics, grammar (EBNF), type-system/runtime changes, and an
implementation plan across the existing lexer → parser → checker → interpreter →
compiler pipeline.

**Scope (v0.5):**

1. **Modules & imports** — explicit, Python-like imports with dot-relative search
   bases, full-path binding, `as`, `pub`, and `pub`-prefixed **re-exports**; the
   filesystem→namespace mapping and resolution corner cases (D17, D22, D54, D57).
2. **Standard library skeleton** — a `std` package providing the modules the
   self-hosted compiler needs, built on top of imports.
3. **Floats** — `float32`/`float64` (IEEE-754), the `float` alias, `f32`/`f64`
   literal suffixes, arithmetic/comparison, `as` conversions, SSE2 codegen
   (D19/D20, scheduled by D56).
4. **`char` type & UTF-8 string model** — a dedicated Unicode-scalar `char`,
   char literals (incl. `\u{…}`), codepoint iteration, and a bytes view; `str`
   stays UTF-8 bytes (D25, refines D42).
5. **Freestanding I/O runtime** — `std.fs`/`std.io`/`std.process` as thin
   no-libc syscall wrappers: file read, `argv`, stdout/stderr, `exit` (D29).
6. **Restricted generic traits** — `trait Comparable<T>`, implementable at most
   once per type, no overload resolution (D55, refines D53).
7. **String interpolation** — `f"…{expr}…"` as pure front-end sugar over
   `format` (D58).

Out of scope (later tiers / post-1.0): process spawning (`fork`/`execve` to drive
`as`/`ld`) is **deferred until after a self-hosted code generator works** (D29);
trait **objects** / dynamic dispatch and **multi-impl / argument-overloaded**
generic traits remain deferred (D55); custom operators stay post-1.0 (D18); a
package **manifest**/build-config format is deferred until real multi-package
builds appear (§1.4). Dispatch stays **static** and everything is
**monomorphized** — no vtables, no runtime type tags, consistent with v0.2–v0.4.

> The sub-decisions this design raises (**D54–D58**) are **locked** in
> [roadmap.md](roadmap.md). This document reflects those decisions; the
> "(Dnn)" markers point at the originating decision for provenance.

## 1. Modules & imports

### 1.1 Files, packages & paths

The dotted path in an import mirrors the directory tree:

- a `.my` **file is a module** (`std/collections/list.my` ↔ `std.collections.list`);
- a **directory is a package** (`std/collections/` ↔ `std.collections`);
- module/package names must be valid identifiers (filename without `.my`).

The search **base** is chosen by the leading-dot count (recap of D22):

| Prefix | Search base |
|--------|-------------|
| (none) | builtins (`std`, …) or the **project root** (§1.4) |
| `.`    | the current file's directory |
| `..`   | the parent directory (one extra level per extra dot) |

### 1.2 Binding & visibility (recap of D22)

- `import a.b.c` binds the **full path** `a.b.c` (it does *not* bind the bare
  `c` — that footgun is rejected).
- `import a.b.c as c` rebinds to a shorter name.
- `from <path> import name` selectively binds the simple name `name` (`as` ok).
- Items are **private by default**; `pub` marks a declaration as exported.
- **Collisions are errors**: importing two things under the same name is a
  compile-time error — no automatic resolution; disambiguate with `as`.

### 1.3 Re-exports (D54)

`pub` is a uniform **prefix modifier on an import statement**, marking the name(s)
it binds as part of *this* module's public surface — there is **no separate
`use` keyword**.

```my
pub import std.collections.list as list   // re-export under the name `list`
pub from .utils import helper             // re-export `helper`
pub import std.collections.list           // ERROR: pub import requires `as <ident>`
```

A `pub import` **requires `as <ident>`** (the export name must be a simple
identifier; the last path segment is never auto-bound, per D22). A
`pub from … import name` already binds a simple name, so no `as` is forced there.
Re-exported names obey the same collision rules as any other binding.

### 1.4 Resolution corner cases (D57)

The model above leaves a few filesystem↔namespace edges; these are the locked
rules:

1. **Package body / public surface.** A directory `foo/` may contain an optional
   **package-root module** named `foo.my` *inside* it (i.e. `foo/foo.my`). When
   present, `import foo` exposes that file, and the package's public surface is
   whatever `foo/foo.my` re-exports (via the §1.3 `pub import` mechanism) — there
   is **no implicit glob re-export** of children. When absent, `import foo` binds
   nothing usable on its own, but deeper paths (`foo.bar`) remain reachable.
2. **File/dir name collision.** If both `foo.my` and `foo/` exist in the same
   parent directory, any reference through `foo` is **ambiguous → compile error**
   (consistent with D22's "collisions are errors, no auto-resolution"). The
   compiler does not pick a winner.
3. **Project root.** For the no-dot base, the **project root is the directory of
   the entry file** passed to `myla build`/`myla run`. No manifest is required
   yet; a `myla.toml`-style package manifest is deferred until real
   multi-package builds exist.
4. **Builtins precedence / shadow protection.** A fixed, reserved set of roots
   (`std`, plus the prelude) resolves to the **builtins first**; a project
   directory that shadows a reserved root is a **compile error**, not a silent
   override.
5. **Module-before-item in `from`.** In `from a.b import c`, resolution tries a
   **submodule** `a/b/c.my` first, then an **item** `c` declared in module
   `a.b`. If both exist, that is an ambiguity error (per rule 2).
6. **Cyclic imports are allowed** for types and functions: the checker resolves
   declarations across a module group in two passes, so mutual references type
   fine. The only order-sensitive case — module-level `const` initializer
   cycles — is *already* a hard error (D28), so nothing new is required.

### 1.5 Implementation notes (modules)

- **Loader:** a new front-end stage resolves an import graph starting from the
  entry file: map dotted paths + dot-prefixes to filesystem paths under the
  search bases, load each module once (memoized), detect file/dir collisions
  (rule 2) and reserved-root shadowing (rule 4), and build a per-module symbol
  table (its own decls + imported/`pub`-imported names).
- **Checker:** name resolution consults the importing module's symbol table;
  `pub` controls cross-module visibility; re-exports add the bound name to the
  module's exported surface. Whole-program coherence for `impl`/traits (D45) is
  preserved — the union of all loaded modules defines a type's method set.
- **Monomorphizer/codegen:** modules are a **front-end** concern; after
  resolution the program is one flat, name-mangled unit (module path folded into
  symbol names), so the backends need no module-specific machinery.
- **Interpreter:** same resolved program; a global environment keyed by mangled
  names.

## 2. Standard library (`std`)

`std` is a **package shipped with the toolchain** (Myla source where possible,
built-ins where a syscall/intrinsic is unavoidable), reachable via the no-dot
base. v0.5 ships only what the self-hosted compiler needs:

| Module | Contents |
|--------|----------|
| `std.io` | `print`/`println`/`eprint`/`eprintln`, raw `write(fd, s)` (§5) |
| `std.fs` | `read_to_string(path) -> Result<str, IoError>`, `open`/`read`/`close` (§5) |
| `std.process` | `args() -> [str]` (argv), `exit(code)` (§5) |
| `std.string` | UTF-8 helpers: `chars()`, byte/char conversions (§4) |
| `std.math` | float helpers as needed (`abs`, `min`/`max`, …) (§3) |

Collections (`[T]`/`[K: V]`/`StringBuilder`) and the prelude (`Option`/`Result`)
remain **built-in** (no import needed), as in v0.2–v0.4. The exact surface grows
on demand during self-hosting; this table is the v0.5 floor, not a ceiling.

## 3. Floats (D19/D20 → D56)

> **Status: landed in v0.5.2.** Lexer/parser/checker/interpreter/native backend
> all support `float32`/`float64` with full interpreter↔native parity (see
> `examples/floats.my`, `tests/unit/test_floats.py`, and the float parity
> programs in `tests/burn/test_compiler_parity.py`).

### 3.1 Types & literals

Mirror the sized-integer model: `float32` and `float64` (IEEE-754), with `float`
a built-in **alias for `float32`** (parallel to `int` = `int32`, D11). Literal
suffixes `f32`/`f64` disambiguate; a float literal is any numeric literal with a
fractional part or exponent, or an integer literal with a float suffix:

```my
let a = 3.14159f64    // float64
let b = 6f32          // 6.0 as float32
let c: float = 1.5    // float = float32 (by context)
let d = 2.0           // unsuffixed, no context -> float32 (the `float` default)
```

An **unsuffixed float literal defaults to `float32`** (= `float`), matching the
`int`→`int32` default-literal convention (D11/D19); write `f64` or annotate the
binding for double precision. (To confirm at implementation time; consistent
with the existing integer story.)

### 3.2 Semantics

- **No implicit int↔float or width mixing** (consistent with D4). Conversions are
  explicit via `as` (extends D26): `i as float64`, `f as int32` (truncates toward
  zero), `f32 as float64` (exact widening), `f64 as float32` (rounds to nearest).
- **Arithmetic** `+ - * / %` and **comparisons** `< <= > >= == !=` use IEEE-754
  semantics (`/` is true division; `%` is `fmod`; `NaN != NaN`; `±0`, `±inf`
  behave per IEEE). **No bitwise/shift** on floats.
- Floats participate in the **fixed operator-trait set** (D52) with built-in
  implicit defaults, exactly like the integer types — `a + b`/`a < b` on floats
  is the hardware op, zero-cost, overridable by a user `impl` only on user types.
- **`print`/`format`** render floats as a deterministic, round-trippable **plain
  decimal** (no scientific notation): the magnitude is scaled to a
  `P`-significant-digit integer (`P = 9` for `float32`, `17` for `float64` — the
  IEEE round-trip digit counts), trailing zeros trimmed, laid out positionally.
  So `0.1f64` prints `0.10000000000000001`, `0.1f32` prints `0.100000001`, and
  `1e20f64` prints the full 21-digit integer. `nan`/`inf`/`-inf`/`-0` are special-
  cased. The algorithm is specified once (double-double / Dekker scaling over a
  shared power-of-ten table) and emitted **identically** by both backends, so
  output is byte-for-byte equal (the same parity discipline as integer wrapping).

### 3.3 Implementation notes (floats)

- **Lexer:** float literal tokens (fractional/exponent forms) + `f32`/`f64`
  suffixes.
- **Checker:** `float32`/`float64`/`float` types; float-literal defaulting and
  contextual typing; `as` conversion matrix incl. float↔int.
- **Interpreter:** Python `float` is `float64`; **emulate `float32` rounding**
  (round to single precision after each op, e.g. via `struct` pack/unpack) so the
  interpreter and native backend agree — the same parity discipline used for
  integer wrapping.
- **Compiler (x86-64):** the **first use of SSE2 / XMM registers** — `addsd`/
  `subsd`/`mulsd`/`divsd` for arithmetic, `ucomisd` (NaN-aware `set*`/`andb`/`orb`
  sequences) for comparisons, and `cvtsi2sdq`/`cvttsd2si`/`cvtss2sd`/`cvtsd2ss`
  for conversions. A float value is carried at runtime as its **f64 bit image in
  a general-purpose register/stack slot** — Myla keeps its existing internal
  calling convention (scalars in 8-byte slots, result in `%rax`) rather than
  adopting the System V XMM arg/return ABI; XMM is used only as compute scratch.
  `float32` results are narrowed via `cvtsd2ss`/`cvtss2sd` round-trips. `%` calls
  a small `__fmod` helper (x87 `fprem`); unsigned-64→float uses the round-to-odd
  halving trick. The SSE2 runtime (helpers + the double-double power-of-ten tables
  + `__float_to_str`) is emitted **only when a program actually uses floats**,
  gated by a `_uses_float` flag.

## 4. `char` type & UTF-8 string model (D25)

> **Status: landed (v0.5.3).** The `char` type, Unicode-scalar literals (`'a'`,
> `'é'`, `'\u{1F600}'`), `char`↔integer `as`, char comparisons, ASCII byte
> compatibility (D42), and round-trippable UTF-8-glyph `print`/`format` (v0.5.3a),
> plus `chars(s) -> [char]` UTF-8 codepoint iteration with the byte view staying
> `s[i]`/`len(s)` (v0.5.3b) — all end-to-end with interpreter↔native parity (see
> `examples/chars.my`, `tests/unit/test_chars.py`, and the `char_*` parity
> programs).

### 4.1 The `char` type

A dedicated **Unicode scalar value** (32-bit), distinct from the integer types.
Char literals carry it:

```my
let nl: char = '\n'
let a:  char = 'a'
let emoji: char = '\u{1F600}'      // multi-byte scalar, only valid as `char`
```

**Migration from v0.3 (D42).** v0.3 made `'a'` a `uint8` byte code so that
`s[i] == 'a'` worked. In v0.5 a char literal's **defaulting type is `char`**, but
— like an integer literal — it stays **flexible**: a single-scalar ASCII literal
is still usable where a `uint8`/integer is expected (so byte comparisons against
`s[i]` keep working). A multi-byte literal (`'é'`, `'\u{…}'`) is **only** valid
as `char`. `char` converts to/from integers via `as` (D26).

### 4.2 String model

`str` remains **length-prefixed, immutable, UTF-8 bytes** (D21):

- **Byte access stays**: `s[i] -> uint8` (bounds-checked, traps OOB), `len(s)` is
  the byte length — unchanged from v0.3 (D42).
- **Codepoint iteration** is UTF-8-aware and yields `char` via the `chars(s) ->
  [char]` builtin: `for c in chars(s) { … }`. (Shipped as a free builtin rather
  than a `std.string` method — it parallels the existing `len`/`push`/`keys`
  builtins and doesn't need the stdlib, which fills out in v0.5.4.)
- A **bytes view** remains the escape hatch for byte-level code: `s[i] -> uint8`
  and `len(s)` (the byte length) are unchanged, so the lexer's hot path stays on
  `s[i]`.

### 4.3 Implementation notes (char/strings)

- **Lexer:** extend char literals to Unicode scalars + `\u{…}` escapes; reject
  invalid scalars (surrogates, > U+10FFFF).
- **Checker:** `char` type; char-literal defaulting/flexibility (§4.1); `as`
  between `char` and integers.
- **Interpreter:** `char` is a Python `int` codepoint tagged with the `char`
  type; `chars()` decodes UTF-8 into a `[char]` (`ListValue` of codepoints).
- **Compiler:** `char` is a 32-bit codepoint carried in a general-purpose
  register (same internal convention as the other scalars); `chars()` is the
  gated `__str_chars` helper — a UTF-8 decode loop over the existing byte buffer
  that builds a `[char]` list cell — with no change to the `str` representation.
- **`print`/`format` (landed):** a `char` renders as its UTF-8 **glyph**. The
  encoder (`types.char_utf8_bytes` / the gated `__char_to_str` asm helper) is
  specified once and emitted identically by both backends (same range branches
  and bit masks), so output is byte-for-byte equal. `int as char` is **unchecked**
  (the codepoint is taken as-is); only char *literals* are validated as scalars.

## 5. Freestanding I/O runtime (D29)

> **Status: v0.5.4 landed (a/b/c).** The bundled standard library ships under
> `<package>/std/`, and `std.io` (raw `write` + `println`/`eprint`/`eprintln`),
> `std.process.exit`/`args()`, and `std.fs.read_to_string -> Result<str,
> IoError>` are live across the interpreter and native backend, with
> byte-for-byte stdout/stderr/exit-status parity (including the errno-keyed error
> paths). These are thin Myla wrappers over low-level runtime primitives —
> `__write(fd, s)`, `__exit(code)`, `__args() -> [str]`, and `__read_file(path)
> -> str` (+ `__io_errno()`) — emitted natively as the Linux `write`/`exit`/`open`
> /`fstat`/`read`/`close` syscalls (argc/argv stashed at `_start`), and backed by
> `os.write`/an exit signal/captured argv/real file IO in the interpreter. The
> `Result`/`IoError` carrier is assembled in pure Myla (`std/fs.my`), so no
> backend hand-builds enum layouts.

A tiny **no-libc** runtime (honoring D2): thin wrappers over Linux x86-64
syscalls.

```my
from std.fs import read_to_string
from std.io import eprintln
from std.process import args, exit

let argv = args()                         // from the stack at _start
let src  = read_to_string(argv[1])?       // open/read/close
eprintln("compiling " + argv[1])          // write to fd 2
exit(0)                                    // exit syscall
```

### 5.1 Surface & semantics

- **`std.io`:** `println` (fd 1), `eprint`/`eprintln` (fd 2), and a raw
  `write(fd: int32, s: str)` — *landed*. (The global `print` builtin remains the
  type-aware printer; it already emits to fd 1, so it coexists with `std.io`
  rather than being relocated. A no-newline `std.io.print` for `str` is omitted
  for now because the bare name would collide with that builtin when imported
  unqualified.)
- **`std.fs`:** `read_to_string(path) -> Result<str, IoError>` over
  `open`/`fstat`/`read`/`close`; errors surface as a `Result` carrier (reuses
  §`?`) — *landed*. `IoError` is `NotFound | PermissionDenied | Other(int32)`
  (the `Other` payload is the raw OS errno; ENOENT/EACCES get named variants).
- **`std.process`:** `exit(code)` and `args() -> [str]` (argv captured at
  `_start`; `args()[0]` is the program name) — *landed*.
- **No process spawning** (`fork`/`execve`): the compiler emits asm and a shell
  wrapper links it for now; a `process.exec` wrapper is **deferred until after a
  self-hosted code generator works** (D29).

### 5.2 Implementation notes (runtime)

- **Bundled stdlib.** The standard library lives in `src/myla/std/*.my`; the
  loader's `default_stdlib_root()` points the `std` search base at the package
  directory, and `from std.… import …` resolves there (and may not be shadowed
  by a project `std/`, D57 r4). The CLI and the burn harness pass this root to
  `link`. The `std` modules are ordinary Myla source — they wrap the runtime
  primitives below, so they are type-checked and compiled like any other module.
- **Runtime primitives.** Three low-level builtins underpin the surface:
  `__write(fd: int32, s: str)`, `__exit(code: int32)` (*diverging*), and
  `__args() -> [str]`. They are namespaced behind `std.io`/`std.process` rather
  than used directly. Natively, `__write` is a tiny helper running the Linux
  `write` syscall (no trailing newline; the str's `[len][bytes]` payload is
  written verbatim) and `__exit` inlines the `exit` syscall. In the interpreter,
  `__write` routes fd 1/2 to the captured stdout/stderr streams (so the burn
  suite can compare both) and any other fd to `os.write`; `__exit` raises an
  exit signal that `Interpreter.run()` turns into the process status (low 8
  bits, matching the syscall). The native `__write`/`__args` helpers are emitted
  only when used (`_uses_write` / `_uses_args`).
- **argv capture.** `_start` always stashes `argc` and `&argv[0]` (from the
  entry stack) into two `.bss` globals before calling the entry; the gated
  `__args` helper walks them, `strlen`/copies each C string into a heap `str`
  cell, and returns a fresh `[str]` list (reference-counted like any list, so it
  is reclaimed when it goes out of scope). The interpreter hands back a copy of
  its captured argv. `args()[0]` is the program name — the binary path natively,
  the `.my` path under `myla run`; the burn harness pins a shared `argv[0]`
  (`subprocess` `executable=` + a chosen `argv[0]`) so both backends match.
- **Exit status.** `Interpreter.run()` now returns an `int`, and `myla run`
  propagates it as its own exit code, so interpreter and native runs observe the
  same status. `myla run file.my [args…]` forwards the trailing arguments as the
  program's argv.
- **File reads.** `read_to_string` is two scalar primitives plus pure-Myla glue:
  `__read_file(path) -> str` opens/sizes (`fstat`)/reads/closes the file, writing
  the bytes into a fresh `str` cell and stashing the errno (0 on success) in a
  gated `.bss` global; `__io_errno() -> int32` reads that global. `std/fs.my`
  then branches — `Ok(data)` on errno 0, else `Err(from_errno(code))` — so the
  `Result`/`IoError` values are built by ordinary Myla enum construction (no
  asm/interpreter coupling to enum layout). The native helper NUL-terminates the
  path on the stack first (Myla `str` is length-prefixed, not NUL-terminated);
  the interpreter uses Python `open(...).read()` and maps `OSError.errno`
  identically (Linux errno numbers). The whole helper + global are gated on
  `_uses_read_file`.

## 6. Restricted generic traits (D55, refines D53)

> **Status: landed (v0.5.5).** A `trait` may take type parameters and a type
> implements it at most once; the checker substitutes the trait parameters with
> the `impl`'s arguments when verifying conformance, and the existing
> `(trait, type)` coherence rule already forbids a second impl (regardless of
> argument). This is a pure front-end change — the parser already accepted
> `trait Name<…>` / `impl Trait for T`; the only edits were lifting the
> "generic traits unsupported" guard, capturing the trait's `trait_args` on the
> `impl`, resolving the trait's parameters as `TypeParam`s in its signatures, and
> extending the `Self`-substitution to also map those parameters. Methods lower
> to ordinary functions, so there is **no new dispatch model and no runtime
> change** (interpreter and native parity come for free; `examples/generic_traits.my`).
> Deferred as designed: multi-impl/argument-overloaded generic traits, generic
> traits as user bounds beyond the built-in set, and trait objects.

### 6.1 Surface

A `trait` may take type parameters; a type implements it **at most once**:

```my
trait Comparable<T> {
    fun compare(self, other: T) -> int32     // <0 / 0 / >0
}

impl Comparable<int32> for Money {
    fun compare(self, other: int32) -> int32 { /* … */ }
}
// A second `impl Comparable<…> for Money` (any argument) is a coherence error.
```

The restriction — **≤ 1 impl of a given generic trait per type** — is what keeps
this cheap: because a type implements `Comparable` for exactly one `T`, a call
`x.compare(y)` needs **no overload resolution**; the single impl fixes `T`.

### 6.2 Semantics & implementation notes

- **Parser:** lift the current block on trait type parameters; parse
  `trait Name<P, …>` and `impl Trait<Arg, …> for Type`.
- **Checker:** store the trait's parameters; on `impl Trait<Args> for T`,
  **substitute** the trait parameters with `Args` and check method conformance
  against the substituted signatures (extends the existing `Self`-substitution
  machinery). Coherence: at most one `impl` of `Trait` for `T` (no argument
  discrimination) — a second is an error. Method tables are keyed by
  `(trait, type)`, unchanged in shape.
- **No new dispatch model:** still static, still monomorphized; generic-trait
  bounds beyond the built-in set, **multi-impl/overloaded** generic traits, and
  trait objects stay deferred.

## 7. String interpolation (D58)

> **Status: landed (v0.5.6).** Implemented entirely in the **lexer**: an `f"…"`
> literal is lowered *in place* to the token stream of a `format(fmt, args…)`
> call (`format ( "<fmt>" , <hole-tokens> … )`), so there is **no new token kind,
> AST node, checker rule, or runtime** — the emitted call rides the existing
> `format` machinery (placeholder/arity/printable-type checks, both backends). A
> balanced-brace scan splits literal text (escapes applied, `{{`/`}}` preserved,
> each hole → `{}`) from `{ … }` holes; nested string/char literals inside a hole
> are skipped so their quotes/braces don't disturb the scan, and each hole's
> source is re-lexed as an ordinary expression (nested f-strings included). See
> `examples/interpolation.my`, `tests/unit/test_interpolation.py`, and the
> negative cases `examples/errors/lex_fstring_*.my`.

Pure **front-end sugar** over the existing `format` intrinsic — zero new runtime.

```my
let msg = f"{name} = {value}"               // -> format("{} = {}", name, value)
let line = f"{path}:{row}:{col}: {kind}"
let lit  = f"set is {{ {x}, {y} }}"          // {{ }} are literal braces
```

- **`f"…"` prefix** (opt-in, so plain strings and existing `format` calls are
  untouched; `{}` is already meaningful to `format`).
- **Arbitrary expressions** inside `{ … }` (`f"{a + 1}"`, `f"{p.name}"`,
  `f"{count()}"`); each hole becomes a trailing `format` argument, so the
  printable-type rule is exactly `format`'s.
- **`{{` / `}}`** are literal braces (the `format` convention).
- **No format specs** (`{x:04}`) in v0.5 — interpolation stays at parity with
  `format`; specs are a later, joint feature.
- **Single-line only** in v0.5 (no multi-line/raw `f"…"`).
- **Desugaring:** `f"…"` lowers at parse/desugar time to `format(fmt, args…)`.

**Implementation note (the one real cost — the lexer):** an `f"…"` literal is
split into literal segments + embedded expression slices by a **balanced-brace
scan**; each `{ … }` slice is re-parsed with the normal expression parser
(handling quotes/braces *inside* the slice, e.g. `f"{m["k"]}"`). Everything after
the scan reuses the `format` checker + both backends.

## 8. Grammar additions (EBNF)

Extends [grammar.md](grammar.md) and the v0.2/v0.3/v0.4 design docs.

```
/* --- imports (recap D22 + pub re-export D54) --- */
import_decl ::= "pub"? ( "import" path ( "as" IDENT )?
                       | "from" path "import" import_item ( "," import_item )* )
import_item ::= IDENT ( "as" IDENT )?
path        ::= "."* IDENT ( "." IDENT )*           /* leading dots = relative base */
/* constraint (D54): a `pub import path` form requires `as IDENT`. */

/* --- types --- */
type        ::= … | "float32" | "float64" | "float" | "char"

/* --- declarations (restricted generic traits, D55) --- */
trait_decl  ::= "trait" IDENT generic_params? "{" method_sig* "}"
impl_decl   ::= "impl" generic_params? type ( "for" type_app )? "{" method* "}"
type_app    ::= IDENT ( "<" type ( "," type )* ">" )?   /* Trait<Arg,…> */

/* --- literals --- */
float_lit   ::= digits "." digits ( exp )? ( "f32" | "f64" )?
              | digits ( exp ) ( "f32" | "f64" )?
              | digits ( "f32" | "f64" )            /* int-form with float suffix */
char_lit    ::= "'" ( char_esc | utf8_scalar ) "'"
char_esc    ::= "\\" ( "n" | "t" | "\\" | "'" | "0" | "u" "{" hex+ "}" )
fstring     ::= "f" '"' ( fstr_text | "{{" | "}}" | "{" expression "}" )* '"'
```

New reserved type names: `float32`, `float64`, `float`, `char`. New tokens: the
`f"…"` string prefix and `f32`/`f64` literal suffixes. `pub`, `import`, `from`,
`as` already exist.

## 9. Implementation notes (per pipeline stage)

- **Loader (new):** import-graph resolution, module memoization, collision &
  shadow checks, per-module symbol tables (§1.5).
- **Lexer:** float literals + `f32`/`f64`; Unicode char literals + `\u{…}`; the
  `f"…"` interpolation literal (balanced-brace split).
- **Parser:** `pub`-prefixed imports + the `as`-required rule; generic trait
  decls + `impl Trait<…> for T`; float/`char` type names; interpolation slices
  re-parsed as expressions.
- **Checker:** cross-module name resolution + visibility; float types/defaulting
  + the extended `as` matrix; `char` typing/flexibility; generic-trait
  substitution + coherence; `f"…"` → `format` desugar (reuses the `format`
  checks).
- **Monomorphizer:** unchanged in shape — modules are folded into mangled names;
  generic-trait methods stamp per `(trait, type)`; floats/`char` are ordinary
  scalar layouts.
- **Interpreter (erasure):** resolved global env; Python-backed `std` I/O;
  emulated `float32` rounding; UTF-8 `chars()`.
- **Compiler (x86-64):** SSE2/XMM float codegen + ABI; `_start` captures
  `argv`/`argc`; new syscall wrappers; `char` as a 32-bit scalar.

Every feature follows project conventions: a runnable example with `#test` cases
(`examples/*.my`), interpreter↔native parity in the burn suite, and a negative
case in `examples/errors/` for each new diagnostic.

## 10. Suggested implementation phasing

Each phase lands end-to-end (checker + both backends + tests) before the next.
Phases 2–6 are largely independent; modules (phase 1) come first because the
stdlib and runtime live behind imports, and interpolation (phase 6) is pure sugar
that is safe to land last.

1. **v0.5.1 — modules & imports**: the loader, dot-relative resolution, `as`,
   `pub`, `pub`-prefixed re-exports, the §1.4 corner-case rules, and a minimal
   `std` skeleton. *Foundation for the stdlib and runtime.*
2. **v0.5.2 — floats**: `float32`/`float64`/`float`, literals + suffixes,
   arithmetic/comparison, the `as` matrix, SSE2 codegen, deterministic
   `print`/`format`.
3. **v0.5.3 — `char` + UTF-8 string model**: the `char` type, Unicode char
   literals, `chars()` iteration + bytes view; byte indexing unchanged.
4. **v0.5.4 — freestanding I/O runtime**: `std.fs`/`std.io`/`std.process`
   syscall wrappers, `argv` capture at `_start`, real `std` modules on top.
   *Phased:* **v0.5.4a (landed)** = bundled stdlib + `std.io` output
   (`write`/`println`/`eprint`/`eprintln`) + `std.process.exit`; **v0.5.4b
   (landed)** = `std.process.args()` (argv capture); **v0.5.4c (landed)** =
   `std.fs.read_to_string` with `Result<str, IoError>`.
5. **v0.5.5 — restricted generic traits (landed)**: trait type parameters, `impl
   Trait<…> for T`, substitution-based conformance + ≤1-impl coherence.
6. **v0.5.6 — string interpolation (landed)**: `f"…"` lexing + desugar to
   `format`.

Process spawning (`as`/`ld` driving) stays deferred until after a self-hosted
code generator works (D29); trait objects, multi-impl generic traits, and custom
operators remain out of scope.

## 11. Sub-decisions (locked as D54–D58)

| # | Question | Decision |
|---|----------|----------|
| **D54** | Re-export syntax | `pub` is a uniform prefix on an import statement (`pub import … as …` / `pub from … import …`); no `use` keyword; a `pub import` **requires `as <ident>`** (no last-segment auto-bind, D22); re-exports obey the collision rules. |
| **D55** | Generic traits | A `trait` may take type parameters but is implementable **at most once per type** — no overload resolution; substitution-based conformance + `(trait, type)` keying, no new dispatch. Multi-impl/overloaded generic traits, trait objects, user-trait bounds deferred. |
| **D56** | Floats schedule | Implement `float32`/`float64` (+ `float` alias, `f32`/`f64` suffixes) per D19/D20 in v0.5. Unsuffixed float literal defaults to `float32`; explicit `as` for int↔float; SSE2/XMM codegen. |
| **D57** | Package/module resolution | Files=modules, dirs=packages; optional `foo/foo.my` package-root module defines a package's public surface via `pub import` (no glob re-export); file/dir name clash → error; project root = entry-file directory (no manifest yet); reserved roots (`std`) shadow-protected; `from a.b import c` resolves module-before-item; import cycles allowed (const-init cycles already error, D28). |
| **D58** | String interpolation | `f"…{expr}…"` prefix, arbitrary expressions in `{ }`, `{{`/`}}` literal braces, **no** format specs in v0.5, single-line only; pure desugar to `format(fmt, args…)` (lexer balanced-brace split). |

## 12. Implementation status

v0.4 (abstraction) is complete; v0.5 (Tier E) is in progress. This section tracks
the v0.5.1–v0.5.6 slices as they land (example, interpreter↔native parity, error
corpus), mirroring §9 of [v0.4-abstraction.md](v0.4-abstraction.md).

### v0.5.1a — import front end (landed)

Lexer/parser/AST support for imports and `pub`, with no semantics yet (the loader
follows in v0.5.1b):

- **Lexer:** new keywords `pub`, `import`, `from` (`as` already existed). Leading
  relative-import dots reuse the existing `.`/`..` (`DOT`/`DOTDOT`) tokens.
- **AST:** `ImportDecl` (whole-module `import a.b.c [as x]` vs. selective
  `from path import a, b as c`), `ImportPath` (leading-dot count + segments),
  `ImportItem`; an `is_pub` flag on every named declaration (struct/fun/enum/
  typealias/const/trait).
- **Parser:** `pub`-prefixed declarations and imports; the D54 rule that a
  `pub import` **requires `as <name>`**; `pub`/attributes rejected on `impl`;
  attributes rejected on imports.
- **Checker:** a temporary guard rejects programs that still contain `ImportDecl`
  at type-check time with "module imports are not supported yet (the loader
  arrives in v0.5.1b)" — removed once the loader lands.
- **Tests:** `tests/unit/test_imports.py` (18 cases: path forms, relative dots,
  `pub`, the `as`-required rule, and the malformed-import errors).

### v0.5.1b/c — module loader + linker (landed, `from` form)

A new front-end stage (`src/myla/loader.py`) turns an entry file plus its import
graph into one flat, name-qualified `ast.Program` that the existing checker /
interpreter / compiler consume unchanged — modules are purely a front-end
concern (§1.5). Shipped with interpreter↔native parity.

- **Loader:** resolves the import graph from the entry file (memoized by
  canonical path, cycles allowed), maps dotted paths + leading dots to files via
  the D22 search bases, and enforces the D57 corner cases — package-root modules
  (`pkg/pkg.my`), file/dir name clashes, project root = the entry file's
  directory, reserved-root (`std`) shadow protection, and module-before-item.
- **Qualified merge:** the **entry** module keeps simple names (id `""`); every
  other module M gets a unique id and its top-level name `n` becomes `M$n`
  (``$`` can't occur in a source identifier, so qualified names never collide
  with user names, method keys, the prelude, or assembler labels). A
  **scope-aware renamer** rewrites every in-module reference (values, types,
  struct/enum names, patterns) to its qualified target, skipping names shadowed
  by a local binding; locals/builtins/prelude names are left untouched.
- **Visibility & re-exports:** `pub` declarations form a module's export table;
  `from P import x [as a]` binds P's exported `x` (importing a non-`pub` name, or
  a name collision, is a `ModuleError`); `pub from P import x` re-exports it
  (resolved to a fixpoint so chains settle).
- **CLI:** `myla run`/`test`/`build` now link the entry file's module graph
  before checking. Direct `check(parse(tokenize(src)))` (single source, no
  imports) still works, and a checker guard rejects a non-linked program that
  still contains imports.
- **Tests:** `tests/unit/test_loader.py` (`from` imports, aliases, cross-module
  structs + methods, local-shadows-import, `pub from` re-exports, package roots,
  nested/parent-relative paths, cycles, diamonds, and the error corpus) +
  `tests/burn/test_modules.py` running the committed `examples/modules/` project
  on both backends.

### v0.5.1b-ii — whole-module imports + member access (landed)

Completes the import surface. A name now resolves to a tagged **binding** —
either a declaration (`("decl", qualified)`) or a module (`("module", id)`):

- **`import a.b.c [as x]`** binds the module (under `x`, or the dotted path
  `a.b.c`) for **member access**: the renamer folds a `module.member[.…]`
  field-access chain into the qualified target, walking re-exported sub-modules
  and leaving any trailing segments as ordinary field accesses. Supports
  function/const access and enum construction (`x.Color.Red`); using a bare
  module as a value, or accessing a non-`pub` member, is a `ModuleError`.
- **`pub import a.b.c as x`** re-exports the *module* under `x`, so a consumer
  can `from M import x` and use `x.member` (resolved to a fixpoint alongside the
  decl re-exports).
- **Limitation:** module-qualified **types** and **`match` patterns** aren't
  dotted (`x.Color` in type/pattern position doesn't parse) — import the type
  directly with `from a.b.c import Color`. Member access is for value/expression
  position (calls, consts, enum constructors).

### v0.5.2 — floats (landed)

`float32`/`float64` (+ the `float`=`float32` alias, `f32`/`f64` suffixes) with
full interpreter↔native parity (§3).

- **Front end:** `FLOAT` token (fractional/exponent/`f`-suffix forms,
  disambiguated from `..` ranges and tuple `.0` indexing); `FloatLit` AST node.
- **Checker:** `FloatType`; literal defaulting to `float32` + contextual typing;
  the `as` matrix incl. int↔float; arithmetic `+ - * / %` and the six
  comparisons; no implicit int↔float or width mixing; no bitwise on floats.
- **Backends:** the interpreter narrows `float32` after each op; the compiler
  uses **SSE2** (carrying the f64 image in a GPR, computing in XMM), an `__fmod`
  helper, and a deterministic round-trippable **plain-decimal** formatter
  (double-double scaling) emitted identically by both, gated by `_uses_float`.
- **Tests:** `tests/unit/test_floats.py`, the `float_*` parity programs, and
  `examples/floats.my`.

### v0.5.3 — `char` type + UTF-8 string model (landed)

**v0.5.3a — char type core:**

- **Lexer:** char literals are scalars (not bytes) with `\u{…}` escapes and
  surrogate/over-range rejection.
- **Checker:** `CharType` (a primitive, valid map key, `Eq`/`Ord` only — no
  arithmetic); char literals default to `char` but an ASCII literal stays
  flexible to an integer type (D42); `char`↔integer `as` (not `char`↔float);
  char comparisons; literal `match` patterns over chars.
- **Backends:** a char is a 32-bit codepoint in a GPR; `print`/`format` render
  it as its UTF-8 glyph via the shared encoder (`char_utf8_bytes` /
  `__char_to_str`, gated by `_uses_char`).

**v0.5.3b — codepoint iteration:**

- **`chars(s) -> [char]`** builtin: the interpreter decodes UTF-8 into a
  `ListValue` of codepoints; the compiler emits a gated `__str_chars` helper (a
  UTF-8 decode loop building a `[char]` cell). `for c in chars(s)` iterates
  scalars; the byte view stays `s[i]`/`len(s)`.
- **Tests:** `tests/unit/test_chars.py`, the `char_*` parity programs (incl.
  `char_chars_iteration`), and `examples/chars.my`.

### v0.5.4a — freestanding I/O runtime: output + exit (landed)

- **Bundled stdlib:** modules live in `src/myla/std/*.my`; the loader's
  `default_stdlib_root()` resolves `std.…` against the package directory, and
  the CLI + burn harness pass it to `link`. The reserved-root shadow guard (D57
  r4) still applies.
- **`std.io`** (`io.my`): `write(fd, s)`, `println(s)`, `eprint(s)`,
  `eprintln(s)` — thin wrappers over `__write`. **`std.process`** (`process.my`):
  `exit(code)` over `__exit`.
- **Runtime primitives:** `__write(fd: int32, s: str)` and `__exit(code: int32)`
  (diverging) — global builtins in the checker. Natively, `__write` is a gated
  helper running the `write` syscall (`_uses_write`) and `__exit` inlines the
  `exit` syscall. The interpreter routes fd 1/2 to its stdout/stderr streams
  (else `os.write`) and turns `__exit` into the process status via a new
  exit-signal path; `Interpreter.run()` now returns the exit code and `myla run`
  propagates it.
- **Tests:** `tests/unit/test_stdio.py` (primitive type rules + linked `std`
  surface) and `tests/burn/test_stdio.py` (interpreter↔native parity on stdout,
  stderr, and exit status, incl. `examples/stdio/main.my`).

### v0.5.4b — command-line arguments (landed)

- **`std.process.args() -> [str]`** over a new `__args` primitive. `args()[0]`
  is the program name.
- **`_start`** stashes `argc`/`&argv[0]` into `.bss` globals (`__argc`/`__argv`)
  unconditionally; the gated `__args` helper (`_uses_args`) builds a `[str]`
  list, `strlen`/copying each C string into a heap `str` cell. The interpreter
  returns a copy of its captured argv; `myla run file.my [args…]` forwards the
  trailing arguments, and the burn harness pins a shared `argv[0]` (via
  `subprocess` `executable=`) so both backends match.
- **Tests:** the `__args` type rules + `args()` cases in `tests/unit/test_stdio.py`,
  the `TestStdioParity`/`TestArgsExample` cases in `tests/burn/test_stdio.py`,
  and `examples/args/main.my`.

### v0.5.4c — filesystem reads (landed)

- **`std.fs.read_to_string(path) -> Result<str, IoError>`** (in `fs.my`), with
  `IoError = NotFound | PermissionDenied | Other(int32)`. The `?` operator
  propagates `IoError` across modules unchanged (D36).
- **Primitives:** `__read_file(path) -> str` (open/fstat/read/close; bytes →
  `str` cell; errno → gated `__io_errno_val` global) and `__io_errno() -> int32`.
  `fs.my` assembles the `Result`/`IoError` in pure Myla. The native helper
  NUL-terminates the path on the stack; the interpreter mirrors it with Python
  file IO and `OSError.errno`. Gated on `_uses_read_file`.
- **Tests:** `tests/unit/test_fs.py` (primitive rules + linked `read_to_string`,
  incl. `?` propagation) and `tests/burn/test_fs.py` (interpreter↔native parity
  on contents, byte length, and `NotFound`/`Other(EISDIR)` errno paths, plus the
  `examples/readfile/main.my` end-to-end program tying together fs + argv +
  streams + exit).

### v0.5.5 — restricted generic traits (landed)

- **Surface:** `trait Comparable<T> { fun compare(self, other: T) -> int32 }`
  with `impl Comparable<int32> for Money { … }`. A type implements a generic
  trait at most once, so `m.compare(x)` needs no overload resolution.
- **Parser:** `ImplDecl` gains `trait_args`; `impl Trait<Args> for T` is now
  accepted (`for` clauses no longer require a bare trait name). `trait Name<…>`
  already parsed.
- **Checker:** the "generic traits unsupported" guard is lifted. `TraitSig`
  stores the trait's `type_params`; trait signatures resolve those parameters as
  `TypeParam`s (alongside `Self`). On `impl Trait<Args> for T`, the arity is
  checked, a `{param: arg}` map is built, and `_subst_self` (now also a
  trait-parameter substitution) maps both `Self → T` and the trait params before
  conformance. Coherence is the **existing** `(trait, type)` duplicate rule — a
  second `impl` of a trait for one type is rejected regardless of arguments.
- **No runtime change:** methods lower to ordinary mangled functions, so the
  interpreter and native backend are untouched; parity is automatic.
- **Tests/example:** `tests/unit/test_generic_traits.py` (parser shape,
  substitution/conformance, arity, coherence, `Self`-as-param rejection,
  interpreter dispatch) and `examples/generic_traits.my` (covered by the example
  run/compile/`#test` burn suites for interpreter↔native parity).

### v0.5.6 — string interpolation (landed)

- **Surface:** `f"{name} = {value}"` → `format("{} = {}", name, value)`. Holes
  hold arbitrary expressions (`f"{a + 1}"`, `f"{p.name()}"`, `f"{m["k"]}"`),
  `{{`/`}}` are literal braces, single-line only, no format specs (parity with
  `format`).
- **Lexer-only:** `_fstring` scans the literal with a balanced-brace pass and
  emits the tokens of a `format(...)` call directly (`format`, `(`, the
  format-string `STRING`, then `,` + each hole's tokens, `)`). Each hole's source
  is captured by `_fstring_hole` (skipping nested string/char literals via
  `_fstring_copy_quoted`) and re-lexed with a sub-`Lexer`, its token columns
  shifted back onto the original line. No new `TokenKind`, AST, parser, checker,
  or backend code — the existing `format` path does the rest, so interpreter and
  native parity are automatic.
- **Diagnostics:** empty `{}` hole, a lone `}` (use `}}`), unterminated literal
  (single-line), and invalid escapes are lexer errors; an unprintable hole type
  is the usual `format` type error. Negative corpus:
  `examples/errors/lex_fstring_empty_hole.my`,
  `examples/errors/lex_fstring_unterminated.my`.
- **Tests/example:** `tests/unit/test_interpolation.py` (token-level desugaring,
  errors, interpreter results) and `examples/interpolation.my` (run/compile/
  `#test` burn suites for interpreter↔native parity).
