# Native backend

The code generator ([[selfhost/codegen.my]], with [[selfhost/lower.my]], [[selfhost/ownership.my]], [[selfhost/ir_x86.my]] and [[selfhost/runtime_x86.my]]) turns the checked program into GAS/AT&T assembly for x86-64 Linux (and, since November 2026, into aarch64 assembly for Linux and a wasm32 module for WASI: the last two sections), making concrete copies of generic code as it goes ([[Architecture/Monomorphization]]); `myla build` writes the `.s`, runs `as --64` and `ld`, and deletes the intermediate files (`driver.my`). There is no libc: the runtime talks to the kernel with system calls (D2, D29). Since [[MYLA-162]] most of it is Myla, `std.rt` over the platform layer `std.platform`, compiled through the IR with every program; what stays hand-written for the target ([[selfhost/runtime_x86.my]]) is the program's start, the traps and the panic, the system-call and memory primitives, the executor's control transfers, a function value's environment copies, composition and the float primitives.

Most of this page describes the x86-64 target. It was written for the Python backend (`src/myla/compiler/codegen_x86.py`, retired with the Python toolchain, [[MYLA-219]]). The self-hosted code generator began as a port of it and keeps its calling convention, value layouts, reference counting, runtime and helpers (its runtime text is the Python backend's, edited in `codegen.my` since); since [[MYLA-107]] it emits every function from its IR ([[Architecture/IR]]) instead of in one pass. Where this page names a function with a leading underscore (`_layout_frame`, `_store_call_words`, …), it is the Python backend's; the self-hosted one does the same in the lowering and the instruction selection.

## Strategy

- Each function is lowered to the IR ([[selfhost/lower.my]], [[Architecture/IR]]), its ownership instructions expanded into plain loads, counts and calls ([[selfhost/ownership.my]]), and translated by the target's backend: [[selfhost/ir_x86.my]] (instruction selection, register allocation on lifetime intervals, [[MYLA-257]]), [[selfhost/ir_a64.my]] or [[selfhost/ir_wasm.my]]. The per-type routines (drop, clone, walks, deep copies, derived equality, an environment's routines) are IR functions too, so every backend gets them by translation.
- Every slot (a local, a match binding, a loop counter) has a cell of its own in the frame ([[MYLA-183]] and D112 would share them).
- The runtime is `std.rt` in Myla over `std.platform`, compiled with every program, plus a hand-written file per target ([[selfhost/runtime_x86.my]], [[selfhost/runtime_a64.my]], [[selfhost/runtime_wasm.my]]) for what Myla can't express: the program's start, system-call stubs, threads and their state, signals, the jumps into frames. Portable pieces still written once per target (composition, the function values' adapters, `__str_eq`) are to become IR ([[MYLA-263]]).

(The Python backend was one pass per function with no IR and no register allocation, every expression leaving its result in `%rax`.)

## Calling convention

The main thread's stack may grow to 120 MiB: `_start` raises the soft `RLIMIT_STACK` to that (or to the hard limit, if lower) with `prlimit64`; Linux reads the limit at each growth of the stack and keeps at least 128 MiB free below it, so deep recursion runs where 8 MiB ended in a segfault ([[MYLA-182]]). Running out of it is `runtime error: stack overflow`: `_start` installs a SIGSEGV handler on a 64 KiB alternate stack (`__on_segv`), which takes a fault within 64 KiB below or 1 MiB above the interrupted stack pointer for the stack's end, prints the error and exits with 1; any other fault gets the default action back and happens again. Workers' stacks are 8 MiB with a `PROT_NONE` guard page below each, and every worker has an alternate signal stack of its own (64 KiB, `sigaltstack`), so a worker's overflow is reported the same way; when two overflow at once, one reports and the other waits for the exit (`__segv_once`, [[MYLA-172]], D106). Heap memory is one arena per worker, reserved in chunks as it allocates (D106).

Each target has Myla's own convention, which its backend chooses and its tests hold it to; a platform's C convention applies only at C boundaries, where the FFI converts ([[MYLA-166]], [[MYLA-241]], D130, changing D119). On x86-64 it is System V's integer registers ([[MYLA-250]]; this section describes the self-hosted backend, the rest of the page the Python one):

- The first six argument words travel in `%rdi`, `%rsi`, `%rdx`, `%rcx`, `%r8` and `%r9`, the rest on the stack (word 6 at `16(%rbp)` in the callee), which the caller pops. A `become` can't pass more words on the stack than its function received (the checker's rule). Floats travel in the general-purpose registers too, until the FFI brings `%xmm0`-`%xmm7`; the stack isn't kept 16-byte aligned yet either.
- Scalars (integers, floats as their f64 bit pattern, `char`, `bool`, `str` pointers, list/map/builder pointers) are passed by value in one 8-byte slot.
- Aggregates (structs, tuples, enums, function values) are passed as a **pointer** to the caller's storage, but for a struct, tuple or enum parameter that a `become` hands one over to (the checker's `become_handovers`, D88): its words are copied into the argument words with references of their own (`_param_byval`, the `("value", …)` items of `_store_call_words`), and the callee binds it as a local there and drops it. This is safe because parameters are immutable; a `var self` receiver is passed the same way, so writes reach the caller. A method writing its receiver gets a copy of an argument read from the receiver's variable instead, as its writes would show through the pointer (`_aliased_args`, [[MYLA-123]], [[MYLA-129]]).
- An aggregate result uses a hidden first argument (sret): a pointer to storage the caller reserved, returned again in `%rax`.
- Function values are called as `code_ptr(args…)` with the env in `%r10`; plain functions used as values get a `myla_<fn>__fnval` adapter, which takes the same words and jumps to the function (a parameter it passes owned retained first, one passed by value copied). The adapters and partial applications' functions are built as IR (`partial_ir` in [[selfhost/lower.my]], [[MYLA-263]]), so every target translates the same thing; only an async function's adapter, a jump to its `__new`, is each backend's.
- `become f(args)` (D87, `emit_tail_call`) loads the words as a call does, drops the statement's temporaries and every owner, moves its stack words into the function's own and jumps; the callee returns to the function's caller. A `become` of the function itself jumps to its entry block.

`_start` stores `argc`, `argv` and `envp`, calls `myla_<entry>`, then exits 0. All user functions are labelled `myla_<name>`.

## Value layout

| Type | Representation |
| --- | --- |
| integers, `char`, `bool` | One 8-byte slot holding the **canonical 64-bit value**: signed types sign-extended, unsigned zero-extended. After arithmetic `_wrap` re-canonicalises (`shl`/`sar`, `movl`, or `and`) |
| floats | The IEEE double bit pattern in a general register; arithmetic in `%xmm0`/`%xmm1`; `float32` is rounded with `cvtsd2ss`/`cvtss2sd` after each operation |
| `str` | Pointer to `[len:8][bytes…]`, a reference-counted heap cell (D62, [[MYLA-18]]). Literals and the renderers' constants (`true`, `nan`, …) are cells in `.data` with the same header and a count of 2^62 (`STATIC_RC`), which retains and drops change but never bring to zero, so they need no special case |
| struct | Fields inline, each in its stored size, in declaration order |
| tuple | Elements inline |
| enum | `[tag:8][payload union]`: the tag is the variant's index; the payload area is as large as the largest variant. A derived `eq` compares tags first; on an enum without payloads only that comparison is emitted ([[MYLA-87]]) |
| boxed (recursive) enum, as a member | An 8-byte pointer to a heap cell holding the inline enum value |
| function value | 16 bytes: `(code_ptr, env_ptr)`; `env_ptr` is 0 when nothing is captured |
| list `[T]` | Pointer to a heap cell `[len:8][cap:8][elem…]`, stride = the element's stored size |
| map `[K: V]` | Pointer to `[len:8][cap:8][slot…][next rank:8]`, slot = `[state:8][key:8][value][rank:8]`, state 0 empty / 1 occupied / 2 removed; the rank is the key's place in the order of insertion (D105, [[MYLA-179]]): a new key takes the next rank, a removal leaves a tombstone and a gap in the ranks without touching another slot, so it takes constant time, and `keys` and `for` go through the ranks in order, skipping the gaps (each key straight at its rank when there are none). When the next rank reaches 0.75 of the capacity, an insert compacts the table: tombstones dropped, ranks renumbered 0 … len − 1, the capacity the smallest power of two that leaves it at most half full, so it grows, stays or shrinks; amortised constant time per operation ([[MYLA-310]], std.rt's `map_put_slot` and `map_rehash`); open addressing with linear probing, a multiplicative hash of the key bytes (string contents for `str`, eight bytes at a time, [[MYLA-133]]; the Python backend used FNV-1a), capacity a power of two, its occupied slots and tombstones kept under 0.75 load. A map holds a reference to each `str` key: `__put_map` retains a key it inserts, a compaction moves keys, `remove` releases its key, and `drop`, `clone` and `keys` treat keys like values |
| `StringBuilder` | Pointer to `[len:8][cap:8][bytes…]` (packed bytes) |
| actor (D89) | Pointer to a reference-counted heap cell holding its fields as a struct's. Copies share the cell (it is a reference); `self.f` and `self.f = v` in its methods go through the pointer, without copy-on-write; the last release drops the fields (`__dropb_<A>`, the boxed enums' helper) |

## Heap and reference counting

Heap cells come from 16 MiB chunks std.rt's allocator maps (`std.platform`'s `map_memory`) when the last one is full, none before the first cell, so a program holds about as much address space as it uses (D106 (B), [[MYLA-162]]; until then a 4 GiB arena mapped at start, one per worker with tasks); a cell bigger than a chunk gets a mapping of its own, as big as it needs in whole 64 KiB pages, which `free` gives back to the system (D157). Where the platform can't give memory back (wasm32), a freed big cell goes on `__big_free` for a later one it is large enough for, and a big list or builder that ends where the memory does grows where it is (`grew_in_place`), so a list of 150 million `int64`s fits in its 4 GiB ([[MYLA-284]]). List and builder growth take every byte of the cell they get as capacity (a power-of-two class above 4 KiB holds more than was asked). The chunks of small cells are never given back, by design (D106): a worker keeps what its arena once reached, and a cell freed on another worker comes back only when the owner's free lists miss, so 16 workers each touching 24 MB once keep about 441 MB resident to the end (measured by the review of 2026-11-06, R29). A program that peaks once on many workers pays that peak for the rest of its run; only big cells go back to the system. Every cell has a 16-byte header `[size:8][refcount:8]`; the pointer handed around points just after it.

- `__alloc` rounds the size up to a multiple of 8, takes a free cell of exactly that size or bumps the arena pointer, and sets the count to 1. Exhausting the arena traps.
- Free cells up to 4 KiB (`_SMALL_CELL_LIMIT`) sit on one LIFO list per 8-byte size class (`__free_buckets`, indexed by the size itself as a byte offset), so allocating and freeing them is O(1); a larger cell is rounded up to a power of two and has one list per power after those. Before this (MYLA-16) all cells shared one scanned list, which made bootstrap stage 2 take four minutes instead of a second; until [[MYLA-80]] larger cells shared one list searched for an exact fit, so a cell of a size never requested again stayed unused for good, and a long-running program (the language server) grew with every check.
- `__free` pushes the cell onto its list. Both follow the C convention (D119): no caller keeps a value in a caller-saved register across them (checked by making both overwrite every caller-saved register: the suite and the bootstrap pass). They are `std.rt`'s `alloc` and `free`, with tasks `alloc_tasks` and `free_tasks` (MYLA-162: the names `.set` to them, each worker's arena set up before it runs, by `_start` and when a worker starts); with tasks a cell freed on another worker goes onto its owner's list with a compare-and-swap, which the owner takes back whole (an exchange) before it bumps its arena.
- **Retain** (`_retain`) increments the counts of every heap pointer a value owns: `str`/list/map/builder cells (`_CELL_TYPES`), boxed enum cells, closure environments, recursively through inline aggregates (`_emit_owned_walk`).
- **Drop** (`_drop_value`) calls the per-type drop helper of each owned pointer: `__str_drop`, `__drop_list_<T>`, `__drop_map_<K>_<V>`, `__dropb_<Enum>`, `__sb_drop`, `__func_drop`. A helper decrements the count and, at zero, drops the children and frees the cell.
- **Ownership rules.** A local owns its value; binding copies and retains. Parameters are borrowed: they are never dropped by the callee, but for the ones a `become` hands a heap value over to (the checker's `become_handovers`, D87), which the callee owns and drops and every caller gives a reference of its own (`_param_owned`). Owning locals are recorded per scope (`_drop_scopes`) and dropped at scope exit, before `return` (`_emit_return_drops`) and on `break`/`continue` (`_emit_loop_exit_drops`). Owning temporaries (a call's result, a literal, a `match` expression's value) are dropped when their statement ends (`_drop_expr_temps`). Where no statement end follows, they are dropped as soon as the value is computed: an `if` or `while` condition, a match guard, a range bound, and each operand of `&&`/`||`, whose right side may not run (`_eval_scalar`). A match registers its scrutinee's temporaries with its drop scope, so an arm that leaves early (`return`, `break`, `continue`, a failing `?`) drops them too. Until [[MYLA-74]] none of these were released, which leaked memory and, by keeping counts above 1, made copy-on-write copy on every write. A `for` loop retains the list or map it iterates for the duration of the loop.
- **Stores** of a heap-owning value (any assignment, MYLA-3) and all stores into containers (`push`, `xs[i] = v`, `m[k] = v`, `append_byte`, and a map literal's values, each after its key) evaluate the value first, into a frame slot that owns one reference (`_stage_value`), and only then find, unshare and grow the container, release the old value and move the new one in (`_commit_staged`). That is the interpreter's order: a `?` inside the value leaves the container untouched, `push(xs, pop(xs))` and `xs[i] = xs[i]` work, and until the commit an early return releases the staged value (MYLA-4).
- **Boxed elements.** A list of a recursive enum holds boxes; `pop` copies the value out of the box, retains what it owns and releases the box ([[MYLA-74]]).
- **Copy-on-write.** A write through a place (`xs[i] = v`, `push`, `m[k] = v`, `remove`, `append`, and a field assignment at any depth such as `xs[i].f.g = v`) first finds the slot that holds the cell pointer, then `_cow_unique` clones the cell if its count is above 1 and stores the clone back; `_mut_place_addr` does this for every container on the path to the place. Clones retain the elements they now share.
- **Match bindings** borrow from the match's copy of the scrutinee. When an arm may write to the variable the scrutinee comes from (an assignment to or into it, a mutating builtin on it, or a method call on it, found by `_may_write`), that copy is retained for the duration of the match, so the write copies on write instead of changing or freeing what the bindings see (MYLA-2). Otherwise nothing is retained: Myla has no references and closures capture by value, so nothing else can change the scrutinee during the match (`arms_may_write`).

The burn tests run allocate-and-drop loops of millions of cells to prove memory is reclaimed ([[Development/Testing]]).

## Closures

A capturing lambda allocates an environment cell: word 0 points at the record of its routines, `[drop, clone, deep]` in the data (`myla_<lifted>_env_routines`; `__env_plain_routines`, shared, when no capture owns heap: std.rt's `free`, and a plain cell's copies), the same on every target ([[MYLA-263]]), the captured values follow inline (a recursive enum too, like a variable holds it), copied and retained. Lambda bodies are emitted as separate functions `myla___lambda_<n>` whose hidden first argument is the environment; a captured name compiles to a load through it. `__func_drop` (std.rt's `func_drop`) decrements the environment's count and, at zero, calls the drop function its record names (`call_code`).

## Async functions and tasks

D90, D91 and D92, [[MYLA-138]] and [[MYLA-137]]: a program with an `async let` (or compiled with `--async-frames`, for the tests) runs its async functions as stackless frame functions, its tasks on a pool of OS threads; without one, an async function is an ordinary function and `await` its operand, a valid schedule for one task, and the program keeps the runtime of one thread. (The Python backend refused concurrency, D91.)

- **Normalized first** (`anf.my`, the compiler's `Norm`): each `await` in a `let` of its own, so no temporary lives across a suspension. An `async let x = e` becomes `async let x = (async || await e)()` (no `await` unless `e` is a call): the child is an async lambda holding deep copies of what `e` uses, its body the self-hosted interpreter's child's (`task_body`), so the two schedule tasks alike on one worker.
- **The frame.** `myla_f__new(args)` (built as IR, `frame_new_ir`, [[MYLA-263]]) allocates `[resume fn 0][caller 8][state 16][task 24][link 32][task's first frame 40][flags 48][parent task 56][actor handed 64][result 72…][slots…]`, zeroed, with owned copies of the arguments; `myla_f` is the frame function, its one argument the frame, held in `%r15` (kept out of allocation), every slot at an offset from it, its entry dispatching on `state` to the points after its `suspend`s. A function value of an async function makes the frame (its `__fnval` adapter jumps to `__new`).
- **Suspensions** are tail calls with the resume state stored first, so a frame is published only once its function has left it: an awaited call (`g(fr)` after `fr = g__new(args)`, `fr.caller = frame`; `return` moves the value into the result and tail-calls `__finish`, which resumes the caller with `jmp *(caller)`), `myla___yield` (a turn for the others after an awaited synchronous call), `myla___wait` (parked on a child: `lock cmpxchg` of its `task` word from 0) and `myla___actor_enter`. A deep chain of awaits uses no stack. An awaited `var self` method of a struct writes its frame's final `self` back into the receiver: a variable, or a field or list element of one, each index computed once before the call ([[MYLA-142]]); also a place in the state of the actor whose async method makes the call, whose copy for the method is deep (it runs off the actor) and is written back once the method holds the actor again (D99, [[MYLA-169]]).
- **Workers.** `_start` starts `MYLA_THREADS` workers, or one per CPU the process may run on (`sched_getaffinity`), at most 32: the main thread and `clone`d threads (`CLONE_VM`, `FS`, `FILES`, `SIGHAND`, `THREAD`, `SYSVSEM`, `SETTLS`) with 8 MiB stacks. Each has a block of runtime state that `%fs` points at (`tls_offset`: its heap, its free lists, the frame it resumed, its stack pointer for a failure, the actor it holds, `io` errno, `run`'s results). Each has a queue of ready frames, a ring under a lock word of its own ([[MYLA-140]]): it pushes onto its own queue and takes its newest frame (depth first), and when its queue is empty it steals the oldest frame of the next queue that has one (the biggest piece of a tree of tasks); a frame yielding a turn goes to the oldest end, behind the others (`__exec_yield_push`). One worker runs the self-hosted interpreter's order (D110, [[MYLA-231]]; it ran first in, first out before). `MYLA_SCHED` (`__sched_init`, [[Language/Concurrency#Order of tasks]]) changes the policy: `fifo` takes the oldest frame and queues a yield at the newest end; `seed:N` queues each push at the end bit 33 of a generator (x · 6364136223846793005 + 1442695040888963407, the interpreter's too) picks. A worker with nothing to run spins a while, then sleeps on a `futex` that a push wakes. The entry's task ending ends the process (`exit_group`); every worker idle with nothing queued is a runtime error (no task can go on).
- **Heaps.** Each worker maps chunks of its own as it allocates, aligned to their size with the worker's number in their first word, so a cell's address rounded down to a chunk tells its owner (a cell bigger than a chunk: an aligned mapping of its own, the same word first, given back by whichever worker frees it). The rings of ready frames are reserved for the workers that run, not for 32. A worker allocates from its own arena and free lists; freeing another worker's cell pushes it onto that worker's list of cells freed elsewhere (`lock cmpxchg`), which the owner takes back whole (`xchg`) when its free lists miss.
- **Tasks.** A child's first frame is its task: its `task` word says 0 running, the frame waiting for it, or 1 done, swapped atomically. `await x` waits (several frames can wait for one task, linked through word 32: the parent and the siblings that await it, [[MYLA-148]]), then the result is copied out (the child has ended; a sibling, which may read it while the parent does, makes a deep clone that only reads it, `clone T`); every scope joins its children on each exit (`join_task`), dropping an unread result. A panic or `exit` in any task ends the program (D94, D97, [[MYLA-150]]): the first claims `__exec_failing` (`__task_fail`, `lock cmpxchg`), from then on a worker taking a frame from a queue drops it instead of resuming it, passing on an actor handed to it (word 64), and once no other worker runs a frame (`__wait_stopped`) the failure is reported and the process exits; a later failure's worker just goes back to the executor. Every frame knows its task's first frame (word 40), a task its parent (word 56): `task.cancel(a)` sets bit 2 of the flags (word 48) of the child's first frame (`__task_cancel`, D96, [[MYLA-149]]) under the timers' lock and wakes the task's sleepers and readers and its children's (D124); a sleeper or reader reads its task's flags under that lock before it waits, so a cancel can't fall between the two (it did, [[MYLA-163]]: a child then slept its whole time), and `task.cancelled()` walks from the running task's first frame up its parents looking for it (`__task_cancelled`; 0 without tasks).
- **Actors** have executors, after their fields (`[lock][running][first waiting][last]`, D92): entering a busy actor queues the frame (linked through word 32) and the worker moves on; leaving hands the actor to the next frame, which goes to the run queue holding it. On more than one worker, a frame finding the actor busy with no frame queued first waits up to 1,000 `pause`s for it to come free ([[MYLA-150]]): a frame queued keeps the actor until a worker resumes it, so without the wait every later caller queued behind it too (a convoy), and nobody waiting before it keeps the order first come, first served. An awaited call of an actor's synchronous method takes the receiver and arguments into slots, leaves the caller's own actor, enters the receiver's, calls, leaves and yields; an actor's async method enters at its start and after each suspension and leaves before each and at its end. On one worker an actor is never busy.
- **Deep copies** (`deep T [%p]`, D92): a child's captures, by the parent; an actor method's arguments as it starts and its result before it leaves. `__deepw_<T>` walks a value; `__deep_<cell>` makes a cell unshared deeply, reusing it when it is the only reference and cloning it otherwise (with the copy-on-write clones), so copying what only the sender holds costs a walk; a function value's env is copied by the routine its record names (`__deep_env`, `__dclone_env`: the record's third and second words; without tasks they are 0). Actor handles are shared: their counts are atomic (`lock incq`, `lock decq`). Static strings are shared too (their counts start at 2^62 and never reach zero).
- **Output.** `print` writes its line with one `writev` (`__print_line`), so lines printed by several workers at once stay whole; every exit is `exit_group`.
- **Costs.** Eight CPU-bound children run 3.9 times as fast on 4 workers as on one, a tree of 131,072 small tasks 3.7 times. A program whose tasks mostly take turns at one actor gains nothing from more workers: eight tasks making 20,000 calls each of one actor take 14 ms on one worker, 49 on two, 80 on four (189 before the wait for a busy actor), the actor's record and the tasks' frames moving between cores at every call; and on one worker a program pays a few milliseconds more than the runtime of one thread for locks, atomics and copies.


### Memory ordering

[[MYLA-267]]. x86-64 keeps stores in order and loads in order, and its locked instructions are full barriers, so the runtime's protocols were first argued there. aarch64 may reorder a store with a later load, a load with a later load, and plain stores with each other. What each protocol needs and what gives it, on aarch64:

| Protocol | What must hold | How |
|---|---|---|
| **Spin locks** (each queue, each actor record, the timers and watches) | What a holder wrote is seen by the next holder | `take_lock`: an exchange (`ldaxr`/`stlxr`, then `dmb ish`). `give_lock`: a release store (`__store_rel64`, `stlr`). |
| **A task's end and its waiters** | A waiter that sees the task done (`task` word 1) sees its result | `task_end`: the result first, then an exchange on the word. The awaiting code's own check (the lowering's `wait_task`, before it calls `__wait`) and `task_wait`: an acquire load of the word (`__load_acq64`, `ldar`), then a compare-and-swap to join the waiters. A plain load there let arm64 hardware read a stale result: siblings cloning a finished child's closure crashed in 3 of 100 runs (t20). Litmus: t23 (1,024 children's heap results). |
| **Parking** (`exec_idle`, `exec_pushed`) | A frame pushed while a worker goes to sleep is run without waiting for another push: the sleeper sees it in its last glance, or the pusher sees the sleeper and wakes it, or the futex wait returns at once because `__exec_seq` moved; at worst a worker wakes for nothing | The sleeper counts itself (`__fetch_add64`), reads `__exec_seq` with acquire (`__load_acq64`, so the glance's loads can't be satisfied before it; the review of 2026-11-06, R17) and looks at the queues; the pusher pushes, bumps `__exec_seq` (`__fetch_add64`) and reads the sleepers. Both read-modify-writes end in `dmb ish`, so neither side reads before its write is seen. The futex compares `__exec_seq`. Litmus: t26 (tasks yielding through the queue, [[MYLA-301]]). |
| **The timers** (`timer_add`, `timers_fire`, `cancel_after`) | Each timer fires once, and none after its frame has ended | The timers' heap under its spin lock; a deadline is armed under that lock only while the child's frame isn't flagged ended (8), and `task_end` takes it back under the same lock when the frame is flagged as having one (4) (R1). Litmus: t24 (cancelled sleepers), t25 (timers from every worker), t22. |
| **The descriptor watches** (`wait_fds`, `poll_events`, `watch_take`) | Every task waiting for a descriptor is woken when it is ready | One registration per descriptor with the poller, the waiters listed under the watches' lock; a ready descriptor queues all its waiters and is forgotten when none is left (R5). Litmus: t27 (child processes' pipes). |
| **The failure flag** (D97) | A failing task sees every frame a worker runs, or that worker sees the flag | A worker publishes the frame it takes (`__xchg64` on `__exec_cur`, a full barrier), then reads `__exec_failing`. `__task_fail` claims the flag (`ldaxr`/`stlxr`, then `dmb ish`), then looks at the workers' frames. |
| **The stuck check** (MYLA-275) | No frame is missed while every worker is idle | The counts are read with read-modify-writes, which are ordered, around a generation that a worker bumps on leaving `exec_idle`. |
| **The poller's claim** (`__exec_polling`) | One worker polls at a time | Claimed by an exchange, given back by a release store. |
| **Remote frees** | A cell freed by another worker is pushed and taken whole | Pushed by compare-and-swap, taken by an exchange. |
| **Glances** (`exec_peek`, `exec_find`'s empty check, an actor's spinning caller) | Nothing: they are hints | A stale value only costs a round. Every decision is made again under the lock, or by the next round. |

Two primitives give the one-sided orders: `__load_acq64` (`ldar`) and `__store_rel64` (`stlr`), the IR's `load_acq64` and `store_rel64` intrinsics ([[Architecture/IR#what-each-instruction-means]]). On x86-64 they are plain moves, on wasm32 plain loads and stores (one worker). The atomics `__cas64`, `__xchg64` and `__fetch_add64` are full barriers on every target. The stress programs run on GitHub's arm64 runner in CI (`scripts/stress-native.py`, 20 runs on each of 1, 4 and 16 workers). qemu on an x86-64 machine can't show a reordering.

## Runtime helpers

The generated code reaches the runtime four ways, the same on every target ([[MYLA-162]], [[MYLA-263]]): std.rt's functions under their Myla names (`myla_std$rt$stat`; lowering maps a primitive's name to its function, `__stat` to `std$rt$stat`, in `myla_runtime_function` of [[selfhost/lower.my]]); a few of them also under the name the code calls (`.set __alloc, myla_std$rt$alloc`); the per-type routines, built as IR; and the target's runtime file for what Myla can't express. Checked against the assembly of the compiler itself (2026-11-07, [[MYLA-298]]).

| Group | Entries |
| --- | --- |
| Start and failure | the runtime file's `_start`, `__panic` and the trap entries `__trap_index`, `__trap_key`, `__trap_pop`, `__trap_div`, `__trap_mod`, `__trap_match`, `__trap_step`, `__trap_char`, `__trap_boundary`, `__trap_oom`, each passing its message to `__panic` (see below), which hands a task's failure to `__task_fail` or calls std.rt's `panic_report` (`.set __panic_report`): `runtime error: <message>` and the position to stderr, exit 1, allocating nothing |
| Printing | std.rt's `print_str` (`.set __print_str`), `print_int`, `print_uint`, `print_bool`, `print_char`, `float_to_str`, `char_to_str`; every output through `std.platform`'s `write_all` (short writes, `EINTR`, `EAGAIN`; a write error is D153's) |
| Strings | std.rt's `str_eq`, `str_concat`, `int_to_str`, `uint_to_str`, `bool_to_str`, `str_chars` (UTF-8 decode, U+FFFD for each byte outside a well-formed sequence), `equal_bytes` (`.set __equal_bytes`) |
| Heap | std.rt's `alloc` and `free` (`.set __alloc`, `__free`), `alloc_tasks`, `free_tasks` (D157), `func_retain`, `func_drop` (`.set __func_retain`, `__func_drop`) |
| Collections | per type, as IR: `__drop_list_T`, `__clone_list_T`, `__drop_map_K_V`, `__clone_map_K_V`, `__dropb_E` (a boxed enum's), `__walkd_T` and `__walkr_T` (a deep copy between tasks, the drop of what it walked); std.rt's `list_grow`, `map_new`, `map_lookup` (each under `.set __<name>`), `map_put_slot`, `map_keys`, `sb_append`, `sb_append_bytes`; the builder's `__sb_drop`, `__sb_clone` and `__str_drop` |
| I/O | std.rt's `write`, `read`, `poll`, `args`, `read_file`, `write_file`, `list_dir`, `mkdir`, `stat`, `unlink`, `rmdir`, `rename`, `getcwd`, `getenv`, `clock_ns`, `wall_ns`, `sleep_ns`, over `std.platform` |
| Processes | std.rt's `run`, `run_with`, `spawn`, `spawn_with`, `reap`, `kill`, `close` |
| Floats | std.rt's `float_to_str` with `two_prod` and `fscale`, its `fmod`, and the tables of powers of ten `__pow10_hi`/`__pow10_lo` it reads |
| Function values | `__compose_call` and `__compose_env_drop` (IR, [[MYLA-263]]) |

The system calls are `std.platform`'s, one module per target: [[lib/std/platform.my]] (x86-64's numbers), [[lib/std/platform_aarch64.my]] (the generic table) and [[lib/std/platform_wasm.my]] (WASI's imports). Its interface is Linux's (negative errnos, `getdents64` records, `st_mode` bits); [[MYLA-265]] is to make it Myla's.

## Runtime-error positions

A runtime error prints the interpreter's first two lines: `runtime error: <message>` (without the values) and `  --> file:line:col`, the position of the node the interpreter reports for the same error ([[MYLA-65]], D75). It works in every build, not only with `-g`:

- Each position a trap can report has a 16-byte record in `.rodata`, `[file str:8][line:4][col:4]`, where the file is a static `str` cell (shared with literals of the same text); records are shared by all traps at one position (`_load_position`).
- A check jumps over a call to the trap entry (`_trap`): `cmpq %rdx, %rax; jb .L7; leaq .Lpos3(%rip), %rsi; call __trap_index; .L7:`. The common case falls through one taken branch. The `call` (it never returns) leaves a return address, so under gdb `break __panic` then `bt` shows the Myla frame and line, and `up` shows its variables.
- `__trap_<kind>` loads its message into `%rdi` and jumps to `__panic`, which writes the prefix, the message and, when `%rsi` isn't 0, the position. `panic`, `assert` and `unreachable` call `__panic` with their message and the call's record. `__trap_oom`, reached from `__alloc`, has no position.
- `append(sb, s, start, end)` checks its range inside `__sb_extend_range`; the caller passes the record in `%r8`.
- The file is named as the loader names it (`set_sources`, `path_of`), as diagnostics name it: for an entry file given relative to the working directory, that path, and the modules it imports relative to the working directory too. (The Python backend named them as the Python CLI did, which is the same for such paths.)

## Float formatting

Natively, `print` and `format` render floats (`__float_to_str`) like this, and the interpreter prints exactly the same (`format_float` in `std.num`): find the decimal exponent by binary search over a table of powers of ten, scale the value to a 9- or 17-digit integer using double-double arithmetic (Dekker's exact product with a high/low power-of-ten table), round half to even, renormalise, trim trailing zeros and lay the digits out positionally. The native version (std.rt's `float_to_str`, [[MYLA-162]]; assembly until then) uses the same constants and the same operation order, so the output is byte-identical to the interpreter's. Two details keep it exact at the ends of the range (MYLA-29): an operand above 2^996 would overflow Dekker's split, so `two_prod` first scales it down by 2^64 and the other operand up (both exact); and for magnitudes below about 10^-292, which are scaled by 10^200 first, the intermediate stays a double-double. The assembly version was the Python backend's, which `scripts/gen_selfhost_runtime.py` copied into `codegen.my` until [[MYLA-219]]; of it only `__fmod` and the tables of powers of ten remain.

## Debug information

`myla build -g` adds DWARF debug information, on x86-64 only so far ([[MYLA-259]]); without `-g` the output is unchanged. See [[Development/Debugging]] for what gdb shows.

- **Line table** ([[MYLA-71]]): `.file`/`.loc` directives, one `.file` per source module (the loader records each function's `source_path`), a `.loc` at each function's label, before every statement and before each expression-bodied match arm, and `.loc <file> 0 0` after each function so the runtime helpers emitted later have no source line. The assembler turns them into the `.debug_line` table. Lambdas take the file of the function they are created in.
- **Variables and types** ([[MYLA-66]], D75): [[selfhost/dwarf.my]] writes `.debug_abbrev` (a fixed table) and one compile unit in `.debug_info`, whose `DW_AT_stmt_list` points at a label opening `.debug_line`, where the assembler puts its table. The unit's language is Rust, whose printing rules and expression syntax suit Myla. The code generator streams the DIEs while it walks a function: `begin_function` opens a subprogram (its label, `myla_<name>`, frame base `%rbp`, and its result type for `finish`: a scalar's or cell pointer's type read from `%rax`, a pointer to an aggregate result, which `%rax` holds after the hidden-pointer return, none for a float result, which is in `%rax` where gdb reads `%xmm0`); every name bound in a scope goes through `_bind` (parameters and captures for the whole function; another binding opens a lexical block at a label emitted after its value is stored, ending at a label emitted when its Myla scope closes, `_push_scope`/`_pop_scope`), so shadowing and scopes are exact. Locations follow the scope entries: `DW_OP_fbreg off` for a local, plus `DW_OP_deref` for an aggregate parameter or a borrowed aggregate loop variable, through the environment for a capture. Types are emitted once each, after the subprograms: base types (a signed integer as its whole 8-byte slot, so gdb writes it sign-extended), structs, tuples (fields `__0`, …), enums as Rust variant parts (a `<tag>` discriminant and one variant struct per tag), function values; a `str` or builder variable is a Rust `&str` made of two computed pieces, a list variable an array at its elements with a count read from the header (`DW_OP_push_object_address`), a `float32` variable the double it is kept as, converted (`DW_OP_GNU_deref_type`, `DW_OP_GNU_convert`). Inside aggregates and lists a heap value is a pointer to a description of its cell (`len`, `cap`, the bytes or items as an array sized from the header, a map's `slots` `[state][key][value]` as many as its capacity), since gdb accepts only fixed-size types there. Generic instances get their Myla names (`Option<int32>`) from the monomorphizer's `type_display_names`.
- **Pretty-printers** ([[MYLA-66]], D82): [[lib/debug/myla_gdb.py]] is embedded in every `-g` binary as an inline Python script (kind 4) in `.debug_gdb_scripts` (`"MS",@progbits,1`: the byte 4, the name `myla-printers` and a newline, the file's text as `.ascii` lines, a NUL). The compiler reads `<stdlib root>/debug/myla_gdb.py` (`dwarf.read_gdb_script`, called by `gen_main` and the CLI driver, passed to `enable_debug_info`). gdb runs it on loading the binary where `auto-load safe-path` allows; it registers a global printer `myla` that recognises the cell types by name and fields (`str`, `StringBuilder`, `[T]` with `items`, `[K: V]` with `slots`), pointers to them, pointers to structs and enums (boxed enums, aggregate results), and the 8-byte base type `float32`. Cells print as their text, elements or entries, the rest as the value pointed at or a float. The script must stay ASCII.

## Integer details

How x86-64 does what [[Architecture/IR#what-each-instruction-means]] says each operation means (the other targets' ways are in their sections):

- `/` and `%` test the divisor for zero (`jz __trap_div` / `__trap_mod`), then use `idivq` (signed, after `cqo`) or `divq`. A signed divisor of -1 skips `idivq` (which faults on the minimum): `/` negates and `%` gives 0, so the result wraps ([[MYLA-5]]).
- Shift counts are masked to `width - 1` before `shl`/`sar`/`shr`.
- Comparisons pick signed (`setl`…) or unsigned (`setb`…) instructions from the left operand's type; `char` compares unsigned.
- Float → integer casts saturate (D59): NaN (`ucomisd` sets the parity flag) gives 0, inputs at or beyond the target's bounds give its minimum or maximum, the rest go through `cvttsd2si`; a `uint64` from 2^63 up converts `x - 2^63` and sets the top bit. `uint64` → float handles the high bit with a halving trick.

## aarch64 Linux

[[MYLA-163]] (D117): `myla build --target aarch64-linux` (and `gen_main --target aarch64-linux`) compiles for Linux on aarch64. The front end, the lowering and the ownership pass are the same; three files are the target's:

- [[selfhost/ir_a64.my]], the IR to aarch64 (GNU syntax), entered from `emit_ir_at` once the ownership instructions are plain. Its register allocation is simple on purpose (the owner's choice, 2026-11-04): every temporary and every slot has a cell in the frame, and each instruction loads its operands into scratch registers (x10 to x15), computes and stores its result back. [[MYLA-257]] is to build one allocator, independent of the target, for both backends; until then this costs speed, not correctness. Myla's convention on aarch64 (D130): the argument words in x0 to x7, the rest on the stack at the caller's sp, a result in x0, an aggregate result's address as the first word, a function value's environment in x9. It differs from AAPCS64 in two points, which matter only at a C boundary, where the FFI converts: floats travel in x registers, not d registers, and the aggregate result's address is the first word, not x8 ([[MYLA-272]]). The frame is `stp x29, x30` at the top, x29 its base, below it the outgoing words, the temporaries' cells, the slots and a scratch cell. `become` is a tail call (a branch after the stack words are written into the ones the function received), and so is a call whose result the function returns at once, with x86-64's guards (`tail_call_at`, `drops_after_free`, `passes_frame_address`), when its words fit the eight argument registers ([[MYLA-283]]). Integer values are kept extended from their type's width as on x86-64 (`sxtw`, `sxth`, `sxtb`, or a mask); a zero divisor traps before `sdiv`/`udiv`; a shift's count is masked to the width; a float is its bits in a general register and goes through d0 and d1 (`fcvtzs`/`fcvtzu` already truncate, saturate and give 0 for NaN, D59; narrower targets are clamped after). Partial applications' functions, the function-value adapters, frame constructors and `__compose_call` are IR ([[MYLA-263]]); only an async function's adapter is written here (`emit_fnval_thunk_a64`).
- [[selfhost/runtime_a64.my]], the hand-written runtime: `_start`, the traps and `__panic`, `__syscall`/`__syscall5` (`svc #0`, the number in x8), the bulk copy and comparison, the function values' counts, composition, std.math's primitives. A float `%` calls std.rt's `fmod` (aarch64 has no `frem`): exact, musl's long division of the significands on the bits, as x86-64's `fprem` gives it.
- [[lib/std/platform_aarch64.my]], `std.platform` for aarch64's system calls (the generic table: `openat`, `newfstatat`, `mkdirat`, `unlinkat`, `renameat2`, `ppoll`, `epoll_pwait`, `clone` for a fork, its unpacked `epoll_event`). The loader takes it for `std/platform.my` on that target (`for_target`, the smallest form of choosing a module per target, [[MYLA-245]]).

On an aarch64 machine, its default target there, assembled and linked by the machine's GNU `as` and `ld`, as the bootstrap from `bootstrap/seed-aarch64.s` does (D127, [[MYLA-276]]); from another machine by `clang --target=aarch64-linux-gnu` and `ld.lld -static`; [[tests/burn/test_aarch64.py]] runs the programs under `qemu-aarch64` against their x86-64 builds, and builds the compiler itself for aarch64: run under qemu, it compiles `examples/maps.my` to the same assembly, for either target, as the x86-64 one. That the aarch64 compiler compiles the whole compiler byte for byte as the x86-64 one does is CI's `bootstrap-arm64` job: the bootstrap on arm64 hardware reaches the fixed point, and that compiler writes the x86-64 seed byte for byte ([[MYLA-268]], D127). Tasks (D90, D92) work as on x86-64: a frame function keeps its frame in x28 (saved and restored, a callee-saved register no other code uses), its slots there as x86-64 lays them out (`slots_at`, `frame_size`), its state at frame + 16; `myla_<f>__new` makes the frame; the executor's entry points, `__task_fail` and the workers (`clone` with `CLONE_SETTLS`, whose aarch64 order is flags, stack, parent tid, tls, child tid) are in `runtime_a64.my`; a worker's state block is at `tpidr_el0` (`msr` for the main thread, the kernel's `CLONE_SETTLS` for the others); the atomics are `ldaxr`/`stlxr` loops. The stress programs ([[tests/burn/test_concurrency_stress.py]]) and the reactor's ([[tests/burn/test_time.py]]) pass under qemu on 1, 4 and 16 workers and in the other orders; qemu on an x86-64 host doesn't reorder memory as aarch64 hardware may, so the atomics' ordering wants a run on hardware. Running out of the stack is reported as on x86-64 (MYLA-182): `_start` raises the stack limit to 120 MiB (`prlimit64`), every thread gets an alternate signal stack (`__alt_stack`), and `__on_segv` reads the fault address at siginfo + 16 and the interrupted sp in the sigcontext (ucontext + 432); the kernel returns from the handler through its own trampoline (no `SA_RESTORER`). Under qemu-user the guest's stack doesn't grow to the limit: it is mapped at a fixed size, 8 MiB unless `QEMU_STACK_SIZE` says otherwise. Not yet: `-g` ([[MYLA-259]]).

## wasm32 on WASI

[[MYLA-158]] (D125): `myla build --target wasm32-wasi` (and `gen_main --target wasm32-wasi`) writes a WebAssembly module for a WASI preview 1 host. As for aarch64, the front end, the lowering and the ownership pass are shared; three files are the target's, and a runner:

- [[selfhost/ir_wasm.my]] translates the IR to LLVM's wasm assembly. wasm has no registers to allocate: every temporary is an i64 local, and the engine allocates. Every function takes its argument words as i64 parameters and gives an i64 (0 when it has none), so a function value is one `call_indirect` type per number of words; its code word is its index in the table (wasm-ld makes the table from the functions whose address is taken), and its environment is the call's last argument (D130): a lambda's body, a partial application's function, a plain function's `__fnval` adapter (which ignores it), an async lambda's `__new` and `__compose_call` take it as their last parameter. No memory word is shared between calls, so the convention holds with threads too. Control flow is a dispatch loop (D125 (3)): a `loop` around a `block` per IR block and a `br_table` on a block-number local; a jump stores the next number and branches back. A stackifier is to replace it when speed matters. The slots are cells of a frame on the shadow stack (`__stack_pointer`, which wasm-ld defines), a frame function's in its heap frame (its one parameter). `become`, the call before a `suspend` and a call whose result the function returns at once (with x86-64's guards, [[MYLA-283]]) are `return_call`; a zero divisor traps first, and the minimum divided by -1 wraps (wasm's `div_s` would trap); float-to-integer casts are the saturating `trunc_sat` (D59), clamped for narrower types; a float `%` is std.rt's `fmod`.
- [[selfhost/runtime_wasm.my]]: `_start`, the dispatcher `__syscall(n, args, …)` through which std.platform calls the WASI import numbered `n` with the words of a static block, the traps and `__panic`, the bulk copy (`memory.copy`) and the executor's entry points on one worker (D125 (4)); a function value's counts and an environment's copies are std.rt's, through the record of its routines, as on the other targets ([[MYLA-263]]). Then `wasm_module` puts the text together for clang: the `.set` aliases resolved (wasm has no function aliases), every function's `.functype` declared first (and each call's word count checked against its callee's), a pointer word in data written as the symbol's 32-bit address and a 0, every data label sized up to the next one. LLVM 18's assembler checks the stack loosely around `unreachable`, so a call's unused result is dropped before one.
- [[lib/std/platform_wasm.my]], `std.platform` over WASI: files through `path_open` and friends against the first preopened directory (descriptor 3) and `PWD` for relative paths, directories through `fd_readdir` rewritten as Linux's records, the clock, sleeping and the poller through `poll_oneoff`, the heap through `memory.grow`, no processes (`run` and `spawn` fail with ENOSYS), WASI's errnos as Linux's.
- [[tools/wasm/run.mjs]] runs a module under Node with [[tools/wasm/wasi.mjs]], a WASI shim of our own (its core imports nothing of Node's; the files and streams come from [[tools/wasm/node_fs.mjs]], the host's, or [[tools/wasm/mem_fs.mjs]], files in memory): Node 22's `node:wasi` crashes with a segmentation fault when the memory grows between two calls (a module that only grows its memory and writes crashed it in 3 runs of 5), and a browser has no WASI at all, so the shim is also what a page will use. It counts a watched input as ready at once (Node can't wait for input without blocking), so a read on wasm blocks the program as a blocking one would.

Clang assembles (`--target=wasm32-wasi -mtail-call -mbulk-memory -mnontrapping-fptoint -msign-ext`) and `wasm-ld` links (`--stack-first -z stack-size=8388608`). Addresses are 32-bit, held zero-extended in i64 and in memory as today's 8-byte words (D126; D122's 4-byte layouts are [[MYLA-260]]). [[tests/burn/test_wasm.py]] holds the programs to their x86-64 builds and the compiler built for wasm to the native one on `examples/maps.my`. The compiler built for wasm (3.4 MB) also compiled the whole compiler under Node in about 5 s, byte for byte as the native one does, for x86-64 and for wasm (the fixed point holds on wasm too); `test_the_compiler_compiles_itself` checks it in CI ([[MYLA-268]]).

Running out of the stack is `runtime error: stack overflow` with exit 1, as natively ([[MYLA-261]]). The module is linked with `--stack-first`, so the shadow stack is `[0, 8 MiB)` and the data lies above it (wasm-ld's default puts the stack above the data, where an overflow ran through the data). Every function's prologue compares `__stack_pointer` with its frame's size; with no room, `__trap_stack` gives the stack back whole (`__stack_high`) and reports the error through `__panic`. The engine's own call stack, which runs out first for small frames, is reported the same way by `run.mjs` and `myla.mjs`; any other trap as `runtime error: <the engine's message>`. A computed NaN's bits follow the host's CPU on wasm, as aarch64's differ from x86-64's (0x7FF8… against 0xFFF8…, [[MYLA-266]]).

### The page API

The checker and the interpreter run in a page ([[MYLA-158]]): [[selfhost/play_main.my]] built for wasm32-wasi (about 2 MB) is `play check <file>` (the diagnostics as JSON: severity, kind, message, path, line, column, the range's end, the notes; the errors as `myla check` reports them, then the warnings), `play run <file> [args]` and `play test <file>` (as `myla run` and `myla test`). [[tools/wasm/myla.mjs]] puts it behind an API a page imports:

```js
import { loadMyla } from "./myla.mjs";
const myla = await loadMyla(fetch("play.wasm"));
const { ok, diagnostics } = await myla.check(source);          // source: main.my's text, or {"main.my": …, "geo.my": …}
const { stdout, stderr, exitCode, files } = await myla.run(source, { stdin: "…", args: [] });
const tests = await myla.test(source);
```

Each call runs a fresh instance with its files in memory (a `MemFs`, which also holds what the program wrote); the standard library is built into the module. A trap comes back as a runtime error (V8's call-stack limit as `runtime error: stack overflow`). A program that never ends never returns, so a page runs it in a Web Worker. [[tools/wasm/page.html]] is the smallest playground on it, and `scripts/build-page.sh` puts the page, the API and `play.wasm` in one directory for a static server. [[tests/burn/test_wasm.py]] holds `check` to `myla check` on the error corpus (226 errors in 203 files: kind, message, position), `run` and `test` to `myla run` and `myla test` on every example, and the page itself in Chromium (where Playwright is installed).
