# Interpreter

[[selfhost/interp.my]] is a tree-walking evaluator over the checked declarations. It runs `myla run`, `myla test` and the REPL. It and the native backend must print the same thing for every program. The type information it needs at run time (integer widths, how to print and format a value, casts) comes from the checker's `resolved` table, keyed by node id.

Until the Python toolchain was retired (D101, [[MYLA-219]]), the Python interpreter (`src/myla/interpreter.py`) defined the language's behaviour and the self-hosted one mirrored it; the burn tests still compare with its output, recorded ([[Development/Testing]]).

## Values

| Myla | `Value` |
| --- | --- |
| integers | `VInt(int64)`, in the type's width after every operation: an operation whose result doesn't fit is the runtime error `integer overflow`, a shift's count past the width `shift amount out of range` (D175; `add_overflows`, `sub_overflows` and `mul_overflows` of [[selfhost/checker.my]], with the result already computed; the interpreter's own arithmetic through the wrapping methods, so it can't overflow where it runs interpreted itself); `wrapping_*` wraps |
| `char` | `VChar(int64)`, the code point |
| floats | `VFloat(float64)`; `float32` results are rounded to single precision |
| `bool`, `str` | `VBool`, `VStr` (a host `str`: bytes) |
| no value | `VUnit` |
| struct, tuple, enum | `VStruct(name, field names, values)`, `VTuple(elements)`, `VEnum(enum, variant, payload)` |
| a `[uint8]` from a stream | `VBytes(str)`: the bytes of a host string, without a value per byte, what `__read_bytes`, `__str_to_bytes` and the `__run_*` results give; `__write_bytes`, `__bytes_to_str`, `len`, an index, a slice, `==` and hashing take it as it is, any other use takes it apart into a `VList` first (`list_values`), so a `push` or an element's assignment makes it an ordinary list ([[MYLA-414]], the 2026-11-10 review's S2: interpreted `io.copy` of 32 MB, 2 s with a value per byte, 31 ms) |
| list, map, builder | `VList(elements)`, `VMap(MapV)`: the keys and values as parallel lists in insertion order, a removed entry leaving a hole, and an index from each key to its place (a native map of the integer, `char` and `bool` keys' numbers, one of the strings; any other key, D163, by its hash, `Interp.key_hash`: its structure, or the `hash` written for its type, each hash's places chained oldest first and the key found among them with `==`, which calls a written `eq`, [[MYLA-313]]; native code's probe meets a hash's keys in that order too, as a new compound key takes the first empty slot past the tombstones, so a written `eq` runs alike, [[MYLA-546]]), so lookups, inserts and removals take constant time; the holes are compacted away when they outnumber the entries ([[MYLA-310]]), and `lo` is the first place that may hold a key, which a removal of the oldest moves on, so `for k in m`, which walks the places from there without the list of the keys, costs what it walks ([[MYLA-496]]), `VSB(bytes)` |
| function value | `VClosure(params, body, capture names, captured values, function name, is a function)`; `VCompose(functions)` for `f >> g`, `VPartial(callable, argument slots, holes)` for `f(a, _)` |
| actor handle | `VActor(i)`: its state in `Interp.actors`, so a copy reaches the same actor (D89) |
| an `async let`'s name | `VTask(i)`: the child in `Interp.tasks` |

**Value semantics.** Structs, tuples, enums, lists and maps are copied when they are bound, assigned, passed, returned and constructed; containers are updated in place ([[MYLA-74]]), so a loop of a million `push`es is linear.

## Execution

- A call starts a fresh frame (`RtFrame`: names and values), since functions see only their parameters, constants and other functions. Functions, constants and enum variants are found by name in an index (`func_ix`, `const_ix`, `variant_ix`, `nullary_ix`), the first declared of each name, and a call by a name no builtin has goes to the function without testing the builtins' names (`names_a_builtin`; [[MYLA-414]]: fib(18) 402 M → 125 M instructions, a lazy `std.iter` pipeline 12.6 → 5 times the hand-written loop).
- **Generic code runs with its types** (D172, [[MYLA-414]]). A generic function's frame binds its type parameters to the types they stand for at that call: its first variable, `%env`, is an index into `Interp.envs`, made once per call site and caller's environment (`env_of`, `env_memo`), one per function and binding (interned in `type_env_memo`, so a recursion through two call sites holds one, not one per call path: generic `fib(27)` 167 MB before, 11 MB, [[MYLA-414]]), from the checker's type arguments of the call (`call_types`), else from the receiver's type and its impl's pattern (`impl_selfs`); a closure made there captures it. So an operator, a comparison, a cast and float rounding typed by a type parameter read the bound type (`typed_of`) and trap, wrap and compare as in a function of that type (`[2000000000, 2000000000].sum(0)` is `integer overflow`, `[uint64].sorted()` orders unsigned, a `float32` rounds), and a format reads the whole type (`full_type_of`: `Option<T>`'s payload). An operator on a generic impl's type and its `format` bind theirs by the operand's type, and so do the interpreter's own calls of a written `eq` or `hash` ([[MYLA-436]]): an element's or a member's `==` (a list's, a tuple's, a derived `eq`'s, called as `a.eq(b)` too), a map's key (a literal's, `m[k]` read or written, `contains`, `remove`), a tuple's `hash`, each by the static type of what it compares or hashes (the operand's, the map's key type, a member's from its container's: `member_types`), memoized by the function and the type (`type_env_memo`). That costs the types' lookups only in a program with such an `eq` or `hash` of a generic struct or enum (`typed_keys`); any other compares and hashes as before (`values_equal` and `key_hash`, against `typed_equal` and `typed_hash`). A missing map key's message writes the key by the map's key type (`typed_repr`: a `uint64` unsigned, [[MYLA-440]]), as natively. An integer literal's type is never a type parameter's, and one from 0 to 127 is itself in every integer type, so it is made without looking its type up; `typed_of` tests for a type parameter only once a generic call has bound one ([[MYLA-546]]: the plain loop 240.7 M → 212.8 M instructions).
- **A place's keys are found once** ([[MYLA-506]]). An assignment, `push`, `pop`, a builder's `append`, `remove` and a `var self` call reach their place (`Place`: a variable and its steps) through `settle`, which checks each index as the read would and keeps where each compound map key was found (`Step.SIndex`'s place and hash, the map's own key in place of the program's); `update_cell` writes there without looking the key up again. A kept place stands while no variable changed since (`Interp.writes`, counted by `update_place` and at a change of task, against `Place.stamp`), or while the map still holds the kept key there (`still_at`), else the key is looked up again. A number's or a string's place, which runs no code of the program's, is found again where it is used. A read `m[k]` looks its key up once for the check and the value (`eval_index`), and a compound assignment at a scalar or a string whose value calls nothing (`fused_compound`) reads and writes its place with one lookup (`exec_fused`, the operator's left operand handed over in `fused_val`), as native code does: a key's written `hash` runs as often on both runners (the parity program `map_keys_hashed_once`).
- A method is the one of the receiver's checked type, a type parameter's the type its frame binds (`type_key`). Without one the receiver is evaluated once, as a place when it is one (`self.items[i]`, `m[k]`), and the method keyed by its value; a `var self` method's final `self` goes back to that place. A `var self` call binds its type parameters after its place is settled, since a key's written `hash` or `eq` that `settle` runs would take the binding ([[MYLA-414]], the 2026-11-12 review's B6). A method or function the interpreter can't find is the runtime error `internal error: no method 'm' found for a value of type 'T'` (`… no function 'f' found`) at the call, not a value.
- Myla has no exceptions, so running a block or call returns how it finished; a pending signal on the interpreter (`Ctrl`: `return`, `break`, `continue`, `exit`, `become`) lets a `return` or `?` inside a match arm's value, or an `exit` or `panic` in the middle of an expression, leave from where it is.
- `become` (D87) leaves the call pending (`TailCall`) for the loop that runs the function (`run_tail`), which goes on with it, so a chain of `become`s doesn't nest calls; a `var self` method that `become` calls on `self` passes `self` on, and the caller stores back the last one's.
- Constants are evaluated once from the checker's folded values.
- **Two methods of the library are the interpreter's own** ([[MYLA-546]]): std.str's `find_from` and std.list's `extend` (`run_own`, found by their functions' indices, `fi_find_from` and `fi_extend`), so the end of a line `read_line` looks for (std.io's `newline_from`) and the bytes a list gathers take no interpreted step a byte; an empty list extended by packed bytes keeps them packed. 3 MB in 60,000 lines: 7.6 s before, 1.3 s; 3 MB gathered by `extend` from 61,000 reads: 5.6 s, 0.9 s. Their results are the CLI's own std.str's, as the interpreter formats with its own std.fmt, so a change to either method shows interpreted only after a bootstrap, and an interpreted `#test` of one tests that copy (`--native` tests the library's code).
- `var self` methods write through to the caller's object; read-only `self` gets a copy.
- Operators on structs and enums are dispatched to the trait's method of the receiver's type (`Type.add`, `Type.eq`, `Type.cmp`, …); `?`, composition and partial application are evaluated directly, from what the checker recorded.
- Runtime errors carry the node's position; the CLI prints them as it prints compile errors, with the source line and carets ([[MYLA-32]]).

## Concurrency

D89, [[MYLA-139]], [[Language/Concurrency]].

- **Async functions** are ordinary calls, unless their body has an `await` or an `async let`: such a body is normalized (`anf.my`: each `await` in a `let` of its own, the order of evaluation kept) and runs on an async evaluator, its statements continuations of its call in its task. Everything else runs on the tree walker.
- **Tasks** take turns at each `await`, one at a time, the newest ready task first (a ring of ready tasks, `Interp.ready`, `ready_behind`, `next_ready`; `MYLA_SCHED`, read from `/proc/self/environ`, picks another order): the order the native runtime keeps on one worker (D110, [[MYLA-231]]; which is why `test_unit_programs.py` runs native code on one worker). An `async let` starts a child task; the scope that started it joins it when it ends. A failure in any task ends the program (D97).
- **Actors** are handles to states in `Interp.actors`. Since one task runs at a time, they need no lock.
- **Waiting for input** ([[MYLA-546]]). With no task ready, the sockets parked on lots (std.net's reactor, MYLA-468) are looked at, a poll each, once a millisecond at most and at most a 32nd of the time (`look_gap`: the next look 32 times what the last one took after it, up to 50 ms); when one descriptor is all anything waits for, the interpreter waits in its poll until it is ready or a sleeper is due (`idle_wait`). An idle server woke 894 times a second, 21 now; with 900 parked connections 677 times and 26.5 percent of a CPU, 50 and 3.5 percent (natively none: the reactor waits in epoll). The price is a parked socket's latency, up to the gap: about 10 ms with 1,000 parked (2026-11-12, `fd6ae4e`).

The Python interpreter ran each `async let` child on a Python thread and gave each actor a lock instead.

## I/O primitives

The interpreter is a native program, so the primitives of the standard library (`__write`, `__read`, `__poll`, `__read_file`, `__write_file`, `__list_dir`, `__mkdir`, `__stat`, `__unlink`, `__rmdir`, `__rename`, `__getcwd`, `__run` and the `__run_*` results) call the native runtime's own and behave as in a compiled program ([[Architecture/Native-backend]]). `__args` gives the file followed by the arguments after it on the command line, as `args()` does for a binary. `__read_bytes` and `__write_bytes` (D177) go through `__read` and `__write` with a string between, which the bytes stay (`VBytes`): the interpreter's values aren't the native lists. Under `myla test` a case's standard output is kept for its report, not written, and `__io_errno` right after such a write reads 0 (`captured_io`; an earlier primitive's errno failed `println` in a file named by its absolute path, the 2026-11-09 review's M5).

That runtime is the `std.rt` and `std.platform` the CLI was built with, at the last `scripts/bootstrap.sh`: `--stdlib lib` (or `MYLA_STDLIB`) changes the library the interpreted program is made of, not the primitives under it. So a change to `std.rt` or a platform module (what `__spawn_piped` does with its options, say, [[MYLA-378]]) shows in a native build at once and in the interpreter only after a bootstrap.

## Strings

A Myla `str` is bytes, and so is the host's `str` that holds it: `len`, indexing, `+`, `format`, `==` and map keys work on the bytes, and `chars` decodes UTF-8, giving U+FFFD for each byte outside a well-formed sequence, as natively ([[MYLA-12]]).

## The test runner

`run_tests` goes through every function's and method's `#test` attributes (D116), evaluates the arguments and the expected value, calls the function and compares the values structurally. A runtime error fails that case only. A failing case shows the values as `py_repr` writes them, the Python interpreter's repr, so the report is the one the Python CLI printed ([[MYLA-81]]); a test function's `Err(e)` shows `e` through its `format`, else in that form (a list's, packed bytes', a tuple's and a map's too, [[MYLA-414]]). An index error writes a `uint64` index unsigned, as natively (`list index 18446744073709551615 out of bounds`, [[MYLA-546]]).

## Depth

The interpreter counts its calls: past 2,500 (`MAX_CALL_DEPTH`) it reports `runtime error: stack overflow` ([[MYLA-182]]). An interpreted call takes some 12 to 25 KB of its native stack, because every IR slot has a cell of its own ([[MYLA-183]] would share them), and the native runtime lets the main stack grow to 120 MiB ([[Architecture/Native-backend]]); a program recursing deeper than 2,500 runs natively, but not in `build/myla run`. (The Python interpreter allowed 100,000 frames.)
