# Myla v0.2 — Data Modeling (design)

This is the detailed, decision-complete design for the **v0.2 "data modeling"**
milestone — Tier A in [self-hosting.md](self-hosting.md) §3 and the first big
step past the v0.0 bootstrap. It expands the sketches in
[future-features.md](future-features.md) §1/§2/§7/§10 into a real specification:
concrete syntax, semantics, grammar (EBNF), type-system changes, and an
implementation plan across the existing lexer → parser → checker → interpreter →
compiler pipeline.

**Scope (v0.2):**

1. **Algebraic data types** — `enum` with payloads, including recursive and
   generic enums.
2. **Pattern matching** — `match` with exhaustiveness checking.
3. **Tuples** — fixed-size heterogeneous products, destructuring, multiple return.
4. **Generics** — parametric `fun`/`struct`/`enum`, monomorphized (D13).
5. **`Option` / `Result` + `?`** — prelude generic enums and error propagation
   (D16).

Out of scope (later tiers): lists/maps/sets and the string toolkit (v0.3),
methods/`impl`/traits and lambdas (v0.4), modules and the freestanding runtime
(v0.5). Where v0.2 needs a heap (recursive/boxed values), it uses **reference
counting** (D12) — v0.2 is where the all-on-stack model of v0.0 ends.

> The sub-decisions this design raised (V1–V8) are now **locked** as **D30–D37**
> in [roadmap.md](roadmap.md). This document reflects those decisions; the
> “(see Vn)” markers point at the originating question for provenance.

## 1. Enums (algebraic data types)

### 1.1 Syntax

```my
enum Color {
    Red
    Green
    Blue
}

enum Shape {
    Circle(int)            // positional payload: radius
    Rect(int, int)         // width, height
    Empty                  // no payload
}

// Recursive — exactly what an AST needs:
enum Expr {
    Num(int)
    Add(Expr, Expr)
    Mul(Expr, Expr)
}

// Generic:
enum Option<T> { Some(T), None }
enum Result<T, E> { Ok(T), Err(E) }
```

Variants carry **positional** payloads only in v0.2 (tuple-style). Struct-style
named-field variants (`Add { lhs: Expr, rhs: Expr }`) are deferred (see **V3**).
Commas between variants are optional (newline-separated like fields).

### 1.2 Construction

Variants are **qualified** by their enum at construction (see **V2**):

```my
let c  = Color.Red
let s  = Shape.Rect(3, 4)
let ok = Result.Ok(42)
```

`Option`/`Result` and their variants are exported by the **prelude**, so the
bare `Some(x)`, `None`, `Ok(x)`, `Err(e)` spellings are also available for those
two types (the most common case). All other enums require the `Enum.Variant`
form until modules/`use` arrive (v0.5).

### 1.3 Semantics

- An enum value is a **tagged union**: a discriminant (which variant) plus that
  variant's payload. Value semantics like structs — copied on bind/assign/arg/
  return (deep, honoring D14).
- **Layout**: `tag : uintN` + a payload area sized to the **largest** variant
  (a union). Non-recursive enums live inline (on the stack / in their container),
  exactly like structs.
- **Recursive variants** (a payload that contains the enum itself, directly or
  transitively) would make the layout infinite, so the recursive payload is
  **boxed**: stored behind a heap pointer. The compiler detects recursion in the
  type graph and inserts the box automatically; the programmer writes
  `Add(Expr, Expr)` and never sees the pointer. **Implemented (v0.2.3):** an enum
  on a by-value cycle is boxed wherever it appears as an aggregate *member* (an
  8-byte pointer to an inline heap cell); it stays inline as a local/param/return.
  A cycle running purely through structs/tuples has nowhere to insert indirection
  and is still rejected ("infinite size"). The heap is a `mmap`-backed bump
  allocator (`__alloc`); see §8.2.
- Reference counting (D12): boxed payloads are refcounted (**landed, v0.2.3b**);
  copying an enum value bumps counts, dropping it decrements and frees at zero.
  Because everything is immutable-by-default and deeply copied (D14), there are no
  reference cycles to
  worry about in v0.2 (an immutable value can't be made to point back at itself).

### 1.4 Generic enums

`enum Name<T, ...>` introduces type parameters usable in variant payloads.
Instantiations are **monomorphized** (D13): each concrete `Option<int>`,
`Option<str>`, … is a distinct stamped-out type with its own layout and code —
no boxing-for-erasure, no runtime type tags beyond the variant discriminant.

## 2. Tuples

### 2.1 Syntax & semantics

```my
let pair: (int, str) = (1, "one")
let x = pair.0                    // 1   (positional field access)
let y = pair.1                    // "one"

let single: (int,) = (42,)        // 1-tuple — note the trailing comma
let z = single.0                  // 42
```

- Tuple **types** `(T1, T2, ...)` and **literals** `(e1, e2, ...)` have arity
  **≥ 1** (D35). The 1-tuple is written `(x,)` (type `(T,)`); the **trailing
  comma** is required, and is what distinguishes a 1-tuple from a parenthesized
  expression `(x)`. There is **no `()` unit type** in v0.2 (void stays "no return
  type"; a unit type may come later).
- Fixed size, heterogeneous, **value semantics**. Layout is a struct-like block
  of fields in order; `.0`, `.1`, … are field accesses.

### 2.2 Destructuring & multiple return

```my
let (lo, hi) = pick_neighbors(5)  // positional destructuring binding
let (_, hi)  = pick_neighbors(5)  // `_` ignores a component

fun pick_neighbors(a: int) -> (int, int) {
    return a - 1, a + 1           // sugar for `return (a - 1, a + 1)`
}
```

`return e1, e2, ...` is sugar for returning a tuple. Destructuring is allowed in
`let`/`var` bindings and in `match` patterns (§3). Nested destructuring works:
`let ((a, b), c) = ...`.

## 3. Pattern matching (`match`)

### 3.1 `match` is an expression (see V1)

v0.0 was statement-oriented (D1); v0.2 introduces the first **value-producing
block construct**, because pattern matching that can't produce a value is
painful (and the AST-walking code that motivates all of this is naturally
expression-shaped):

```my
fun eval(e: Expr) -> int {
    return match e {
        Expr.Num(n)    => n,
        Expr.Add(l, r) => eval(l) + eval(r),
        Expr.Mul(l, r) => eval(l) * eval(r),
    }
}
```

- Each **arm** is `pattern => body`, where `body` is an expression or a
  `{ block }` whose value is its final expression (a block ending in a statement
  has no value and may only be used where the `match` value is discarded).
- All arms must yield the **same type**, which is the type of the `match`
  expression. A `match` used as a statement (its value discarded) may have
  value-less arms.
- Arms are separated by commas; a trailing comma is allowed.

### 3.2 Patterns

| Pattern | Example | Notes |
|---------|---------|-------|
| Wildcard | `_` | matches anything, binds nothing |
| Binding | `n` | binds the whole value to `n` |
| Literal | `0`, `true`, `"hi"`, `'a'` | int/bool/str/char (D25) literals |
| Enum variant | `Shape.Rect(w, h)`, `.Some(x)` | sub-patterns are nested patterns |
| Tuple | `(a, b)`, `(_, y)` | positional |
| Struct | `Point { x: px, y: py }`, `Point { x, y }` | named; `{ x }` shorthand binds `x` |
| Or-pattern | `Color.Red \| Color.Blue` | same bindings required on both sides |
| Guard | `Shape.Circle(r) if r > 0` | boolean condition after the pattern |

Nested patterns compose (`Expr.Add(Expr.Num(0), r) => r`). Bindings introduced by
a pattern are in scope in that arm's guard and body. Deferred to later: `@`
bindings (`whole @ Pattern`) and range patterns (see **V4** for the exact v0.2
set).

### 3.3 Exhaustiveness

The checker **requires** a `match` to cover every possibility:

- For an enum scrutinee, every variant must be matched (or a `_` / binding arm
  present). A missing variant is a compile-time error naming it.
- Or-patterns and nested patterns are accounted for. Literal patterns on an
  unbounded type (e.g. `int`) always require a `_` fallback.
- A redundant (unreachable) arm is a warning/error (see **V4**).

Exhaustiveness is the headline correctness win for compiler code: adding a new
AST node forces every `match` over it to handle the case.

## 4. Generics

### 4.1 Syntax

```my
struct Box<T> { value: T }
enum   Pair<A, B> { Both(A, B) }

fun first<T>(xs: (T, T)) -> T {
    let (a, _) = xs
    return a
}
```

Type parameters are declared in `<...>` after the name of a `fun`/`struct`/
`enum`. v0.2 generics are **unconstrained** — there are no trait bounds yet
(traits land in v0.4); operations on a `T` are limited to what works for any
type (move/copy, pass, store, pattern-bind). `Option`/`Result` need no bounds.

### 4.2 Type arguments & inference (see V5)

- In **type positions**, type arguments are explicit and unambiguous:
  `Option<int>`, `Result<int, str>`, `Box<Point>`.
- In **expression positions**, type arguments are **inferred** from the
  arguments / expected type; Myla v0.2 does **not** offer an explicit
  `f<int>(x)` call syntax, because `<` is ambiguous with comparison there. If
  inference is insufficient, annotate the binding (`let x: Box<int> = ...`).
- Nested closers like `Option<Result<int, str>>` end in `>>`; since `>>` is a
  single token (D24), the **parser splits it** when a type-argument list expects
  a `>` (standard technique; not user-visible).

### 4.3 Monomorphization (D13)

After type checking, the compiler collects every concrete instantiation reached
from `main`/entry and stamps out a specialized copy of each generic
`fun`/`struct`/`enum`. This keeps native codegen simple (each monomorph has a
fixed layout, no boxing for type-erasure, no runtime type tags) at the cost of
code size — an acceptable trade for a bootstrapping compiler. The interpreter
can treat generics by erasure (it already works on tagged runtime values), as
long as observable behavior matches the compiled monomorphs.

**Implemented — generic functions (v0.2.4a).** Type parameters parse on `fun`
(`fun id<T>(x: T) -> T`); the checker resolves a generic signature under its
parameters (a bare `T` becomes an opaque `TypeParam`), checks the body once
(operations needing concreteness — arithmetic, `print`, field access — reject a
`T`), and at each call site infers the type arguments by unifying the argument
types against the parameter types (D34), recording them on the call. A
pre-codegen pass (`compiler/monomorphize.py`) then walks the reachable
instantiations and stamps a specialized, mangled copy of each generic function
(`id` → `id__int32`, `id__str`, …), rewriting every generic call to its stamp,
so codegen only ever sees concrete types. The interpreter runs the single
generic body unchanged (erasure). Both back ends are checked for identical
output.

**Implemented — generic structs & enums (v0.2.4b).** Type parameters parse on
`struct`/`enum` (`struct Box<T>`, `enum List<T>`), and a use supplies concrete
type arguments in any type position (`Box<int>`, `List<str>`); the checker
resolves fields/payloads under the declaration's parameters (a member `T` is a
`TypeParam`) and carries the inferred arguments on the `StructType`/`EnumType`.
Type arguments in *value* position are inferred — a struct literal or variant
constructor unifies its initializer/payload types against the (parametric)
field/payload types, and a payload-free variant (`List.Nil`) takes its
arguments from the surrounding annotation or from the other arguments of its
call (left-to-right). The monomorphizer stamps a concrete, mangled *layout* for
each reached instantiation (`Box<int>` → `Box__int32`), re-emitting field/payload
type annotations concretely and rewriting every type reference — annotations,
`StructLit` names, enum-constructor names, and `match` pattern names — to the
stamp; the generic templates and all type aliases are dropped from the program
that reaches codegen. Recursive generic enums are boxed and reference-counted
exactly like non-generic ones, per instantiation. The interpreter runs the
single generic body by erasure. `Option`/`Result` + `?` are the next step.

## 5. `Option` / `Result` and `?` (D16)

### 5.1 Prelude definitions

```my
enum Option<T>    { Some(T), None }
enum Result<T, E> { Ok(T), Err(E) }
```

Defined in the prelude and available unqualified (variants too — see §1.2).

### 5.2 The `?` operator

`expr?` is postfix early-return propagation:

```my
fun double(s: str) -> Result<int, str> {
    let n = parse(s)?        // if Err(e): `return Err(e)` from double; else n = the Ok value
    return Ok(n * 2)
}

fun head(xs: (int, int)) -> Option<int> {
    let first = lookup()?    // if None: `return None`; else unwrap the Some
    return Some(first)
}
```

- On `Result<T, E>`: `Ok(v)` evaluates to `v`; `Err(e)` does `return Err(e)`.
- On `Option<T>`: `Some(v)` evaluates to `v`; `None` does `return None`.
- **Carrier match (see V7):** the enclosing function's return type must use the
  **same carrier** as the operand — `?` on a `Result` requires a `Result` return,
  `?` on an `Option` requires an `Option` return. No cross-carrier conversion and
  no error-type coercion in v0.2 (that needs traits, v0.4+). It desugars to a
  `match` (so it needs nothing the checker doesn't already have for §3).

### 5.3 Implementation status (v0.2.4c — landed)

- **Prelude injection.** `check()` prepends the parsed `Option`/`Result`
  definitions to every program, so they are always in scope and monomorphized
  like any other generic enum. The monomorphizer drops the unused generic
  templates and re-checks the concrete program with `with_prelude=False`.
- **Unqualified variants.** `Some`/`None`/`Ok`/`Err` resolve to their prelude
  enum without the `Enum.Variant` prefix (D31). A bare `None` (no payload) is a
  value; `Some`/`Ok`/`Err` carry payloads and so must be *called*. The
  monomorphizer rewrites each to a qualified reference to the stamped concrete
  enum (e.g. `Result__int32_str.Err`) so the re-check binds the right layout.
- **`?` desugaring.** Once the operand's carrier is known, the checker rewrites
  `expr?` to `match expr { Ok(v) => v, Err(e) => { return Err(e) } }` (or the
  `Some`/`None` form) and type-checks *that*; a post-check pass replaces the
  `?` node with the `match`, so the interpreter and compiler only ever see a
  `match`. This relies on **divergent match arms**: an arm whose body
  definitely `return`s yields no value and so does not constrain the match's
  result type — a small, generally-useful checker rule. RC is inherited from
  `match`/`return`: the early-return path drops the heap locals still in scope
  (covered by a native stress test).

## 6. Grammar additions (EBNF)

Extends [grammar.md](grammar.md). New keywords reserved: `enum`, `match`. (`as`,
`const`, `char`, etc. belong to other milestones.)

```
/* --- declarations --- */
decl_body    ::= struct_decl | fun_decl | typealias_decl | enum_decl

generics     ::= "<" IDENT ("," IDENT)* ">"

struct_decl  ::= "struct" IDENT generics? "{" field_list? "}"
fun_decl     ::= "fun" IDENT generics? "(" param_list? ")" ret_type? block
enum_decl    ::= "enum" IDENT generics? "{" variant_list? "}"
variant_list ::= variant (","? variant)* ","?
variant      ::= IDENT ( "(" type ("," type)* ")" )?

/* --- types --- */
type         ::= prim_type
               | tuple_type
               | IDENT type_args?        /* struct/enum/alias/`int`, maybe generic */
tuple_type   ::= "(" type "," ( type ("," type)* ","? )? ")"   /* (T,) or (T, U, ...) */
type_args    ::= "<" type ("," type)* ">"     /* parser splits a trailing ">>" */

/* --- expressions --- */
primary      ::= INT | STRING | BOOL | CHAR
               | IDENT
               | struct_lit
               | tuple_lit
               | match_expr
               | "(" expression ")"
tuple_lit    ::= "(" expression "," ( expression ("," expression)* ","? )? ")"
               /* (e,) is a 1-tuple; (e) is just a grouped expression */
postfix_op   ::= "(" arg_list? ")"            /* call */
               | "." IDENT                     /* field / variant / method-name */
               | "." INT                       /* tuple index: t.0, t.1 */
               | "?"                            /* Result/Option propagation */

match_expr   ::= "match" expression "{" match_arm ("," match_arm)* ","? "}"
match_arm    ::= pattern ("if" expression)? "=>" (expression | block)

pattern      ::= or_pattern
or_pattern   ::= base_pattern ("|" base_pattern)*
base_pattern ::= "_"
               | literal                         /* INT | STRING | BOOL | CHAR */
               | IDENT                            /* binding */
               | enum_pattern
               | tuple_pattern
               | struct_pattern
enum_pattern   ::= (IDENT ".")? IDENT ( "(" pattern ("," pattern)* ")" )?
tuple_pattern  ::= "(" pattern "," ( pattern ("," pattern)* ","? )? ")"  /* (p,) or (p, q, ...) */
struct_pattern ::= IDENT "{" field_pat ("," field_pat)* ","? "}"
field_pat      ::= IDENT (":" pattern)?           /* `x` shorthand == `x: x` */

/* --- statements --- */
var_decl     ::= ("let" | "var") binding (":" type)? "=" expression
binding      ::= IDENT | tuple_binding
tuple_binding::= "(" binding_elem "," ( binding_elem ("," binding_elem)* ","? )? ")"
binding_elem ::= "_" | binding
return_stmt  ::= "return" (expression ("," expression)*)?   /* 2+ = tuple; `(x,)` for a 1-tuple */
```

Notes:
- `match` slots into `primary`, so it is a full expression (§3.1).
- The `.` `INT` postfix (`t.0`) is distinct from `.` `IDENT` field access; the
  lexer must not glue `t.0` into a float literal (floats aren't in the language
  yet, so a `.` followed by digits after an expression is a tuple index).
- Generic `type_args` reuse the `>>`-splitting rule (§4.2).

## 7. Type-system & checker changes

- **New `Type` representations**: `TupleType(elems)`, `EnumType(name, type_args)`,
  and generic type **parameters** (`TypeParam(name)`) plus instantiation/
  substitution. `Option`/`Result` are ordinary `EnumType`s from the prelude.
- **Generic environment**: when checking a generic `fun`/`struct`/`enum` body,
  bind its `<...>` params; resolve payload/field/param types under that env.
- **Inference**: unify call-argument types with parameter types to solve type
  variables (Hindley–Milner-lite, local to a call; no global inference). Integer
  literal flexibility (existing behavior) still applies inside.
- **`match` checking**: each arm's pattern is checked against the scrutinee type
  (binding the pattern variables), each body checked against a common result
  type; **exhaustiveness** computed over the enum's variant set (and nested
  patterns / or-patterns); redundant-arm detection.
- **`?` checking**: operand must be `Result<_, E>` or `Option<_>`; the enclosing
  function's return type must share the carrier (V7); result type is the unwrapped
  `T`.
- **Recursion detection**: build the type-reference graph to decide which enum
  variant payloads must be boxed (§1.3).

## 8. Interpreter & compiler implications

### 8.1 Interpreter
- New runtime values: `TupleValue(elems)` and `EnumValue(enum_name, variant,
  payload)`; both deep-copy for value semantics (extend the existing
  `StructValue` copy logic).
- `match`: evaluate scrutinee once, try arms top-to-bottom, bind on the first
  matching pattern, evaluate guard, run the body; exhaustiveness guarantees a
  match (a fallthrough is an internal error).
- `?`: desugars to `match` (Ok/Some → value; Err/None → `_ReturnSignal`).
- Generics: erased — the interpreter operates on tagged runtime values, so a
  single generic body works for all instantiations.
- Reference counting is not strictly needed in the interpreter (Python GC backs
  it), but recursive structures must be representable (they are — just nested
  `EnumValue`s).

### 8.2 Compiler (x86-64)
- **Enum layout**: `tag` (smallest `uintN` that fits the variant count) followed
  by the max-payload union, with per-variant field offsets. Boxed (recursive)
  payloads store an 8-byte refcounted pointer instead of the inline value.
- **Tuples**: identical to structs (ordered slots); `.0/.1` are field offsets.
- **`match` lowering**: a tag dispatch (jump table or compare chain) + field
  extraction into the arm's bound slots + the guard test; arms lower to the
  existing block/expression codegen.
- **Heap allocator** *(landed, v0.2.3)*: `__alloc` reserves a large anonymous
  `mmap` arena on first use and bump-allocates from it — the first heap in the
  compiler. Boxing a value (`_box`) allocates a cell and copies the inline value
  in; matching through a boxed edge unboxes (deref + copy) into a temp slot.
- **Reference counting runtime** *(v0.2.3b, landed)*: every heap cell carries a
  `[size, refcount]` header. Cells are retained (`incq` the count) whenever a boxed
  pointer is copied into a new owner, and released through generated `__dropb_<E>`
  glue that decrements, recursively drops children, and pushes the cell onto an
  exact-fit free list (`__free`) at zero — so a build/discard loop runs in bounded
  memory. Drops are inserted at scope exit, at the end of the statement that
  produced a temporary, before an overwriting assignment, and on `return` (after
  the result is retained into the caller's buffer). Parameters, the `match`
  scrutinee copy, and pattern bindings *borrow* (no retain/drop) since they never
  outlive the owner they read from.
- **Monomorphization (D13)** *(generic `fun`/`struct`/`enum` landed, v0.2.4a–b)*:
  a pre-codegen pass (`compiler/monomorphize.py`) walks reachable instantiations
  and stamps specialized, mangled `fun` copies and concrete `struct`/`enum`
  layouts, rewriting every reference (calls, type annotations, struct literals,
  enum constructors, `match` patterns) to its stamp so codegen then sees only
  concrete types; generic templates and type aliases are dropped before codegen.
  The interpreter runs generics by erasure.
- **Parity**: the existing burn-test methodology extends — every new example
  must produce identical output under interpreter and native binary.

This is a large milestone; suggested implementation order mirrors the tiers:
tuples → non-generic enums + `match` (+ exhaustiveness) → recursive enums (heap +
refcount) → generics (monomorphization) → `Option`/`Result` + `?` (mostly
desugaring on top of the above).

## 9. Decisions (resolved)

The sub-decisions this design raised are **locked** as D30–D37 in
[roadmap.md](roadmap.md): `match` is an expression (D30); `Enum.Variant`
construction with prelude shorthand for `Option`/`Result` (D31); positional
variant payloads only (D32); the pattern set incl. or-patterns + guards (D33);
generic args inferred at call sites (D34); tuple arity ≥ 1 with `(x,)` 1-tuples
and no unit type (D35); same-carrier `?` (D36); and `==` primitives-only with
structural equality deferred to traits (D37).
