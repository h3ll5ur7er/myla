## 1. Executive summary

1. **The project is in far better shape than a two-week, 196-commit sprint usually leaves a codebase.** Every suite is green, the fixed point holds, the IR verifier runs in production, diagnostics are byte-identical between the two toolchains, and the JSON/TOML/float code matches Python bit for bit. The native concurrency runtime survived ~400 adversarial runs on 1 to 16 workers without a crash *inside the documented rules*.
2. **The one serious hole is in the concurrency checker, not the runtime** **[verified]**: an `async let` inside an actor method may read `self.xs`; the child then reads the actor's list on another worker while a sibling mutates it. Both checkers accept it; natively it crashes with "index out of bounds" or hangs at 4 and 8 workers. The central isolation promise of the Concurrency page is false until this is rejected.
3. **Stack depth is unguarded everywhere except native user code** **[verified]**: `build/myla check`/`run`/the language server segfault on ~1000 nested parentheses or ~900 levels of recursion; the Python toolchain dies with a raw `RecursionError`. For an editor-facing tool this is a crash-on-paste.
4. **Four accepted programs behave differently across implementations or crash the oracle** **[verified]**: a map literal with a generic value (`[1: Some(2)]`) fails the Python backend with a `KeyError`; `let c = 2147483648` is accepted and wraps; `1e38 * 10.0` crashes the interpreter where native prints `inf`; an awaited `var self` struct method on an actor field gives 2000 / 1000 / internal error across the three runners.
5. **The documentation's rules are accurate; its status text is stale by one to four months.** README, Home, Language.md, Architecture.md, Decisions.md, Roadmap.md and Testing.md still say D1–D58, "in progress", "designs not built yet", "~410 tests", "166 corpus files", "notably float codegen is missing". Someone arriving today would misjudge the project by a whole version.
6. **The process has two meanings of "done".** The agent set all 52 `done` statuses itself; 87 tasks wait in `review` and the owner has moved none. Everything else about the board is unusually disciplined.
7. **Six implementations of every semantic change** (two checkers, two interpreters, two backends) is now the project's largest structural cost, and the Python backend is already behind (no concurrency, the `Option` bug). D71 should be revisited with an end state.
8. **The stdlib is thin where users feel it first**: no string split/join/trim/compare, no sorting, no `min`/`max`, no format width or precision, no clock, no env, no file handles. The consequence is measurable: ~25 private copies of `trim`, `starts_with`, `is_digit` and merge sort across `selfhost/`, `tools/` and `std/`.
9. **The convention "every value-returning function in `selfhost/` has `#test` cases" is not true** **[verified]**: 1164 of 1259 have none. Either enforce it or stop claiming it.
10. **The roadmap is now very wide** (LLVM, aarch64, macOS, Windows, wasm, C FFI, an Angular website with a gamified tutorial, a SwiftUI-like GUI) for a README that still says "very simple custom language, focus on simplicity, not safety". The vision statement and the plan have drifted apart; one of them should move.

## 2. What is genuinely good

- **Engineering discipline.** Test-first with evidence in every task; the error corpus (203 files) pins message, range, notes, error count and native stderr per rule; the self-hosting gates compare canonical tokens, ASTs, every diagnostic with its range and notes, interpreted and native output, and declaration mutants (674 of them). The fixed point is checked in CI.
- **Diagnostics** are among the best in a hobby compiler: ranges, "declared here" notes, "did you mean" help, a summary line, errors attributed to the right module, runtime-error positions in non-`-g` builds, the same text from both toolchains.
- **Design decisions are recorded with alternatives and reasons** (97 of them), and each task links to its decision. The honesty is notable: the Concurrency page's "What Myla guarantees, and what it doesn't" table names its limits.
- **Native runtime quality.** Hand-written assembly with a correct Dekker-style futex sleep protocol, push-only waiter lists (ABA-free), per-worker heaps where the address tells the owner and remote frees are drained by one `xchg`, actor hand-off without thundering herds. Reviewers tried hard to lose a wakeup and could not.
- **The IR** (D79, D85) is small, printable, verified in production, and the async lowering (frames, `suspend`, deep copies) was added through it rather than around it. `become` with owned parameters threads a list through 300k steps in well under a second where every other implementation is quadratic.
- **`std.json`, `std.toml`, `std.num`** are correct on every nasty edge thrown at them and are fuzzed against Python's modules on thousands of documents; float formatting is byte-identical across the interpreter and both backends.
- **The project tool** works end to end on first try, including Git dependencies, a lock file, `.partial` checkout recovery and caret-level manifest errors.
- **The language server** answers hover/definition/references/completion in under 5 ms on real files and typed member completion in 0 ms; a 20k-line file checks in 1.5 s.
- **The VS Code extension** is strict TypeScript, lint-clean, 54 tests including eight against real gdb, DAP-over-MI with no dependency on other extensions.
- **The `myla` skill's "Rust and Swift habits that are wrong in Myla" table** is the best onboarding artefact in the repository.
- **Task board hygiene** is excellent mechanically: 159/159 files parse, consistent key order, no id mismatch, no broken wiki links across 1,675 of them, superseded tasks closed honestly.

## 4. Concepts and philosophy

**What the project says it is.** README: "Very simple custom language… Focus on simplicity, not safety… No dependencies." Language.md: statically typed, explicitly sized, value semantics, immutable by default, mostly statements, errors as values, everything checked before running. Home: self-hosted, x86-64 Linux without libc.

**What it has become.** A language with monomorphized generics, traits with operator overloading, closures, guaranteed tail calls with an eight-rule checker, Swift-style actors with a stackless lowering and a work-stealing multi-threaded runtime, a mid-level IR with an ownership verifier, DWARF with embedded gdb pretty-printers, a cargo-like project tool with Git dependencies, a language server, a tree-sitter grammar generated from an EBNF, and a plan for LLVM, four more platforms, a C FFI, a website and a GUI framework.

**Assessment.**

- The *core* language philosophy (value semantics, sized ints, no implicit conversion, `let` deep immutability, ADTs + `match`, `Option`/`Result` + `?`) is coherent and consistently applied; the reviewers found no place where the implementation contradicts it. Actors as "the only reference type" is a clean, single escape hatch.
- "Simplicity, not safety" no longer describes the project. The concurrency design's whole justification (D89) is "safety from the checker"; D93 rejects a lambda mutating a capture for safety; D95 adds warnings. That's fine, but say so: the vision bullets in the README should be rewritten to what the project actually values now (predictability, parity, self-hosting, zero dependencies, checker-enforced safety where cheap).
- "No dependencies" is honoured scrupulously (stdlib-only Python, no libc, external `as`/`ld` only) and it is a real differentiator. The LLVM plan (D98 to be) keeps it by treating `llc` as a build tool like `as`; good.
- **The interpreter is the semantics** (D71) is the load-bearing principle and it is now under strain: the Python backend refuses concurrency, has the `Option` map bug, and is quadratic on `become` chains; the self-hosted interpreter is the one users actually run. Two full interpreters and two full backends means every semantic change is made six times (the self-hosted reviewer counted 322 hand-mirrored error sites in `checker.my`). The gates make this *work*, but it is the single biggest tax on velocity and the reason the stdlib stays thin (every builtin is a six-way change). A decision about the end state is due: e.g. "the Python toolchain is frozen as the stage-0 bootstrap and a semantics oracle for the language as of v1.0; new features are specified by the self-hosted interpreter and gated by the parity corpus," or the reverse.
- **Decision-log churn.** D94, D96 and D97 were written on one day and D97 supersedes parts of both D89 and D94. "Locked decisions" that are superseded within hours are session notes, not decisions. Nothing wrong with iterating, but the log would be more honest with a "provisional" state, or by waiting a day before numbering.
- **Scope.** The roadmap ideas (MYLA-62, 63, 158 to 167) are all reasonable individually. Together they are several person-years. With 87 tasks unreviewed, adding eight planned platform tasks reads as a plan for an agent, not for a person. A one-line "what we will *not* do in the next quarter" on the Roadmap would help more than another epic.

## 5. The language itself

Things a language designer would question, with a judgement on each. These come from running probes, not just reading.

| Choice | Judgement |
| --- | --- |
| `int` = int32, `float` = **float32**, unsuffixed float literals are float32 | int32 is defensible. `float` being the *less* precise type surprises everyone (the skill has to bold it) and `0.1 + 0.2 == 0.3` is true only through float32 rounding. Worth a decision to flip `float` to float64, or to drop the alias. |
| Collections use free functions (`push(xs, v)`, `len(s)`) while user types and even `impl int32` get methods; `impl [T]` is forbidden | The single largest source of "looks right, fails here". Either allow `impl [T]`/method sugar on builtins or make the free functions the only style. Half-and-half is the worst option. |
| No `+=`, no `if`-expression, `return` required, `match` as the only expression-level branch | Coherent "mostly statements" story, but `let v = match c { true => a, false => b }` as the ternary idiom is clumsy. `if` as an expression and compound assignment are the two most asked-for post-1.0 items and cost little. |
| Newline ends a statement with **no** continuation after an operator or inside parentheses | Stricter than Swift, Go, Python and Rust; long conditions can't be split. Allowing continuation after a trailing binary operator and inside unclosed brackets is cheap and removes a daily annoyance. |
| Trailing commas: allowed in literals and bodies, not in calls or parameter lists, yes in method parameter lists (B22) | Inconsistent; pick one rule. |
| `E.Variant` to construct, bare or `.Variant` in patterns, bare `Some`/`None`/`Ok`/`Err` everywhere | Three spellings for one concept. Acceptable, but the prelude exception should be documented as the only one. |
| Generic bounds unlock operators but not trait methods (`x.show()` on `T: Show` fails) | A half-feature that contradicts the word "bound". Either finish it or rename it in the docs ("operator bounds"). |
| No `if let` / `while let`, no string slicing or `<` on strings, no unit type, `?` without error conversion | Deliberate minimalism and honestly documented; the first two will top the FAQ. |
| Closures can't mutate captures (D93) | Right call; the diagnostic with its help line is good. |
| `become` with eight rules that leak the calling convention (function values borrow parameters, etc.) | The most "designed" feature; the rules are correct but a user shouldn't need to know who owns what. Consider stating the rules in terms of "what can be passed without the caller's frame" only. |
| `#test(args)[expected]` | Genuinely nice. The `[…]` bracket is idiosyncratic but fine. |
| Map iteration order undefined (B21) | Define insertion order in both backends; it costs an order vector natively and makes `#test` on maps possible. |
| Actors reentrant with a syntactic warning (D95) | Pragmatic, and already ahead of Swift (which has no warning), but the warning is bypassable through `self` methods (B12). A non-reentrant method kind ("no await inside", Kotlin-style) is what most invariants actually want. |
| Deep copy at every task/actor crossing (D89 (4)) | Simple and keeps counts non-atomic, but invisible and O(n): passing a 100k-element list to a sync actor method costs ~1.45 ms per call, and the *same program* without an `async let` runs 200× faster because frames mode is off. Needs a doc paragraph now and a move optimisation later. |
| Fail-fast with nothing catchable, no `defer`, no cleanup hook; cooperative `task.cancel` beside it | Two cancellation mechanisms coexist. Programs that own external state have no hook. The docs should at least say "make children return `Result`". |
| Only suspension points: child tasks and actor calls; no sleep/yield/timers/async I/O/async trait methods | Today's concurrency is CPU parallelism plus actor serialisation. Correct first slice, but it should be named as such on the page, and a `sleep`/`yield` builtin is the smallest missing piece (the stress programs busy-wait on an actor). |

## 6. The toolchains

### Python toolchain (stage 0 and oracle)

- Architecture is clean: one checked AST, two consumers, sugar removed early, checker annotations recorded on nodes. Almost no dead code, no module-level state, no TODOs.
- **Smell:** every builtin is dispatched by name in three separate switch statements (`_infer_call` 311 lines, `_gen_call`, `_eval_call`) plus `_BUILTIN_FUNCS`; adding `__getcwd` touched four Python files and the self-hosted compiler. A builtin table before the LLVM backend would pay for itself.
- **Smell:** checker annotations are untyped dynamic attributes read with `getattr(node, "x", None)` (about 90 sites). Missing an attribute silently becomes `None`, which is how B2 stayed hidden.
- The monomorphizer's second `check()` reports its own failures as user type errors pointing at correct lines (B2's second repro).
- The hand-written assembly runtime is ~2,300 of codegen's 6,500 lines as `e("\t…")` calls; `.s` template files would be easier to read and diff.
- `__version__` is `0.0.1` while Home says v1.0; 39 "v0.x" historical comments remain in `types.py`; the impl-target and derive messages still cite "v0.4.1"/"v0.4.4".
- Performance as an oracle: every argument is deep-copied, so 2,000 calls passing a 20k-element list take 7.8 s. Fine for an oracle, worth noting on the Interpreter page.
- Test suite: behavioural, fast (621 in 5 s), one tautological assertion (`assertIsNotNone`), `test_literal_too_large` uses 999 for uint8 so it can't catch B6. Unit gaps: shifts, map order, `become`, casts to `char`.

### Self-hosted compiler and interpreter

- `codegen.my` (8,007 lines) is not a leftover emission path: ~4,100 lines are the hand-written runtime as string literals (prelude, heap, I/O, `run`, maps, builders, the whole executor, deep copies), ~500 DWARF, ~600 AST analyses, ~470 shared instruction sequences. It is misnamed, not duplicated. Splitting it into `runtime.my`, `layout.my`, `dbg.my`, `census.my` would make it navigable.
- Note: `scripts/gen_selfhost_runtime.py` generates only the float and `__char_to_str` routines; the concurrency runtime is hand-written Myla string literals, not generated.
- Bring-up residue that MYLA-34 claims is gone: stale section headers (`-- maps / strings / chars (filled in later C4 sub-slices)`, `-- the executor (D90, D91: one thread)` while it is multi-threaded), a duplicated comment block in `lower.my:1446-1449`, dead `is_cell` (`lower.my`), `all_reports` (`diag.my`), `load_program_with` (`loader.my`).
- Frame layout constants live in three places that must agree (`FRAME_*` in `lower.my`, `FRAME_HEADER` in `ir_x86.my`, literal offsets like `48(%rdi)` throughout `emit_executor`); the async `__new` convention is detected by comparing the last five characters of a name.
- Magic numbers in assembly without names: futex 202, clone flags 855808, mmap flags 147490.
- Per-slot frame cells with no overlap between disjoint scopes or match arms make `Interp.eval` a 2.5 KB frame and `eval_name_call` 3.7 KB: this is both B3 and the memory-traffic bound MYLA-133 stopped at. Liveness-based slot sharing is the single most valuable self-hosted optimisation left.
- `#test` coverage: 1164 of 1259 value-returning functions have none **[verified]**; the convention is enforced only for `examples/`. The tests that exist are meaningful.
- Documentation numbers are stale: four line counts in `Self-hosted-compiler.md`, three contradictory self-compile times (0.8 s / 2.1 s / 2.9 s), "4.4 MB of assembly" vs "8.0 MB" vs the actual 6.1 MB.
- Both interpreters are O(n²) on `var a = acc; push(a, n)` recursions where native is O(n); the self-hosted interpreter copies the container on each update.

### The IR

Clean 3AC on blocks with explicit retain/drop/cow/moved, printable, verified in production, stable per D85 with the extensions (`become`, `suspend`, `deep`, `clone`) each added with text form, verifier rule and backend. Weak spots: stringly-typed runtime calls (`Rt(d, "__str_concat", …)`, `Call(-1, "__wait", …)`), the verifier is weaker than documented (B20) and tracks slot state but not count balance.

## 7. Concurrency (the recent big change)

Verdict: a solid foundation with an unusually robust runtime and honest documentation, **not yet something to promise isolation on** (B1, B5, B12). Both isolation fixes are checker-level and a day's work each.

- Runtime: no crash, hang or variance beyond output order in ~400 runs across 1–16 workers *within the rules*; 120k tiny tasks, 40k async actor calls from 8 tasks, 2M cross-worker frees, actors created in children and dropped elsewhere: all correct with constant RSS. Reviewers could not construct a lost wakeup.
- Parity: all 16 stress programs and `examples/concurrency.my` identical on the Python interpreter, the self-hosted interpreter and native at 1/4/16 workers. The evidence numbers in MYLA-137/140/144 reproduce.
- Scheduler policy: FIFO on one worker (to match the self-hosted interpreter) means breadth-first expansion: `task.all` over 1.1M functions takes 20.7 s and 3.3 GB at T=1 vs 1.7 s / 631 MB at T=4. Parity of order is bought with an asymptotic memory difference; depth-first everywhere plus a "deterministic order" test knob would be saner. Tiny tasks are 10× slower on 4 workers than on 1 (ring under a spin lock, no Chase-Lev).
- Stress-test plan: good and honestly mapped (11 of 12 N/A or covered), but none of its programs exercises the four places where problems were found (actor state from a child task, awaited struct methods on actor fields, failure beside a CPU-bound sibling, lines over PIPE_BUF). Each should become a `t0x_` program, the first two as error-corpus cases once rejected. The plan's "controlled schedules / record the seed" item is not done.
- Minor parity drift: `==` on actor handles gives different messages from the two checkers.

## 8. Standard library and tooling

- **Stdlib coherence** is good where it exists (Option for parses, `Result<_, IoError>` for I/O, errno kept). Oddities: `write_to_file`, `make_dir`, `remove_*`, `rename` return `Result<int32, …>` with the int always 0 (wants a unit type); `write`/`println`/`eprintln` return nothing, so EPIPE is invisible; `std.task.cancel(child: int)` is a fake signature the compiler intercepts and hover shows it; `std.process.run` has no PATH search, cwd, env or stdin (the project tool works around PATH with `/usr/bin/env git`); no format width/precision (`1.0/3.0` prints `0.33333333333333331`).
- **Duplicated helpers across the repo**: `is_digit` ×2, `trim`/`trim_end` ×5, `starts_with`/`ends_with` ×4, merge sort ×6, `slice` ×4, `join_*` ×7. A `std.str`, `std.sort`, `std.char` would delete ~25 functions.
- **Builtins boundary**: 16 user builtins + 22 `__` primitives, identical in both checkers (good), but the primitives are callable from user code (B13) and `get(m, k)` being "a prelude function, not a builtin" is an invisible exception.
- **Language server**: fast and feature-complete per its page; crashes on deep nesting (B4); bare completion at a statement start dumps 1,554 workspace items in 855 ms; single-threaded so a slow check blocks requests; no pathological-input tests.
- **Project tool**: everything documented works; `clean` bug (B17); `--help` (B18); `myla.lock` stores unnormalised URLs; no `new --lib`.
- **VS Code extension**: clean; output capture via polled files means stdout appears late and interactive stdin is impossible; no snippets for `actor`, `async fun`, `async let`, `#main`.
- **Repo hygiene**: `timer.py` at the root is an unrelated personal stopwatch (delete); `scripts/run.sh`/`samples.sh` duplicate justfile recipes and go through `build/stage3`; justfile `bs` needs `uv` in a "no dependencies" project; `.vscode/settings.json` is only comments; 1.3 MB generated `parser.c` plus six language bindings committed for a grammar nobody consumes yet (defensible for tree-sitter, but it dominates PR diffs: PR #21 was 95 % `parser.c`).
- **CI**: sound structure, but (a) the burn job installs no gdb so every debugger test always skips (MYLA-156, `todo`); (b) PR burn tests run the language server and CLI built by the *Python* backend; only the bootstrap job runs the real `build/myla`, on `hello.my` alone; (c) no caching of `build/test-tools` or the tree-sitter npm install; (d) the burn job is ~6.5 min here while docs say 30 s, 65 s, 42 s and 400 s in four places.
