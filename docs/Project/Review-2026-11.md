## 1. Executive summary

1. **The week's headline work holds.** The seed bootstrap is reproducible and auditable, the runtime in Myla is shared by three targets, the aarch64 and wasm32 backends match the interpreter on every suite, every example and every adversarial program the reviewers wrote, the IR has a written contract, and the sixteen language features are built carefully and agree across all four runners. The reflection page's own critique of the IR boundary is accurate and the plan it sets is the right one.
2. **Three high-severity bugs, all verified**: (a) `task.timeout` races its own deadline: when the child finishes before the deadline is armed, a stale timer later writes into freed memory, giving a spurious `None`, a cancelled unrelated task, or a segfault (3 of 12 runs crashed under load on 16 workers); (b) on x86-64 a function-value parameter is read from `%rdi` after the call's own argument loads overwrote it when the function also contains a tail call, so the binary segfaults where aarch64 and the interpreter print 72; (c) a program's `impl [T] { fun len }` or `impl str { fun len }` is picked up by the standard library's own calls in native code but not in the interpreter, so `xs[1:]` and a format spec crash natively.
3. **The oracle has quietly eroded.** With the Python toolchain retired, the recorded answers cover only the examples and the error corpus: all 57 toolchain files are skipped by the lexer, parser and CLI gates (183 skips), 20 new error-corpus files are checked against the self-hosted CLI's own output, and 15 of the 17 MB of recordings can never be consulted again. The suite is still a real semantic check because 49 of 69 modules compare the interpreter with native code or use hard expectations, but the docs and README overstate what the recordings do.
4. **The seeds are eating the repository.** 153 x86-64 and 44 aarch64 seed versions in six days account for 110 of the 117 MB pack, against 3.5 MB in October; the docs assume one seed per pull request, the history shows one per commit (60 percent of commits). At this rate a year is several gigabytes.
5. **Raw memory is one warning away from user code.** `__load64(0)`, `__free`, `__store64` and `__addr_of` are callable from a program with a warning (D100), and natively that is a bare segfault with no runtime error. D100 was written for I/O primitives; the raw-memory ones need to be errors outside the standard library.
6. **Documented claims that are no longer true**: `#test` coverage of `selfhost/` is 70 percent, not 80 (the harvester left with Python, the denominator grew by 343 functions); the Targets page promises 4 GiB on wasm32 but a list stops at 2^26 elements; the Decisions header says "to D143" while D147 exists; "D1–D138" on two pages; the fast suite "about 20 s" is 50 s; the burn suite "870 tests, 120 s" is 1035 and 313 s.
7. **Decision churn continues**: 50 decisions in six days, two superseded the day they were made (D138→D140, D135→D141), seven rows unmarked by D134's own rule, three owner decisions (MYLA-205, 208, 214) with no D-number anywhere findable, and the process decision MYLA-214 implemented in prose only (the `design`/`test` task types, epic parents, one evidence heading, PRs per theme: none applied).
8. **The board**: 83 in review, 0 signed off by the owner since 1 November (the 23 flips since were agent commits "with the owner's agreement"). This report judges all 83: 72 ready, 11 need a change first (§6).
9. **Small but telling hygiene**: an empty file literally named `{` is committed at the repository root; `seed-aarch64.s` and `embedded_std.my` lack the `-diff` attribute, so pull requests show 20 MB diffs; a 400-word single sentence describes `std.rt` on the user-facing Standard-library page.
10. **What's genuinely impressive this round**: the integer and float edge-case parity across four runners; `std.math` within 1 ulp of glibc on 342 values; fail-fast beside sleepers in 31 ms; a stress suite that runs 20× on arm64 hardware in CI; MYLA-275's write-up of a wrong first hypothesis corrected by instrumentation; and `defer`, defaults, format specs and slices behaving exactly as their decisions say in every corner the reviewers poked.

## 2. What is genuinely good

- **Differential testing across targets works as a method.** The aarch64 runs found a cancel race that also existed on x86-64; the wasm runs found a Node WASI crash and the NaN-bits divergence; this review's qemu and Node runs agree with the interpreter on 96 example comparisons and every probe. The Targets page's guarantees (MIN/−1, shift masking, saturating casts, canonical NaNs, float `%`, stack overflow reported as a runtime error, exit codes, broken pipes) were each verified on all three targets.
- **The seed scheme is sound end to end.** Two bootstraps are byte-identical; each seed's header SHA-256 matches its body; the previous seed compiling the next commit's sources reproduces that commit's seed byte for byte; the emulated aarch64 bootstrap reaches `seed-aarch64.s` exactly, and the aarch64 compiler writes `seed.s` exactly. The pre-push hook and `check-seed.sh` do what they say.
- **The runtime in Myla is small and readable** (2,608 lines, 25 sections), with the machine-specific remainder per target at 500 to 800 lines; `runtime_x86.my` holds only `_start`, the signal handler, the syscall stubs, `__copy_bytes` and the executor entry points.
- **The IR contract is real**: every intrinsic has written semantics (`ir.my:359-424`), the verifier checks arity and result presence, and the IR page writes down wrapping, division, shifts, float `%`, casts and memory ordering once.
- **The optimisation pass is conservative in the right places.** `hoist_cows` disqualifies a loop on any call, store, append, pop, retain or copy; bounds-check elision requires the builtin `len`, refuses parts of `var`s and an async actor's `self`, and descends into `defer`, lambdas and match arms. Sixty adversarial programs (lists mutated inside the loop through every construct, 8- and 16-bit counters, `^` indexes, `MIN / -1`, loops at `INT32_MAX`) agree with the interpreter, traps included.
- **The reactor is idle when idle** (0 CPU over a 2 s sleep on 1 and 4 workers), accurate (100 × `sleep(10)` = 1021 ms), cancels through sleeps, joins children before deferred blocks, and ends the program 31 ms after a panic beside 10 s sleepers.
- **The language features are Swift's where they should be**: `defer` computes the return value first and runs per iteration; D144's by-address receivers survive `?`, `become` and panics; defaults evaluate in the callee's module scope; format specs round on the binary value and count Unicode scalars; slices clamp. The diagnostics for misuse are precise (I tried twelve wrong programs: every message names the rule and the fix).
- **The standard-library round delivered its decisions**: portable error causes map every case the way Rust would; `Command` has PATH, cwd, env and stdin and survives 2 MB of stdin; `std.math` is a faithful fdlibm port with a Payne–Hanek reduction; `std.time` is monotonic.
- **CI is sound and fast** (whole run 3.5 min): content-keyed tool cache, `MYLA_REQUIRE_TARGETS` really fails on missing tools, an arm64 runner bootstraps from its own seed and runs the stress programs 20×.
- **Process writing is honest**: the reflection page names what did not hold, MYLA-275 records a wrong hypothesis, Known-issues keeps lines until `done` as the last review asked.

## 4. The big picture: concepts, philosophy, direction

**What changed in kind.** A month ago Myla was a language with a Python reference implementation and one native target. Today it is a self-certifying toolchain: the compiler's own assembly is the root of trust, the runtime is Myla, and the same IR feeds three backends. That is a real architectural achievement, and the reflection page's honesty about where the boundary leaked (glue written three times, runtime calls by name, GAS text as the interface, Linux shapes in the platform layer) is the best piece of writing in the repository.

**The cost of retiring the oracle was underestimated.** D101 moved correctness from "the interpreter agrees with an independent implementation" to "the interpreter agrees with the native code, and both agree with what the Python toolchain once said about files that no longer exist". The recordings decayed to the examples and corpus within five days. The project's tests are still strong, but for a different reason than the docs give: the interpreter is now the oracle, the other targets are the independent check, and the hard expectations in the corpus directives carry the diagnostics. Say so, and convert the remaining recorded facts into expectation files (full rendered diagnostics for the corpus, token/AST files for the examples), then delete the stores.

**Speed of decisions versus their weight.** Fifty decisions in six days, several reversed within a day, three more living only in task files. The decision log is a changelog now (every row names a task and a date), not a reference; the last review said the same at 12.8k words, it is 19.9k now. A provisional state and the heading-per-decision format are both decided in principle (MYLA-205 "on hold until Genbeya has a mechanism", MYLA-193 waiting on it); the hold is the problem. Either do the format now or accept that the "why" of the language is effectively write-only.

**"Done" and "review".** The last review asked for one meaning of done. Conventions now say only the owner moves tasks to done; in practice the agent moved 23 with "the owner's agreement" in commit messages, and 83 wait with no owner sign-off since 1 November. The board is honest about this, but the pile-up means the review state has again stopped carrying information. This report's verdicts (§6) are meant as the bulk instrument.

**Safety posture.** Three findings are the same shape: a thing that is unsafe is allowed with a warning or a comment. Raw-memory primitives from user code (R4), builtin method names overridable program-wide (R3), negative slice bounds silently meaning "before the start" (R23). Myla's philosophy since the October review has been "safety from the checker where it is cheap". Each of these is cheap to close.

**Scope.** The roadmap after the reflection is disciplined: specify, consolidate, verify before a fifth target. The language work (sixteen features in a week) is complete and well tested but has no examples, no tutorial and no doc blocks of its own; D114's tutorial was gated on the ergonomics round, which is done. The standard-library round is half-landed (no `std.str`, `std.char`, `std.sort`, no integer `min`/`max`/`abs`); the duplicated helpers the last review counted are still there.

## 5. Area notes

### 5.1 Language (the sixteen features, D102–D104, D116, D135–D144)
Everything agrees on all four runners; the design is coherent; the bugs are at the seams between features (R3, R10–R14, R20–R24). Spec gaps worth fixing with them: Lexical-structure.md:140 still says there are no format specifiers; Functions-and-closures.md:24 says calls give exactly the declared arguments five lines above "Default values"; Statements.md:32 says `self` can't be reassigned (false after D144); D136's "doesn't refer to other parameters" also excludes `self`, unstated; `as` doesn't continue a line although listed as a binary level; the corpus has no file for any format-spec, slice, unit or `defer`-with-`await` error; `type_var_self_on_builtin.my` now tests the async case its name denies. **No example in `examples/` uses any of the sixteen features**, and the Getting-started reading order ends at `concurrency.my`. Design notes for the owner: `pop()` returning `T` and failing on empty makes `while let Some(x) = stack.pop()` a type error, so `while let` has no library partner; named arguments will come back once trailing-only defaults meet "skip the middle one"; `print(x)` refuses a `Format` type while `print(f"{x}")` takes it.

### 5.2 Runtime and the x86-64 optimisation pass (MYLA-162, 246–253, 263, 264)
Sound under everything thrown at it except R2. Benchmarks reproduce: geometric mean 1.95× C's time over twelve programs (stored 2.12×), instruction counts equal to MYLA-251's to the digit; self-compile 1.41 s and 176 MB peak here (IR.md says 0.8 s and 92 MB; Benchmarks.md 0.72 s). `rt.my` has 8 `#test` cases for 136 functions; `ownership.my` none. The Native-backend "Runtime helpers" table still lists seventeen assembly symbols that no longer exist. Frame-word offsets (`+24`, `+32`, `+48`, `+64`) are raw numbers repeated across `rt.my`, `lower.my` and three backends (MYLA-185).

### 5.3 Backends and targets (MYLA-158, 163, 261, 266, 268, 276, 281–283)
Parity on every probe. The seed scheme closes the loop both ways, but an x86-64-only contributor's `check-seed.sh` cannot see an aarch64 miscompile of the compiler: only CI's `targets` and `bootstrap-arm64` jobs can, and Bootstrap.md reads as if the local check suffices. The `targets` CI job would print "16 of 16 suites passed" if binutils were missing (every suite skips). The browser page is tested only where Playwright happens to be installed (not in CI). `wasmtime` is claimed as a host and tested nowhere. Panics in the backends are all internal-error paths; the wasm text re-parser (~280 lines) and the `__syscall` import chain are the two places MYLA-269 and a `br_table` would clean up.

### 5.4 Concurrency and the reactor (MYLA-228–231, 267, 275, 144, 169, 171, 172)
All first-round findings are fixed and hold under 30-run campaigns with and without load, including isolation shapes now rejected by the checker and a failure reported in 31 ms beside sleepers. The memory-ordering placement is right on paper except R17. The reactor's two holes (R1, R5) are both in arming and watching bookkeeping, not in the poll loop. Docs: the suspension-point list omits the async reads; nothing says one waiter per descriptor; the one-worker sleep latency (a `sleep(5)` beside a 300 ms computing sibling wakes after 299 ms) is documented only in a comment in `task.my`.

### 5.5 Bootstrap, tests, CI (MYLA-218, 219, 235, 243, 184, 240, 216)
See §1 points 3 and 4 and R15–R16, R27–R28. Additional: the burn suite cannot run on aarch64 hardware (`CAN_BUILD_NATIVE` requires x86-64 and `_assemble` hard-codes `as --64`), so `bootstrap-arm64` runs only examples and stress programs and the page doesn't say so; the seed header names the parent commit, so regenerating "at its commit" means finding the child; `backup/python-toolchain-final`, the independent root of the whole trust chain, is a branch, not a tag, and its seed's hash is recorded nowhere; `MYLA_STDLIB` pointing at a missing directory yields only "cannot resolve import 'std.json'".

### 5.6 Standard library, docs, decisions, board (MYLA-177, 179, 186, 190, 200, 201–217, 248, 258, 273, 278)
Stdlib correctness is good (R7–R9 aside); D113 half-landed; float printing still 17 digits (`print(0.1)` → `0.10000000000000001`, `1e300` → 301 digits) now that specs exist to make the shortest form the default. Docs: the rules are accurate and 66 doc blocks pass the burn test; the status text has rotted again in the same places as last time (D-ranges, headers, timings, stdlib lists, the skill's "x86-64 Linux binaries"). Last round's seven wrong `#L` links were removed rather than fixed. Board: 7 tasks with undefined types (four created after MYLA-214 said to stop), epic parents still in `Roadmap ideas/`, 24 evidence-heading variants, 23 done tasks with unticked items, overlaps (189/277, 195/244, 194/214, 193/205, 230/258), Known-issues missing MYLA-275/281/282 and listing a done one. PRs #24–#38 come from three long-lived branches; #38 is 448k lines, 4k without generated files.
