# Decisions

The locked design decisions, newest first. They were made while the language was designed (June 2026) and are the "why" behind the rules on the [[Language]] pages. A decision is settled: changing one means adding a new numbered decision that supersedes it, not editing the old row.

Links in the table point at the design documents in [[Archive]], where each decision is discussed in detail.

## Adding a decision

Add a row at the top with the next number (D62, …), today's date, the decision and the reason, and update the affected [[Language]] or [[Architecture]] pages. Decisions that tasks need are referenced from the task (for example [[MYLA-6]] asks for one on float-to-integer casts).

| D70 | 2026-10-27 | The language server tells a value's type from the source, without the checker: annotations, literals, function and method results (type parameters bound by matching parameter types against argument types), fields (type arguments substituted), elements, tuple parts, `?`, operators, `self`. Types are kept as written text (`[P]`, `Option<P>`); unknown is empty and falls back to the lookup by name. Completion resolves a patched text (a placeholder at the cursor, or the line cut to the receiver chain) ([[MYLA-80]], [[MYLA-51]]) | Completion happens on text that doesn't type-check or parse; a syntactic guess covers the receivers people write (78 of 79 member accesses in the examples, all agreeing with the checker) at a fraction of a check's cost |
| D69 | 2026-10-27 | The language server written in Myla resolves names by scope from its own walk over the parsed document, keyed by identifier token positions, rather than through the checker: locals, parameters, type parameters, match and lambda bindings, the file's declarations, imports found by the loader's rules, variants and fields named through their type. Members reached through a value stay unresolved until the server has types, and fall back to the lookup by name; references to a global are its name's occurrences less those that resolve elsewhere and other files' locals ([[MYLA-80]], [[MYLA-51]]) | The checker stops at the first error and records types, not which declaration each use means; a walk works on any document that parses, type errors and all, and is fast enough per request (cached per text). The differences from the Python server's answers are the point of [[MYLA-51]] |
| D68 | 2026-10-27 | The language server's semantic tokens come from the compiler's lexer, not a separate highlighter: token kinds give keywords, types, numbers, strings and operators; comments are found between tokens; identifiers are classified from the outline and their neighbours (no scopes yet). Legend: the standard LSP token types namespace…decorator and the modifiers declaration, readonly ([[MYLA-80]]) | One definition of the lexical syntax for the compiler and the editor, so highlighting can't drift from what compiles (the task's goal); scope-based classification comes with the checker-based lookups of [[MYLA-51]] |
| D67 | 2026-10-27 | The language server written in Myla syncs documents in full and debounces without threads: a primitive `__poll(fd, timeout_ms)` (one `poll(2)`) behind `Reader.ready` lets the loop wait 0.4 s for more input after a change; opening and saving check at once. A check runs the self-hosted loader with every open document's text as an override ([[MYLA-80]]) | No threads in Myla; full sync needs no range arithmetic and is fast enough for source files; the checker is fast enough to run per change (0.5 ms for a small file, 230 ms for the largest compiler module) |
| D66 | 2026-10-27 | `std.json` follows Python's `json`: `Json` has `Int` and `Float` numbers, objects are ordered member lists (duplicates kept), errors carry Python 3.13's messages and positions, and `to_string` writes Python's compact form with shortest floats. Number conversion moves from the self-hosted compiler to `std.num`, which both use ([[MYLA-79]]) | One reference to test against byte for byte (values, text and errors); member lists keep order, which maps don't define; one exact float conversion instead of two |
| D65 | 2026-10-27 | Part of a string is taken with `append(sb, s, start, end)`, which appends the bytes `s[start..end]` to a builder; out-of-range bounds are a runtime error like an index. No slicing syntax and no new builtin name ([[MYLA-85]]) | Interpreted code otherwise copies byte by byte (31 s per MB of lines in the Python interpreter); a new name like `slice` would reserve it and break existing declarations; the builder already normalises split UTF-8 in the interpreter |
| D64 | 2026-10-27 | Reading is one primitive, `__read(fd, n)` (one `read(2)`, `""` at the end, errno through `__io_errno`), and a buffered `std.io.Reader` written in Myla on top of it (`read_line`, `read_exact`, `read_to_end`); output stays unbuffered, and the interpreter flushes before it reads ([[MYLA-78]]) | One small primitive per implementation, the rest shared Myla code; a struct holds the buffer because Myla has no globals; unbuffered output keeps request/response protocols (the language server) from deadlocking |
| D63 | 2026-10-27 | The syntax has one machine-readable description, `grammar/myla.ebnf`; the tree-sitter grammar and its highlight keywords are generated from it by a Myla tool, and tests tie it to the compiler (its terminals lex as the self-hosted lexer's tokens, the self-hosted parser accepts programs sampled from it, tree-sitter parses the whole corpus). The parsers stay hand-written ([[MYLA-77]]) | The parsers' error messages need hand-written code, so the grammar can't be derived from them; a hand-written editor grammar drifted (it still followed the Rust dialect) |
| D62 | 2026-10-27 | **`str` is reference-counted** in native code, like lists and maps: strings built at run time (`+`, `format`, f-strings, `build`, rendering, I/O) are freed when the last owner drops them; a map holds a reference to each `str` key. Literals are cells in the binary whose count never reaches zero, so retain and drop need no branch. Supersedes the "arena-resident, never freed" note on `str` from D41's era. ([[MYLA-18]]) | A long-running program that builds strings, such as a language server, otherwise exhausts the 1 GiB arena; the compiler itself needed 2.6× the memory |
| D61 | 2026-10-26 | **Optional semicolons**: a `;` may stand for the line break that ends a statement or a declaration: between the statements of a block, between top-level declarations, between the methods of an `impl` or a trait, and after a bare `return`. A run of `;` and line breaks is one separator, so a trailing `;` is harmless. Everywhere else (`f(a; b)`, `[1; 2]`, struct fields, match arms) it is an error. (refines D1; MYLA-76) | Short declarations and bodies read better on one line (`fun abs(x: int) -> int { if x < 0 { return -x }; return x }`); line breaks stay the normal style. A separate token, not a newline, so it can't slip into the places where line breaks are skipped |
| D60 | 2026-10-26 | **A partial application evaluates its parts once, when it is made**: in `f(a, _)`, `recv.m(a, _)` and `fv(a, _)`, the receiver and the filled arguments are evaluated left to right when the partial is created, and each call of the partial reuses those values; a variable contributes its value at that moment. (refines D51; MYLA-75) | What D51's "captured by value" says, and what the self-hosted interpreter and code generator already did; the Python toolchain re-evaluated the arguments at every call (or never, for an unused partial) |
| D59 | 2026-10-26 | **Float → integer casts saturate**: `x as T` truncates toward zero and clamps to the range of `T`; NaN gives `0`, `+inf`/`-inf` give the maximum/minimum. Applies to every integer width, `uint64` included (values from 2^63 up are exact). (MYLA-6) | The same rule as Rust; total (no trap, no undefined value), so the interpreter, const folding and native code can agree. Wrapping a truncated float has no hardware equivalent above 2^63, and `cvttsd2si` alone yields 2^63 for anything out of range |
| D58 | 2026-06-28 | **String interpolation `f"…{expr}…"` (sugar over `format`)**: an `f"…"` prefix; arbitrary expressions inside `{ }`; `{{`/`}}` are literal braces; **no** format specs in v0.5 (parity with `format`); single-line only. Lowers at parse time to `format(fmt, args…)` (lexer balanced-brace split, each slice re-parsed as an expression). | Opt-in prefix keeps plain strings / existing `format` calls untouched; zero new runtime, reuses the `format` checks + both backends; the lexer scan is the only real cost so it lands last. [v0.5-modules-and-runtime.md](../Archive/v0.5-modules-and-runtime.md) §7 |
| D57 | 2026-06-28 | **Package/module resolution corner cases**: files=modules, dirs=packages; an optional `foo/foo.my` package-root module defines a package's public surface via `pub import` (no implicit glob re-export); a file/dir name clash in one parent → compile error; the **project root = the entry-file's directory** (no manifest yet); reserved roots (`std`, prelude) are **shadow-protected** (a project dir shadowing one is an error); `from a.b import c` resolves **module-before-item**; import cycles are allowed (only `const`-init cycles error, D28). | Pins the filesystem↔namespace mapping left open by D17/D22 with the simplest unambiguous rules; reuses D54 re-exports for package surfaces instead of inventing `__init__` semantics. [v0.5-modules-and-runtime.md](../Archive/v0.5-modules-and-runtime.md) §1.4 |
| D56 | 2026-06-28 | **Floats pulled into v0.5 scope**: implement `float32`/`float64` (+ the `float` alias and `f32`/`f64` literal suffixes) as designed in D19, in v0.5 alongside modules & runtime. (schedules D19/D20) | The self-hosted compiler/stdlib and numeric code benefit; v0.5 is the natural home now that the integer/abstraction tiers are complete |
| D55 | 2026-06-28 | **Generic traits (restricted) scheduled for v0.5**: a `trait` may take type parameters (`trait Comparable<T>`) but is implementable **at most once per type** — no multiple `impl`s of the same trait for one type with different arguments, hence **no overload resolution**. Needs trait-parameter substitution in conformance + `(trait, type)` method-table keying, but no new dispatch model. Full multi-impl / argument-overloaded generic traits, trait objects, and user-defined bounds remain deferred. (refines D53) | Adds the generic traits the self-hosted compiler wants without importing argument overloading, which conflicts with name-only method dispatch (D46) |
| D54 | 2026-06-28 | **Re-exports via a `pub`-prefixed import**: `pub` is a uniform prefix modifier on an import statement, marking the name(s) it binds as part of the module's public surface (`pub import a.b.c as c`, `pub from .x import foo`). A `pub import` **requires `as <ident>`** (the export must be a simple identifier — no auto-binding the last path segment, per D22); `from … import name` already binds a simple name. No separate `use` keyword. Re-exports obey the existing collision rules (D22). (resolves the open `pub use` question) | Reuses the existing `pub` visibility modifier as one orthogonal "make this binding public" prefix; avoids a `use` keyword Myla lacks and the last-segment footgun D22 rejected |
| D53 | 2026-06-28 | **Generic trait bounds (limited)**: a type parameter may carry built-in-trait bounds `T: Trait` (`+`-combined); operators/methods named by the bound are usable on `T`, checked at the **call site** during monomorphization (no dynamic dispatch). User-defined trait bounds + trait objects deferred to v0.5. (X9) | Enough for generic numeric/`Eq` code in the self-hosted compiler without a full bounds system |
| D52 | 2026-06-28 | **Operator overloading via a fixed built-in trait set** (`Add/Sub/Mul/Div/Rem/Eq/Ord`): `a OP b` desugars **uniformly** to the trait method, resolving to a user `impl` or the type's built-in implicit default (primitives ship defaults; zero runtime cost when unoverridden). `#derive(Eq)` synthesizes structural equality (allow-list = `Eq` first, then `Ord`); lifts the D37 primitives-only restriction for implementing types. (X8) | Ergonomic operators + structural equality without committing to a broad trait system |
| D51 | 2026-06-28 | **Partial application** `f(…, _, …)`: `_` holes in call-argument position desugar to a lambda over the holes (left-to-right), filled/receiver args captured by value; works on method calls too. **No implicit auto-currying** (a missing non-`_` arg is still an arity error). (X7) | Explicit and loud; keeps arity mistakes from silently becoming partial applications |
| D50 | 2026-06-28 | **`\|>` pipeline + `>>` composition**: `\|>` is a new lowest-precedence, left-associative operator splicing the left value as the **first** argument; `>>` composes when both operands are function-typed, else right-shifts (operand-typed, D24). (X6) | Unambiguous functional plumbing that reuses the existing `>>` token |
| D49 | 2026-06-28 | **Function-value representation**: a 16-byte `(code_ptr, env_ptr)` fat value; `env_ptr` → a refcounted heap cell of captures; non-capturing lambdas & plain `fun`s use `env_ptr = 0`; one calling convention `code_ptr(env_ptr, args…)`. Forward-compatible with `ref` capture (D15) as an additive change (box `ref`-captured locals, store box pointers in the env). (X5) | The OCaml/Rust closure representation; lets `ref` land later without redesign |
| D48 | 2026-06-28 | **Closures capture by value** (snapshot copy at creation, retaining heap captures into the env; mutation affects only the copy). By-reference `ref` capture deferred. (X4, refines D15) | Simple codegen now; clear additive path to `ref` |
| D47 | 2026-06-28 | **Method receivers**: `self` is read-only by value; `var self` mutates and **requires a mutable lvalue receiver** (same rule as `push`/`m[k]=v`, D40) — no mutating calls on temporaries or `let` bindings. (X3, refines D27) | Consistent with the binding-mutability + lvalue rules already in the language |
| D46 | 2026-06-28 | **No UFCS**: methods live in a **per-type namespace**; `recv.method(args)` is the only surface call form (`T::method` is internal lowering). Complementary to the functional operators (method chaining ↔ `\|>`; `_` works on method calls; wrap a method in a lambda to compose). A method-reference value / UFCS may be added later as a non-breaking extension. (X2) | Avoids polluting the value namespace / colliding with builtins (`len`/`push`); the restrictive choice is reversible |
| D45 | 2026-06-28 | **No orphan rule / no origin restriction on `impl`**: any trait (user or built-in) is implementable for any type (user or built-in) — user-on-builtin, builtin-on-user, and builtin-on-builtin all allowed; inherent + trait `impl` allowed on any named type incl. builtins; method names unique per type and distinct from fields; at most one *user* impl per `(Trait, T)`, which **overrides** any built-in implicit default; whole-program coherence. (X1) | Myla is inspired by Rust, not a copy — "simplicity over safety": free mix-and-match, the author takes responsibility |
| D44 | 2026-06-27 | Out-of-range shift amounts: a **constant** amount `>= width` is a compile error; a **runtime** amount is **masked to the operand width** (`n & (width-1)`) rather than trapping (refines the v0.3 "runtime trap" sketch). `<<`/`>>` are parsed as two column-adjacent `<`/`>` tokens, not lexed as single tokens, so nested generic closers (`Option<List<int>>`) keep working. | Masking keeps the interpreter and native backend trivially in parity and matches the hardware shift instructions; the common (constant) mistake is still caught at compile time |
| D43 | 2026-06-27 | Add `0x`/`0b`/`0o` integer literals (with `_` separators + type suffixes) in v0.3. (W6) | Bitmasks and byte/char tables read far better in hex; pairs with the new bitwise ops |
| D42 | 2026-06-27 | v0.3 strings are **byte-oriented**: `s[i] -> uint8`, char literals `'a'`/`'\n'` are their byte code (ASCII only); the dedicated Unicode **`char`** type stays in v0.5. (W5) | What a byte-level lexer needs; keeps Unicode complexity out of v0.3 |
| D41 | 2026-06-27 | `str` `+` concatenation is **allowed** (produces a new immutable `str`); `StringBuilder` is provided for hot loops to avoid O(n²). (W4) | Ergonomic for the compiler's many small concatenations; builder covers the loop case |

| D38 | 2026-06-27 | Lists & maps have **value semantics with copy-on-write** under RC: a copy shares the cell (refcount bump) and any write through a mutable lvalue clones cells with refcount > 1 first; deep immutability (D14) holds.
