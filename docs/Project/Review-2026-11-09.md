## 1. Summary

1. **73 of 85 tasks can be signed off**: 32 as they are, 41 with follow-ups a new task should carry. **12 are not ready**; ten of those need one small fix each, two need real work (MYLA-395, MYLA-391: both are the interpreter's handling of generic code).
2. **The new standard library holds up remarkably well under differential testing.** Several million generated cases against Python's `hashlib`, `zlib`, `tomllib`, `csv`, `datetime`, `itertools`, `tarfile`, `zipfile`, expat, PyYAML and Go's `regexp`: digests, checksums, encodings, URLs, number parsing, bigint, B-tree, collections, TOML 1.0, XML, CSV, compression in both directions, sockets and HTTP under load all agree. What failed is a short list of edge cases (section 3.3).
3. **The serious findings are in the toolchain, and most are older than this week's tasks.** The reviewers' probes of new features walked into them:
   - The **interpreter loses integer width, sign and float size inside generic code**: `[uint64].sorted()` orders signed, `xs.sum(0)` never overflows, a generic `100i8 + 100i8` is 200. The interpreter is the project's oracle, and every `std.list` method over `uint64` or narrow integers is affected under `myla run` and `myla test`.
   - **Three native memory-safety bugs**: an actor method that stores a list, map or string argument segfaults; a recursive enum handed to a child task segfaults; and `m.remove(key())`, `m[key()] = v`, `xs[f()] = v` write into a freed or shared table when the key expression touches the container.
   - **`myla build` never ends on polymorphic recursion** (1.2 GB in 23 s), where `check` says `ok` and `run` prints the answer.
4. **Overflow checking (D175) made a class of library bugs visible.** Arithmetic on a caller's number traps interpreted and wraps natively: an HTTP chunk size, a tar pax number, `to_hex`'s width, `Duration.abs`, `deque.with_capacity`. The HTTP one lets a single request kill a checked server or pass the body limit of a plain one.
5. **The native test harness agrees with the interpreter on passing reports and disagrees on failing ones** (a failing float, `exit(0)`, a scalar `Err`, a case's stderr, expected panics). No burn test compares a failing report across runners.
6. **Baseline**: bootstrap from the seed is a fixed point in 13 s. The full burn suite: 1,385 tests, 1 failure (the load-sensitive `test_children_run_in_parallel`, which passes alone), 333 skipped. `#test` coverage of `selfhost/` fell to 67 % (target 80 %, was 70 %).

### Decisions the owner should make first (they shape P3, P5, P8, P11)

1. **Handles as values.** `File`, `TcpStream`, `Child`, `Notifier` are structs holding a descriptor or an address; a copy outlives a close and a forged one is a wild pointer (H8, M13). One answer for all: an opaque handle type, or a table index with a generation.
2. **Private fields and methods of a `pub` type.** Today every helper method of a public type is public API and every field writable from outside (`Lru.slot_keys`, `Notifier.id`), so no library type can protect an invariant.
3. **`Option` and `Result` as `Hash`** (MYLA-379's proposal 2): a derived key struct with an `Option` field is refused today.
4. **Expected panics natively** (M9): compare a `panic`'s message exactly, and give native runtime errors the interpreter's values, or keep the prefix rule and say which errors can't be expected on both runners.
5. **Overflow in library code** (D175): which library arithmetic wraps on purpose, which returns an error; the sweep in P11 needs the rule.
6. **The two open proposals** in MYLA-378 (`stdin_from_stdout` or a `Stdio` variant) and MYLA-363 (`walk_with(dir, bool)`).
7. **The D169 rule's reach** (M1): call arguments only, or also list and tuple literals, with the cost that `[a < b, c > (d)]` stops meaning two comparisons.
8. **Raw mode after a failure**: an exit hook in the runtime, or a documented limit.

## 5. Observations for the whole-codebase pass (part 2)

- The interpreter is the oracle, and it is the weakest runner: wrong in generic code (H1, H6), 100 to 500 times slower than native (byte-level parsers at 10 KB/s, `test_std_modules` 3.5 minutes, of which std.compress interpreted is 98 s), and it turns an internal miss into the printed value `ERR: VUnit` with exit 0.
- Deep copies between tasks and actors (D92) have almost no tests; wasm32 makes no copies, so its suite can't stand in for native there.
- Parity tests compare stdout and exit codes, never stderr: runtime error texts differ between runners (`map key 5 not found` against `map key not found`).
- `#test` can't sit on a generic function, so generic arithmetic has no case-level coverage in either runner; `std.list` has 13 cases for 45 methods.
- No module test uses a stream that gives short reads; parsers of untrusted input aren't fuzzed under `--checked`.
- Resource limits are uneven across the formats (JSON and YAML limit depth, TOML doesn't; whole-buffer decoders have no output limit; HTTP sizes are `int32`).
- Error types come in three shapes and not all implement `Format`; names are uneven (`parse_int` gives an `Option`, `parse_int32` a `Result`; `read_to_end` and `read_all`; `set.new`, `btree.set_new`, `cache.new_memo`, `heap.keyed_new`).
- Inference is left to right with all-or-nothing hints (MYLA-401, `and_then`, `?`, the second `if` branch): one design would serve better than more special cases. The checker also seems to stop at a function's first error.
- The compiler's own command line is parsed by hand in `selfhost/main.my` while `std.args` exists and `tools/embed` uses it.
- [[Project/Known-issues]] lists 20 done tasks; evidence counts in task files age silently. A board and wiki check in CI (MYLA-194) would catch both.
- External suites: toml-test is vendored, the W3C XML suite isn't, the YAML suite is cloned from the network at test time.
- The seeds doubled in two days, and each update now adds about 3.4 MB to the pack.
