# Advent of Code 2015 to 2021

In November 2026 an agent solved all of Advent of Code 2015 to 2021 in Myla: 175 days, about 15,000 lines, 350 stars, with no wrong answer submitted. That is the largest body of Myla written outside the toolchain. It found no compiler bug and no wrong result. 167 of the 175 days ran natively in under half a second without tuning. This page keeps what the run showed about the language, the tools and the standard library, and where each finding went on the board. The solutions themselves live outside this repository.

## Findings

The agent reproduced each finding on toolchain `f2bfa05`. Each task holds figures measured again on master `d5d80bc`.

| ID | Severity | Finding | Task |
| --- | --- | --- | --- |
| F1 | High | `m.remove(k)` takes time in the map's size, so emptying a map is quadratic | [[MYLA-310]] |
| F2 | Medium | `int` wraps silently at 32 bits (D4, D6) | [[MYLA-311]] |
| F3 | Medium | `#test` runs only in the interpreter, so a case that is fast natively can be far too slow as a test | [[MYLA-312]], done by [[MYLA-307]] (`myla test --native`) |
| F4 | Medium | Tuples and structs can't be map keys, and tuples have no `==` | [[MYLA-313]] |
| F5 | Medium | The standard library lacks everyday helpers (`split`, `trim`, `join`, `sort`, sets, queues, heaps, MD5) | [[MYLA-314]], [[Project/Standard-library-roadmap]] |
| F6 | Medium | A generic function can't build an empty generic value, and a call's expected type takes no part in inference | [[MYLA-315]] |
| F7 | Low | The docs say `#derive(Eq)` rejects `char` and float fields; the compiler accepts them | [[MYLA-316]] |
| F8 | Low | The interpreter is about 500 times slower than native code | [[MYLA-317]] |
| F9 | Low | Small gaps that cost lines: `for` over a `str`, `<` on strings, `'p' - 'a'`, a list of n equal values, a map lookup with a default | [[MYLA-318]] |

## What held up

- **Correctness:** no compiler bug and no wrong result in 175 days. Every failure was a mistake in a solution or in its test.
- **Native speed:** the slowest days were dominated by the agent's own MD5 (2016 Day 14 took 18 s, Day 5 12 s, 2015 Day 4 3.6 s), which is why the roadmap's MD5 is to be tuned.
- **Value semantics:** copying a state to try something was simple and cheap. A copied Intcode machine served as a free snapshot.
- **Error messages:** the checker's messages were precise enough to fix nearly every mistake from the message alone.
- **Deep recursion:** 10 million calls deep ran without a stack overflow.

## The helpers it wrote

The agent kept a library of its own beside the solutions, 785 lines in `lib/aoc/`. Each helper was proved on the puzzles. They are the first input to [[Project/Standard-library-roadmap]]:

| File | Holds |
| --- | --- |
| `text.my` | `find_from`, `includes`, `starts_with`, `ends_with`, `trim`, `split`, `lines`, `words`, `join`, `ints` (every integer in a line), `str_less` |
| `num.my` | `int64` `abs`, `min`, `max`, `gcd`, `lcm`, `modulo` (always non-negative), `sum`, `mulmod`, `powmod`, `modinv` |
| `sort.my` | `sort_by<T>(xs, before)` and `sort<T: Ord>(xs)`, stable merge sorts |
| `collections.my` | `Queue<T>` (a list and a head index) and `Heap<T>` (a binary min-heap keyed by an `int64` priority) |
| `combin.my` | `permutations` |
| `md5.my` | MD5 of a string, as bytes and as hex |
| `grid.my` | A character grid read from text; `(x, y)` packed into one `int64` key, because tuples can't be keys (F4) |

`Queue` and `Heap` have no constructor functions, because of F6: each use spells out a literal. `#test` can't take a generic helper (D116), so they were tested through wrappers.

## Not covered

- Only x86-64 Linux; aarch64 and wasm32 weren't run.
- Concurrency (`async`, actors) was never used.
- The solutions ran natively; interpreter and native output were not compared across all days.
- Timings are single runs on one machine.
