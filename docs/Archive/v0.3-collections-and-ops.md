# Myla v0.3 — Collections, Strings & Operators (design)

This is the detailed, decision-complete design for the **v0.3 "collections,
strings & ops"** milestone — Tier B + C in [self-hosting.md](self-hosting.md) §3.
It expands the sketches in [future-features.md](future-features.md)
§1/§10/§11/§12/§13/§15/§16/§17 into a real specification: concrete syntax,
semantics, grammar (EBNF), type-system changes, and an implementation plan
across the existing lexer → parser → checker → interpreter → compiler pipeline.

**Scope (v0.3):**

1. **Lists** `[T]` — growable, homogeneous, value semantics (copy-on-write).
2. **Maps** `[K: V]` — hash maps with primitive keys, value semantics (CoW).
3. **String toolkit** — `+` concatenation, byte indexing (`s[i] -> uint8`),
   char literals, a growable `StringBuilder`, and `format`.
4. **Bitwise & shift operators** — `& | ^ ~ << >>` (D24).
5. **Numeric casts** — `x as T` (D26).
6. **Numeric literal bases** — `0x` / `0b` / `0o`.
7. **Loop control** — `break` / `continue`.
8. **Module-level `const`** (D28).
9. **`assert` / `panic` / `unreachable`** internal-invariant intrinsics.

Out of scope (later tiers): **sets** (deferred until a concrete need; a set can
be a thin wrapper over a map), methods/`impl`/traits and lambdas (v0.4), modules
and the stdlib (v0.5), and the dedicated Unicode **`char`** type (v0.5 — v0.3 is
byte-oriented). Because modules don't exist yet, lists, maps, and `StringBuilder`
ship as **compiler built-ins** (monomorphized like our generic structs/enums,
heap cells reference-counted like recursive enums), not as a stdlib.

> The sub-decisions this design raised (W1–W6) are **locked** as **D38–D43** in
> [roadmap.md](roadmap.md). This document reflects those decisions; the “(see
> Wn)” markers point at the originating question for provenance.

## 1. Lists `[T]`

### 1.1 Syntax

```my
let xs: [int] = [1, 2, 3]
let ys: [str] = []            // empty list — element type from the annotation
let grid: [[int]] = [[1, 2], [3, 4]]
```

- **Literal:** `[e0, e1, ...]`, trailing comma allowed. All elements unify to one
  element type `T` (integer-literal flexibility applies, as elsewhere).
- **Empty literal `[]`:** carries no element type on its own; it takes `T` from
  the expected type (annotation, parameter, return, the other side of an
  assignment). With no context it is a type error (mirrors a bare `None`).

### 1.2 Semantics — value semantics with copy-on-write (see W1, D38)

A list is a **value**, exactly like a struct/tuple/enum: binding, passing,
returning, and assigning it produce an independent value, and deep immutability
(D14) holds — mutating one binding never affects another.

It is implemented as a reference-counted heap cell shared on copy (a copy just
bumps the refcount) and **cloned lazily on mutation**: any write through a
mutable lvalue path clones each cell on that path whose refcount is `> 1` before
writing (the **copy-on-write invariant**). This keeps the value semantics of the
rest of the language while avoiding an O(n) copy every time a list is passed
around — important for the self-hosted compiler, which threads token/AST lists
through every stage.

```my
var a = [1, 2, 3]
var b = a          // shares the buffer (refcount 2)
b[0] = 99          // b is shared -> clone, then write; a is untouched
// a == [1, 2, 3], b == [99, 2, 3]
```

### 1.3 Operations (built-in intrinsics)

No methods/`impl` until v0.4, so list operations are **built-in functions**
(resolved by the checker like `print`, not user-shadowable). Mutating ones
require a **mutable lvalue** first argument (see W3, D40) and apply the CoW
invariant:

| Form | Type | Notes |
|------|------|-------|
| `[e, ...]` | `[T]` | literal |
| `len(xs)` | `int` | element count |
| `xs[i]` (read) | `T` | bounds-checked; out-of-bounds **traps** |
| `xs[i] = v` (write) | — | lvalue; bounds-checked (trap); CoW |
| `push(xs, v)` | — | append; `xs` must be a `var` lvalue; CoW |
| `pop(xs)` | `T` | remove & return last; **traps** if empty; CoW |
| `for x in xs { }` | — | iterate elements in order (extends `for…in`) |

Indexing reuses the existing **trap** path (like divide-by-zero); a safe,
non-trapping accessor is left to the stdlib (v0.5) where it can return `Option`.

### 1.4 Representation & monomorphization

- `[T]` is a built-in **generic** type: each concrete instantiation (`[int32]`,
  `[str]`, `[[int32]]`, …) is monomorphized to a distinct stamped type, reusing
  the v0.2 monomorphizer and name-mangling.
- Heap layout: a refcounted cell `[refcount, length, capacity, <elements…>]`
  (elements inline; growth reallocates and copies). Boxed/aggregate elements
  follow the same boxing rules recursive enums already use.
- RC: a list slot is an owner; retained on share, dropped at scope exit, and at
  refcount zero its elements are dropped before the cell is freed — the existing
  `__drop`/`__retain`/arena machinery, extended with a per-element walk.

## 2. Maps `[K: V]`

### 2.1 Syntax

```my
let ages: [str: int] = ["ann": 30, "bob": 25]
let empty: [str: int] = [:]        // empty map literal (distinct from [] list)
```

- **Literal:** `[k0: v0, k1: v1, ...]`, trailing comma allowed; keys unify to `K`,
  values to `V`. Empty map is written **`[:]`** to disambiguate from the empty
  list `[]`.

### 2.2 Key type

`K` must be a **primitive** comparable type — an integer type, `bool`, `str`, or
a byte (`uint8`). This matches D37 (equality is primitives-only until traits),
so map keys can be hashed and compared without user-defined `Eq`.

### 2.3 Semantics & operations

Value semantics with copy-on-write, exactly as lists (W1/D38). Operations are
built-in intrinsics (mutating ones need a `var` lvalue, W3/D40):

| Form | Type | Notes |
|------|------|-------|
| `[k: v, ...]` / `[:]` | `[K: V]` | literal / empty |
| `len(m)` | `int` | entry count |
| `m[k]` (read) | `V` | **traps** if key absent (use `get` to be safe) |
| `m[k] = v` (write) | — | insert or update; lvalue; CoW |
| `get(m, k)` | `Option<V>` | safe lookup (uses the v0.2 prelude!) |
| `contains(m, k)` | `bool` | membership |
| `remove(m, k)` | — | delete if present (no-op otherwise); CoW |
| `keys(m)` | `[K]` | snapshot of keys (for iteration) |
| `for k in m { }` | — | iterate keys (unspecified order) |

### 2.4 Representation

A refcounted open-addressing hash table cell (load-factor-bounded, grows by
rehash). Monomorphized per `(K, V)` instantiation; RC drops keys and values at
refcount zero. Hashing is a fixed built-in per key type (FNV-1a over the bytes of
the canonical value).

## 3. Strings

v0.0 `str` stays **length-prefixed, immutable, UTF-8** (pointer + length). v0.3
adds the toolkit a byte-level lexer/diagnostic printer needs.

### 3.1 Concatenation `+` (see W4, D41)

`a + b` on two `str` values produces a **new immutable `str`** (allocates, copies
both, refcounted). v0.0's "`+` on `str` is an error" is lifted. For
construction in loops, prefer `StringBuilder` (§3.4) to avoid O(n²); `+` is for
the common small case (`name + "." + variant`).

### 3.2 Byte indexing & char literals (see W5, D42)

v0.3 is **byte-oriented**; the dedicated Unicode `char` type stays in v0.5.

- `s[i] -> uint8`: the byte at index `i` (bounds-checked; out-of-bounds **traps**).
- **Char literals** `'a'`, `'\n'`, `'\t'`, `'\\'`, `'\''`, `'\0'`: their byte
  value, of type `uint8` (and integer-literal-flexible, so `s[i] == 'a'` checks).
  Only single-byte (ASCII) char literals are valid in v0.3; a multi-byte literal
  is an error until the v0.5 `char` type.

### 3.3 `format`

```my
let msg = format("{}.{} at {}:{}", enum_name, variant, line, col)
```

- A variadic built-in intrinsic `format(fmt: str, args…) -> str` (special-cased
  like `print`, since general varargs don't exist yet).
- `{}` is a positional placeholder filled left-to-right; each argument is
  rendered by its type's `print` representation (int/bool/str/byte). `{{` / `}}`
  are literal braces. The checker verifies placeholder count == argument count.

### 3.4 `StringBuilder`

A built-in growable byte buffer (refcounted, value semantics):

| Form | Type | Notes |
|------|------|-------|
| `StringBuilder()` | `StringBuilder` | empty builder |
| `append(sb, s)` | — | append a `str`; `sb` must be a `var` lvalue |
| `append_byte(sb, b)` | — | append a `uint8` |
| `len(sb)` | `int` | bytes written |
| `build(sb)` | `str` | materialize the accumulated bytes as a `str` |

## 4. Operators

### 4.1 Bitwise & shift `& | ^ ~ << >>` (D24)

- Defined on **integer types only**; result is the operand type. `~` is unary
  bitwise-not. For `&`, `|`, `^` the two operands must share a type (no implicit
  mixing, D4). Shifts are the exception: the **shift amount** is an independent
  integer of any width (`x << n`), and the result takes the type of `x`.
- Right shift is **arithmetic** for signed types (sign-preserving `sar`),
  **logical** for unsigned (zero-filling `shr`) — matching the canonical
  representation codegen already maintains.
- Shifting by an amount outside `0..width`: a **compile error** when the amount
  is a constant. For a runtime-variable amount the count is **masked to the
  operand width** (`n & (width-1)`), a single well-defined wrap that the
  interpreter and the native backend share verbatim. (This is a deliberate
  simplification of the earlier "runtime trap" sketch: masking keeps the two
  backends trivially in lock-step and matches the hardware shift instructions.)
- Precedence, loosest→tightest among the new operators: `|` , then `^` , then
  `&` (all **tighter** than the comparison operators, so `a & b == c` parses as
  `(a & b) == c` — avoiding C's famous footgun), then `<< >>`, then the existing
  arithmetic levels (`+ -`, `* / %`). So `1 << 2 + 3` is `1 << (2 + 3)`.
- `>>` also denotes function composition (D24) — but functions aren't first-class
  values until v0.4, so in v0.3 `>>` is unambiguously a shift (integer operands).
  To keep nested generic closers like `Option<List<int>>` working, `<<`/`>>` are
  **not** lexed as single tokens; the parser recognises two column-adjacent
  `<`/`>` tokens as a shift at the shift-precedence level.

### 4.2 Numeric casts `x as T` (D26)

- `x as T` where `x` and `T` are both numeric (incl. `uint8` bytes). Narrowing
  **wraps** (mod 2^width); widening **zero-extends** from unsigned sources and
  **sign-extends** from signed; equal-width sign reinterpretation is a no-op.
- `as` becomes a keyword. Precedence: a cast binds tighter than the binary
  operators and looser than unary/postfix, so `a + b as int` is `a + (b as int)`
  and `-x as uint8` is `(-x) as uint8`. Grammar: `cast ::= unary ("as" type)*`.

### 4.3 Numeric literal bases (see W6, D43)

The lexer accepts `0x…` (hex), `0b…` (binary), `0o…` (octal) integer literals,
with optional `_` digit separators and the usual type suffix (`0xFFu8`,
`0b1010_0101`). They are ordinary integer literals (same flexibility rules).

## 5. Control flow: `break` / `continue`

- `break` exits the nearest enclosing `while`/`for`; `continue` jumps to its next
  iteration (a `for`'s step still runs). Both are statements; using either
  outside a loop is a compile error (the checker tracks loop-nesting depth).
- Codegen targets the loop's existing end/continue labels with a `jmp`.
- Labeled break/continue is a possible later addition (not v0.3).

---

## 6. Module-level `const` (D28)

```my
const NEWLINE: uint8 = 10u8
const MAX: int = 1 << 20
```

- A file-scoped, immutable, compile-time-constant binding — Myla's **only**
  top-level binding (no top-level `let`/`var`, D28).
- The initializer must be a **constant expression**: literals, `const`
  references, and arithmetic/bitwise/cast operations over them. The checker
  folds and validates it (cycles among `const`s are an error).
- Codegen emits the value into `.rodata` or inlines it; the interpreter
  evaluates all `const`s into a global environment at startup.

---

## 7. `assert` / `panic` / `unreachable`

For **internal invariants**, distinct from user-facing recoverable errors
(`Result`/`?`, D16). All three are built-in intrinsics that reuse the existing
trap path plus a `stderr` write, exiting nonzero on failure:

```my
assert(pos < len)                       // abort if false
assert(pos < len, "index out of range") // optional message
panic("internal error")                 // unconditional abort
unreachable()                           // a branch that must never run
```

- `assert(cond)` / `assert(cond, msg)`: abort with a message + source position
  when `cond` is false.
- `panic(msg)`: unconditional abort with the message.
- `unreachable()`: aborts if reached, and is a **diverging expression** the
  checker treats like a `return` (it satisfies a missing match arm / a
  non-returning path, reusing the v0.2.4c divergent-arm machinery).

## 8. Grammar additions (EBNF)

Extends [grammar.md](grammar.md) and [v0.2-data-modeling.md](v0.2-data-modeling.md) §6.

```
/* --- types --- */
type        ::= … | list_type | map_type
list_type   ::= "[" type "]"
map_type    ::= "[" type ":" type "]"

/* --- top-level declarations --- */
decl_body   ::= … | const_decl
const_decl  ::= "const" IDENT ":" type "=" expression

/* --- expressions --- */
expression  ::= … (cast is the new lowest-precedence unary layer)
cast        ::= unary ("as" type)*
/* binary precedence, loosest→tightest:
   || , && , (== !=) , (< <= > >=) , | , ^ , & , (<< >>) , (+ -) , (* / %) , cast */

primary     ::= … | list_lit | map_lit | char_lit
list_lit    ::= "[" ( expression ("," expression)* ","? )? "]"
map_lit     ::= "[" ":" "]"                              /* empty map */
              | "[" map_entry ("," map_entry)* ","? "]"
map_entry   ::= expression ":" expression
char_lit    ::= "'" ( CHAR | ESCAPE ) "'"

postfix_op  ::= … | "[" expression "]"                   /* index: list/map/str */

INT         ::= dec_int | hex_int | bin_int | oct_int    /* with '_' separators */

/* --- statements --- */
stmt        ::= … | "break" | "continue"
lvalue      ::= … | lvalue "[" expression "]"            /* indexed assignment */
```

New reserved keywords: `as`, `const`, `break`, `continue`. (`StringBuilder`,
`len`, `push`, `format`, `assert`, … are built-in **intrinsics**, resolved by the
checker, not reserved words.)

## 9. Implementation notes (per pipeline stage)

- **Lexer:** new tokens `& | ^ ~ << >>`, `[` `]` already exist; `'…'` char
  literals; `0x`/`0b`/`0o` and `_`-separated integer literals; keywords `as`,
  `const`, `break`, `continue`.
- **Parser:** list/map literals & types; index expression + indexed lvalue;
  `as`-cast layer; bitwise/shift precedence levels; `const` decls; `break`/
  `continue` statements.
- **Checker:** list/map element/key/value inference (incl. empty `[]`/`[:]` from
  context); intrinsic signatures (`len`/`push`/`pop`/`get`/`contains`/`remove`/
  `keys`, `append`/`build`, `format`, `assert`/`panic`/`unreachable`); mutable-
  lvalue checking for in-place ops; `as` numeric-pair validation + constant-
  shift-width error; const-expression folding; loop-depth tracking;
  `unreachable()` as a diverging expression.
- **Monomorphizer:** stamp `[T]` / `[K: V]` / `StringBuilder` per instantiation,
  mangled like v0.2 aggregates; rewrite intrinsic call sites to the concrete
  element/key/value layout.
- **Interpreter (erasure):** new runtime values `ListValue`, `MapValue`,
  `StringBuilderValue`; CoW is automatic (Python value copies on mutation);
  intrinsics are evaluated directly; `assert`/`panic` raise the runtime-error
  path; `+`/casts/bitwise extend `_eval_binary`/`_eval_unary`.
- **Compiler (x86-64):** refcounted heap cells with the CoW clone-if-shared
  invariant on mutation; element/entry drops at refcount zero (extends the RC
  walker); bitwise/shift/cast map to single instructions (`and`/`or`/`xor`/
  `not`/`sar`/`shr`/`shl`/`movzx`/`movsx`); `str` concat allocates + copies;
  `format`/`StringBuilder` build into a growable buffer; `assert`/`panic`/
  `unreachable` reuse `__trap` + a `stderr` `write`.

Every feature follows the project conventions: a runnable example with `#test`
cases (`examples/*.my`), interpreter↔native parity in the burn suite, and a
negative case in `examples/errors/` for each new diagnostic.

## 10. Suggested implementation phasing

The milestone is sliced so each phase lands end-to-end (checker + both backends +
tests) before the next:

1. **v0.3.1 — operators & literals:** bitwise/shift, `x as T`, `0x`/`0b`/`0o`
   literals, `break`/`continue`. (All design-locked, no heap — quick wins.)
   **— landed (see §11).**
2. **v0.3.2 — `const` + `assert`/`panic`/`unreachable`.** Top-level decls and the
   invariant intrinsics. **— landed (see §11).**
3. **v0.3.3 — lists `[T]`:** literals, indexing (+ lvalue), `len`/`push`/`pop`,
   `for…in`, CoW + RC, monomorphization. **— landed (see §11).**
4. **v0.3.4 — maps `[K: V]`:** literals, `m[k]` get/set, `get`/`contains`/
   `remove`/`keys`, iteration, CoW + RC. **— landed (see §11).**
5. **v0.3.5 — string toolkit:** `+` concat, byte indexing, char literals,
   `StringBuilder`, `format`.

Sets remain out of scope; revisit if a concrete need appears before v0.4.

## 11. Implementation status

### v0.3.1 — operators & literals (landed)

Shipped end-to-end (lexer → parser → checker → interpreter → x86-64 codegen),
with interpreter↔native parity and a negative corpus:

- **Integer-literal bases** `0x` / `0b` / `0o` with `_` digit separators between
  digits (e.g. `0b1111_1111`, `0xFFu8`), reusing the existing suffix machinery.
- **Bitwise & shift** `& | ^ ~ << >>` on integers, with the precedence in §4.1
  (bitwise tighter than comparison; `&` > `^` > `|`; shifts between the bitwise
  and additive levels). `<<`/`>>` are parsed as two adjacent `<`/`>` tokens so
  nested generic closers keep working. Constant out-of-range shift amounts are a
  compile error; runtime amounts are masked to the operand width.
- **Numeric casts** `x as T` (`as` is now a keyword): numeric→numeric only,
  truncating/zero-/sign-extending via the shared `_wrap` width logic.
- **`break` / `continue`** in `while`/`for`, rejected outside a loop by the
  checker (loop-depth tracking). The native backend drops any heap owners bound
  in the loop body scope before the jump, so early exits don't leak (covered by
  an arena-exhaustion stress test).

Surface: `examples/operators.my` (+ `#test` cases), parity programs and the
break/continue RC stress test in `tests/burn/test_compiler_parity.py`, and the
`lex_int_*` / `type_shift_*` / `type_cast_*` / `type_bitwise_*` /
`type_break_outside_loop` / `type_continue_outside_loop` negative cases in
`examples/errors/`.

Deferred to a later v0.3 phase: `>=`-width runtime shift **trapping** (we mask
instead, see §4.1), and labeled break/continue.

### v0.3.2 — `const` + `assert`/`panic`/`unreachable` (landed)

Shipped end-to-end with interpreter↔native parity and a negative corpus:

- **Module-level `const`** (D28): `const NAME: T = <constexpr>` — a file-scoped,
  immutable binding requiring an explicit type. The checker folds the initializer
  to a value (literals, references to other `const`s, and unary/binary/cast/logical
  operations over them), detecting **cyclic definitions** on demand and rejecting
  non-constant initializers (e.g. a function call) and `const` division by zero.
  The interpreter seeds folded values into a global environment; the native
  backend **inlines** each value at its use site (a `movabsq` for integers, a
  `.rodata` label for strings), so there is no runtime storage or init order.
- **`assert(cond[, msg])`**: a no-op when the condition holds; otherwise it writes
  the message (default `"assertion failed"`) to stderr and exits nonzero.
- **`panic(msg)`**: unconditional abort with the message.
- **`unreachable()`**: aborts with `"reached unreachable code"`.
- `panic`/`unreachable` are **diverging** expressions: the checker treats them
  like a `return` (via the v0.2.4c divergent-arm machinery), so they discharge an
  otherwise-missing `match` arm or a non-returning path. `assert`/`panic`/
  `unreachable` are reserved builtins and cannot be redefined.
- Native backend: a shared `__panic` routine writes `[len][bytes]` + newline to
  fd 2 (stderr) and `exit(1)`; the interpreter raises a `MylaRuntimeError`.

Surface: `examples/constants.my` (+ `#test` cases), the `const_folding` /
`assert_pass_and_match_unreachable` parity programs and the panic/assert/
unreachable abort tests in `tests/burn/test_compiler_parity.py`, and the
`type_const_*` / `type_assert_non_bool` / `type_panic_non_string` /
`type_unreachable_with_args` / `type_redefine_builtin_panic` negative cases in
`examples/errors/`.

### v0.3.3 — lists `[T]` (landed)

Shipped end-to-end (lexer → parser → checker → interpreter → x86-64 codegen),
with interpreter↔native parity and a negative corpus:

- **Type & literals:** `[T]` is a built-in generic type; `[e0, e1, …]` literals
  (trailing comma allowed) unify their elements to one `T` (integer-literal
  flexibility flows in from the expected type). An empty `[]` takes `T` from the
  expected type and is a type error without one (mirrors a bare `None`).
- **Operations** (built-in, not user-shadowable): `len(xs)`; `xs[i]` read;
  `xs[i] = v` write; `push(xs, v)`; `pop(xs)`; and `for x in xs` (the `for`
  loop now accepts either a `start..end` range or a list iterable). Indexing and
  `pop` are bounds-checked and **trap** on misuse. `push`/`pop`/index-assign
  require a **mutable lvalue** (W3/D40), including nested paths like
  `grid[i][j] = v` and `push(grid[i], v)`.
- **Value semantics + copy-on-write (D38):** a list is a value; binding/passing/
  returning/assigning is an independent value. The interpreter deep-copies on
  every bind (same observable deep immutability, D14). The native backend shares
  the buffer on copy (refcount bump) and **clones lazily** on the first write
  through a shared path — `_cow_unique` clones every cell on the lvalue path
  whose refcount is `> 1` before writing.
- **Representation & RC:** a heap cell `[len:8][cap:8][elems…]` (elements inline
  at `_stored_size`, boxed members as pointers) behind the standard
  `[size,refcount]` arena header. A list is itself a refcounted **leaf owner**
  (an 8-byte pointer wherever it appears), retained on share and dropped at scope
  exit; at refcount zero its elements are dropped (a per-element walk) before the
  cell is freed. Per-element-type helpers `__drop_list_<E>` / `__clone_list_<E>` /
  `__grow_list_<E>` are emitted like the recursive-enum `__dropb_<E>`. `push`
  grows with **amortized doubling** so freed cells fall into reusable size classes.
- **Monomorphization:** each concrete `[T]` is carried through the existing pass
  (substitution, reification, and a `L_<elem>` mangle token); no decl is stamped
  since lists have no user-defined body.

Surface: `examples/lists.my` (+ `#test` cases, including value-semantics and
nested-CoW checks), the `list_*` parity programs and the `STRESS_LIST` arena
test in `tests/burn/test_compiler_parity.py`, and the `type_list_*` /
`type_index_non_list` / `type_for_in_non_list` / `type_push_*` / `type_pop_*` /
`type_redefine_builtin_len` / `runtime_list_index_oob` / `runtime_pop_empty`
negative cases in `examples/errors/`.

Deferred to the stdlib (v0.5): a safe, non-trapping accessor returning `Option`.

### v0.3.4 — maps `[K: V]` (landed)

Shipped end-to-end (lexer → parser → checker → interpreter → x86-64 codegen),
with interpreter↔native parity and a negative corpus:

- **Type & literals:** `[K: V]` is a built-in generic type; `[k0: v0, …]`
  literals (trailing comma allowed) unify keys to one `K` and values to one `V`.
  The empty map is written **`[:]`** (disambiguated from the empty list `[]` in
  the parser) and takes its key/value types from the expected type — a bare `[:]`
  with no context is a type error. The key type `K` must be a **primitive
  comparable** type (an integer type, `bool`, or `str`); a non-primitive key is
  rejected by the checker (D37).
- **Operations** (built-in, not user-shadowable): `len(m)`; `m[k]` read (traps
  on an absent key); `m[k] = v` insert/update; `contains(m, k) -> bool`;
  `remove(m, k)` (delete if present, no-op otherwise); `keys(m) -> [K]`; and
  `for k in m` (iterates keys in unspecified order). The safe lookup
  `get(m, k) -> Option<V>` ships as a **generic prelude function** (`fun get<K,
  V>(…)`, monomorphized at each call site) rather than a builtin, reusing the
  v0.2 `Option`/prelude machinery. `m[k] = v` and `remove` require a **mutable
  lvalue** (W3/D40), including nested paths like `m[k].field = v`.
- **Value semantics + copy-on-write (D38):** a map is a value, exactly like a
  list; the interpreter deep-copies on every bind, and the native backend shares
  the cell on copy (refcount bump) and clones lazily on the first write through a
  shared path (`_cow_unique`).
- **Representation & RC:** a refcounted **open-addressing hash table** cell
  `[len:8][cap:8][slot0…]`, each slot `[state:8][key:8][value:vs]` with `state`
  ∈ {empty, occupied} and a power-of-two capacity. Hashing is **FNV-1a** over the
  8 key bytes (`str` keys hash their bytes), collisions resolve by **linear
  probing**, and the table **grows by rehash** past a 0.75 load factor. The map
  is itself a refcounted leaf owner: at refcount zero its owned keys/values are
  dropped before the cell is freed. **`remove` uses rebuild deletion** — it
  allocates a fresh cell and re-inserts every surviving entry — so the probe
  helpers never deal with tombstones (simpler and correct at an O(n) delete cost,
  acceptable for the bootstrap compiler). Per-`(K,V)` helpers `__new_map_*` /
  `__put_map_*` / `__find_map_*` / `__clone_map_*` / `__grow_map_*` /
  `__drop_map_*` / `__keys_map_*` / `__remove_map_*` are emitted alongside the
  list helpers.
- **Monomorphization:** each concrete `[K: V]` is carried through the existing
  pass (key/value substitution, reification, and an `M_<K>_<V>` mangle token),
  including the generic `get<K, V>` instantiations.

Surface: `examples/maps.my` (+ `#test` cases, including value-semantics, growth,
remove/reinsert, and map-of-lists CoW checks), the `map_*` parity programs and
the `STRESS_MAP` arena test in `tests/burn/test_compiler_parity.py`, and the
`type_map_key_not_primitive` / `type_map_empty_no_type` / `type_map_index_wrong_key`
/ `type_map_heterogeneous` / `runtime_map_key_absent` negative cases in
`examples/errors/`.

Deferred to the stdlib (v0.5): a non-trapping `m[k]` accessor (use `get`), and
ordered iteration.

### v0.3.5 — string toolkit (landed)

Shipped end-to-end (lexer → parser → checker → interpreter → x86-64 codegen),
with interpreter↔native parity and a negative corpus. Delivered in three slices:

**v0.3.5a — char literals, byte indexing, `len(str)`.**

- **Char literals** `'a'`, `'\n'`, `'\t'`, `'\\'`, `'\''`, `'\0'`: lexed to a new
  `CHAR` token carrying the byte value, parsed into an `IntLit` flagged
  `is_char`. The checker defaults them to `uint8` but keeps them
  integer-literal-flexible, so `s[i] == 'a'` checks and they are usable as
  `match` literal patterns.
- **Byte indexing** `s[i] -> uint8`: bounds-checked, **traps** out of bounds. The
  native backend loads the byte with `movzbq` past the length prefix. Strings
  stay immutable — `s[i] = v` is a type error.
- **`len(s)`**: the string's byte length (the length prefix), joining lists and
  maps under the same `len` builtin.

**v0.3.5b — `+` concatenation + `format`.**

- **`str + str`** produces a new `str` (allocates, copies both halves). The
  checker widens `+` to accept either integer or string operands (`str + int` is
  still an error); the native backend assembles the result with a `__str_concat`
  runtime helper.
- **`format(fmt, args…)`** is a variadic builtin special-cased like `print`. The
  format string must be a **literal** so the checker can validate it at compile
  time: `{}` is a positional hole filled left-to-right, `{{`/`}}` are literal
  braces, every argument must be printable (int/bool/str/byte), and the hole
  count must equal the argument count. The native backend renders each argument
  with `__int_to_str` / `__uint_to_str` / `__bool_to_str` and stitches the pieces
  with `__str_concat`.
- **Heap model (deliberate simplification):** concat and `format` results are
  heap-allocated but **not** reference-counted — they persist for the program's
  lifetime, exactly like `.rodata` string literals. Full `str` RC rippled into
  too much existing collection machinery (map keys, `get` return values,
  retain-on-read) to be worth it for the bootstrap compiler; arena growth from
  transient strings is an accepted, documented limitation. Use `StringBuilder`
  for hot loops.

**v0.3.5c — `StringBuilder`.**

- A built-in growable byte buffer with the **same value semantics as lists**:
  `StringBuilder()` (empty), `append(sb, s)` (append a `str`), `append_byte(sb,
  b)` (append a `uint8`), `len(sb)` (bytes written), `build(sb)` (materialize a
  `str`). The mutating ops require a `var` lvalue (W3/D40); `StringBuilder`,
  `append`, `append_byte`, and `build` are reserved builtins.
- **Representation & RC:** a refcounted heap cell mirroring a `List<uint8>`
  (`[len:8][cap:8][bytes…]`) — it reuses the list RC/CoW/grow design with
  dedicated `__sb_new` / `__sb_drop` / `__sb_clone` / `__sb_grow` / `__sb_extend`
  / `__sb_build` helpers. Copying shares the buffer (refcount bump) and the first
  write through a shared path clones it (copy-on-write), so a builder threaded
  through aggregates and functions keeps mutable value semantics without breaking
  the RC model. Carried through monomorphization as a stamped heap-owning type.

Surface: `examples/strings.my` (+ `#test` cases for byte indexing, char
literals/`match`, concat, `format`, and `StringBuilder` value-semantics/CoW), the
`string_len_and_index` / `string_char_literals_and_match` / `string_concat` /
`string_format` / `string_builder` parity programs plus the `STRESS_SB`
builder-RC arena test in `tests/burn/test_compiler_parity.py`, and the
`lex_char_empty` / `lex_char_multibyte` / `runtime_str_index_oob` /
`type_str_index_assign` / `type_str_index_not_int` / `type_concat_str_int` /
`type_format_non_literal` / `type_format_arg_count` / `type_format_unprintable` /
`type_format_lone_brace` / `type_sb_ctor_args` / `type_sb_append_immutable` /
`type_sb_append_wrong_type` / `type_sb_build_non_builder` negative cases in
`examples/errors/`.

Deferred: full reference counting for transient `str` values (concat/`format`
results leak into the arena by design), and the dedicated Unicode `char` type
(v0.5 — v0.3 stays byte-oriented).
